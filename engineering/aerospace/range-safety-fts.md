# 飛行安全と自律飛行中断システム (Range Safety & Autonomous Flight Termination Systems)

## 概要 (Overview)

ロケットは、数百トンの推進剤を積んで人口密集地の近くから打ち上がる。**飛行安全 (range safety)** とは、機体が制御を失ったときに**公衆への被害を確実に防ぐ**ための仕組み——飛行経路の制限、リアルタイムの追跡、そして最後の手段としての**飛行中断システム (Flight Termination System, FTS)**——の総称である。打ち上げの信頼性がどれほど上がっても、FTS は「失敗しても安全 (fail-safe)」を保証する独立の砦として要求され続ける。

伝統的な FTS は、地上のレーダ追跡と**飛行安全担当官 (Mission Flight Control Officer)** の判断による無線コマンド破壊だった。SpaceX はこれを、機体自身が GPS/慣性航法で自機の状態を監視し、事前に読み込んだ飛行安全規則に照らして**自律的に中断を判断する AFSS (Autonomous Flight Safety System)** へ置き換える転換を主導し、2017年に Falcon 9 で初の運用飛行を実現した[^45sw]。AFSS は人員・地上設備を削減するだけでなく、**高頻度打ち上げ・複数機同時飛行・ブースタ帰還**という SpaceX の運用モデルの成立条件でもある。

本ドキュメントは、飛行安全の原理（飛行回廊・破壊限界線・瞬時落下点）、FTS のハードウェア構成、コマンド式から自律式への転換の論理、そして Starship 飛行試験での FTS 作動事例を分析する。分析深度は Level 3。

> 関連: 冗長計算機と fail-safe/fail-operational の設計原理は `avionics-gnc.md`、射点側の安全は `launch-ground-systems.md`。

## 方法論 (Methodology)

- 飛行安全を「**公衆リスクの定量管理**」として定式化し、飛行回廊・破壊限界線・瞬時落下点 (IIP) という基本概念を整理する。
- FTS を**判断系**（誰が・何を根拠に中断を決めるか）と**執行系**（どう飛行を終わらせるか）に分け、コマンド式→自律式の転換を判断系の移設として読む。
- 標準文書（Range Commanders Council RCC 319、FAA 商業宇宙輸送規則 Part 450）と、運用主体（米宇宙軍第45デルタ）の公式発表を一次資料とする。
- Starship IFT-1/IFT-2 の FTS 作動を FAA の事故調査文書に基づき分析する。

## 発見事項 (Findings)

1. **飛行安全の単位は「機体」ではなく「公衆リスク」。** 規制（FAA Part 450）は、飛行経路下の人口に対する予測死傷リスク (expected casualty, E_c) を閾値以下に抑えることを要求する。機体を守るためではなく、**機体を犠牲にしてでも**公衆を守るのが FTS である[^part450]。
2. **鍵となる計算は瞬時落下点 (IIP)。** 「今この瞬間に推力が止まったら破片はどこに落ちるか」を連続的に計算し、その点が保護区域に入る前——**破壊限界線 (destruct lines)** を越える前——に飛行を終端する。判断は常に「手遅れになる前」でなければならない。
3. **執行は「推力停止」と「タンク開放」。** 液体ロケットの FTS は、エンジン停止に加えて線形成形炸薬 (linear shaped charge) でタンクを開き、推進剤を分散させて**地上到達エネルギーを最小化**する。爆発させることが目的ではなく、まとまった質量とエネルギーの落下を防ぐことが目的である[^rcc319]。
4. **AFSS は「判断系の機上移設」。** 地上レーダ＋人間の判断を、機上の GPS/IMU＋事前定義の規則群 (mission rules) に置き換える。冗長化された機上計算機が自機位置を航法解で監視し、規則違反で自律的に終端する。標準は RCC 319 に成文化されている[^rcc319]。
5. **SpaceX が運用の先駆となった。** 2017年2月の Falcon 9 (CRS-10) が AFSS の初運用飛行であり、米空軍第45スペースウィング（当時）は人員・設備の削減と柔軟性向上を公式に認めた[^45sw]。以後、AFSS は米国の新型機の事実上の標準になりつつある。
6. **AFSS は SpaceX の運用モデルの成立条件。** (1) 高頻度: 地上要員・設備の占有が減り、射場のターンアラウンドが縮む、(2) 帰還ブースタ: 降下してくる第1段の安全管理も機上で完結、(3) 複数機・新回廊: ケープからの極軌道回廊の再開（2020年）など、従来の地上追跡網では困難な飛行形態を可能にした[^polar]。
7. **Starship 飛行試験は FTS の実地検証でもあった。** IFT-1 では姿勢喪失後に FTS が作動したが**破壊までに想定超の時間**を要し、FAA 是正措置の対象となった（炸薬増強と再認定で対応）。IFT-2 では両段の自律安全系が設計どおり終端を実行した[^faa-ift]。

## アーキテクチャ (Architecture)

### 飛行安全の空間構造 (Corridors, Lines, IIP)

```
        打ち上げ方位
            │
   ┌────────┼────────┐
   │  飛行回廊        │ ← 公称経路+分散を包む「許された空間」
   │  (flight        │    経路下の人口密度から E_c を算出し
   │   corridor)     │    閾値以下になるよう設計
   │        │        │
 ──┼────────┼────────┼── ← 破壊限界線 (destruct lines)
   │        ▼        │    IIP がこれを越える「前」に終端する
   │   IIP の軌跡     │
   │  (瞬時落下点:    │ ← 「今推力が止まれば破片はどこへ」
   │   連続計算)      │    を航法解から毎瞬計算
   └─────────────────┘
   ▓▓ 保護区域（人口密集地・航路）▓▓
```

### 判断系の転換 — コマンド式 vs 自律式 (Command vs Autonomous)

| 観点 | コマンド式 FTS（従来） | AFSS（自律式） |
|---|---|---|
| 追跡 | 地上レーダ・テレメトリ網 | **機上 GPS + IMU（冗長）** |
| 判断 | 飛行安全担当官（人間） | **機上計算機 × 事前定義規則** |
| 執行指令 | 秘匿無線リンクで送信 | 機上で完結（RF リンク不要） |
| 地上要員・設備 | 多い（射場ごとに常設） | **大幅減**（規則の事前検証に移る） |
| 反応時間 | 人間の判断＋リンク遅延 | 計算周期のみ（決定論的） |
| 弱点 | リンク妨害・人的遅れ | **規則とソフトの事前検証が全て** |
| 標準 | RCC 313 系 | **RCC 319**（FTS 共通標準）[^rcc319] |

- **本質**: 安全判断の正しさを「その場の人間の判断力」から「**事前に検証された規則集合**」へ移す転換であり、航空宇宙ソフトウェアの検証文化（`avionics-gnc.md` の fail-safe 設計）が公衆安全の最前線に立つことを意味する。

### FTS ハードウェア構成 (FTS Hardware)

```
 [航法] GPS 受信機 ×2系 ＋ IMU ×2系（独立電源・独立配線）
    │      機体主系とは独立した安全専用系として構成
    ▼
 [判断] 冗長 AFSS 計算機 — mission rules (破壊限界線, ゲート,
    │      時刻・高度条件) を照合。系間で独立に判断
    ▼
 [執行] 起爆管制ユニット → 線形成形炸薬 (タンク縦方向に開く)
           ＋ エンジン推力停止指令
    ・全系が独立バッテリで動作（機体電源喪失後も機能）
    ・保護区域を離れた後は「セーフ化」(safing) して誤作動を防ぐ
```

## 技術詳細 (Technical Details)

### 執行の設計 — なぜ「タンクを開く」のか

FTS の執行は直感に反して「爆破」ではない。

- **目的は分散**: 満載のタンクがまとまって落ちると、地表で大規模な爆発・火災になる。線形成形炸薬でタンクを縦に開き、推進剤を高空で放出・分散させれば、地上に届くのは燃え残りの構造片になる。**地上到達エネルギーの最小化**が設計目標である[^rcc319]。
- **固体モータの違い**: 固体ブースタは「消火」できないため、ケースを開いて推力を無効化する設計になる（燃焼は続くが推進が成立しない）。液体機のエンジン停止＋タンク開放とは執行の物理が異なる。
- **時間余裕**: 破壊限界線の内側には、判断→起爆→分散完了までの遅れ時間を見込んだマージンが要る。IFT-1 の教訓（後述）はまさにこの遅れの見積もりだった。

### SpaceX と AFSS — 採用の経緯と運用効果

- **初運用**: 2017年2月19日の Falcon 9 CRS-10（KSC 39A からの初打ち上げ）が、**AFSS を主系とした初の運用飛行**。第45スペースウィングは「射場の人員・設備所要を削減し、スケジュール柔軟性と即応性を高める」と公式に評価した[^45sw]。
- **帰還ブースタとの相性**: RTLS（射点帰還）では、上昇する第2段と降下する第1段が**同時に飛行安全の管理対象**になる。機上完結の AFSS は、この複数オブジェクト管理を地上網の増強なしに成立させる。
- **回廊の解放**: 2020年、ケープカナベラルからの**極軌道回廊**が約60年ぶりに再開された。キューバ上空を通過する経路は、AFSS による確実な終端能力を前提に公衆リスク計算が成立したもので、「自律化が物理的に新しい軌道を開いた」事例である[^polar]。
- **規制の並走**: FAA の商業打ち上げ規則は Part 450 へ統合され、性能基準ベース（E_c 閾値）の枠組みで AFSS を含む新方式を受け入れる構造になった[^part450]。

### 事例分析 — Starship 飛行試験での FTS 作動

- **IFT-1 (2023-04)**: 上昇中に複数エンジン不調から姿勢を喪失、FTS が指令された。しかし**起爆からタンク破壊・飛行終端までに想定を超える時間（約40秒）** を要し、機体はタンブリングを続けた後に分解した。FAA 事故調査の是正措置には **FTS の炸薬増強と再認定**が含まれ、以後の機体に適用された[^faa-ift]。——巨大なステンレスタンク（`rocket-structures-tanks.md`）に対する終端手段の実効性は、実飛行で初めて検証されたことになる。
- **IFT-2 (2023-11)**: ブースタはホットステージング後のブーストバック中に、シップは飛行後半に、それぞれ自律安全系が異常を検知して終端した。機体は失われたが、**「異常時に設計どおり自律終端する」ことが両段で実証**された飛行でもある[^faa-ift]。
- **読み方**: FTS は「使われないことが最良」の系だが、開発初期の高頻度試験では実際に作動する。fly-fail-fix の反復開発は、機体だけでなく**安全系そのものの実証機会**としても機能している——ただしそれは、飛行回廊と退避区域の設計が正しく、公衆被害ゼロで失敗できたからである。

## セキュリティ考察 (Security Considerations)

- **攻撃面の交換**: コマンド式 FTS は秘匿化された無線リンクという**RF 攻撃面**（妨害・なりすまし）を持つ。AFSS はリンクを廃してこの面を消す代わりに、**ソフトウェアと規則データの完全性**が安全の全てになる——mission rules の検証・署名・改竄防止、開発環境のサプライチェーン管理が、事実上の飛行安全要件となる。
- **誤作動と不作動の非対称**: FTS の不作動は公衆被害に、誤作動は機体喪失に至る。設計は「疑わしきは終端」に倒しつつ（公衆保護が上位）、正常飛行での誤終端を防ぐため冗長系の合意と保護区域外でのセーフ化を組み合わせる——`avionics-gnc.md` の fail-safe/fail-operational の使い分けの、最も重い応用例である。
- **本リポジトリの立場**: FTS の具体的な起爆装置仕様・無線プロトコルの詳細は公開標準 (RCC 319) の範囲でのみ扱い、運用中システムの脆弱性探索にあたる内容は扱わない（`CLAUDE.md` の Security & Ethics 方針）。

## 結論 (Conclusions)

飛行安全は「ロケットを守る」技術ではない。**ロケットを確実に壊せることを保証する**技術であり、その保証があって初めて、人の住む惑星からロケットを打ち上げる社会的許可が成立する。IIP と破壊限界線という空間の設計、タンクを開いて分散させる執行の設計、そして判断を人間から検証済み規則へ移した AFSS——いずれも「失敗を安全に失敗させる」ための工学である。

SpaceX にとって AFSS は安全対策であると同時に**運用アーキテクチャの要石**だった。高頻度打ち上げ、帰還ブースタ、新しい飛行回廊は、判断系の自律化なしには規制上も物理上も成立しない。そして Starship の飛行試験は、FTS が図面上の保証ではなく**実飛行で検証されるべき系**であることを示した——IFT-1 の「壊しきれなかった40秒」は、安全系にも fly-fail-fix が必要だという、この分野で最も高価な教訓の一つである。
