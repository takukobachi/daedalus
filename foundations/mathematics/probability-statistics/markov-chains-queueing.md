# マルコフ連鎖と待ち行列 (Markov Chains and Queueing Theory)

## 概要 (Overview)

確率・統計シリーズの第2回。前回は1個の確率変数を扱ったが、システムの分析で本当に知りたいのは**時間とともに確率的に変化する状態**(予測器の学習状態、キューの長さ、セッションの遷移)である。その最も実用的なモデルが**マルコフ連鎖 (Markov chain)**: 「次の状態は現在の状態だけで決まり、過去の履歴には依らない」という**マルコフ性**を持つ確率過程である。

マルコフ性は制約に見えて、実は設計原理である。状態に「未来の予測に必要な情報」をすべて詰め込めば、どんな系もマルコフ的に書ける。分岐予測器の飽和カウンタも、TCP の輻輳状態機械も、キューの長さも、この形をしている。本回はマルコフ連鎖の言語(遷移行列・定常分布)を線形代数第2回と合流させたうえで、その連続時間版として**待ち行列理論 (queueing theory)** の入口(ポアソン過程、M/M/1、**リトルの法則**)まで進む。「利用率を上げるとレイテンシが爆発する」という性能工学の基本法則が、定常分布の計算から定量的に出てくる。

## 本論 (Main Content)

### 1. マルコフ性と遷移行列 (Markov property and transition matrix)

状態空間 S 上の確率過程 X₀, X₁, X₂, … が**マルコフ連鎖**であるとは、次が成り立つことをいう (Norris 1997, Ch. 1)。

```text
P(Xₙ₊₁ = j | Xₙ = i, Xₙ₋₁, …, X₀) = P(Xₙ₊₁ = j | Xₙ = i) = Pᵢⱼ
(未来は現在の状態のみに依存 — マルコフ性)
```

遷移確率 Pᵢⱼ を並べた**遷移行列 (transition matrix)** P は各行の和が1の確率行列であり、時刻 n の分布(行ベクトル πₙ)の時間発展は `πₙ₊₁ = πₙP` である。つまり**確率過程の時間発展が行列の冪に還元される**。n ステップ後の遷移確率が Pⁿ の成分になること(チャップマン–コルモゴロフの等式)は、線形代数第2回「対角化と行列の冪」がそのまま確率論の道具になることを意味する。

モデリングの要点は状態の設計にある。「過去2回の分岐結果に依存する」系は一見マルコフ的でないが、状態を(直近2回の履歴)と定義し直せばマルコフ連鎖になる。**履歴を状態に畳み込む**この操作が、分岐予測器のパターン履歴テーブルの数学的意味である。

### 2. 定常分布と収束 (stationary distribution and convergence)

分布 π が `π = πP` を満たすとき**定常分布 (stationary distribution)** と呼ぶ。定常分布は、1ステップ進めても分布が変わらない平衡点であり、線形代数の言葉では固有値1の左固有ベクトルである。基本定理を次に示す (Norris 1997, Th. 1.8.3)。

```text
既約 (どの状態からどの状態へも到達可能) かつ非周期的な有限マルコフ連鎖は、
唯一の定常分布 π を持ち、初期分布に依らず πₙ → π に収束する。
さらに π_i = 状態 i に滞在する時間割合 (長時間平均 = 分布平均, エルゴード性)
```

「初期状態を忘れる」この性質が、定常分布を**長期挙動の要約**として使う根拠である: 予測器の定常ヒット率、キャッシュの定常ヒット率、ランダムウォークの訪問頻度(PageRank の原型)はすべて π の成分として計算される。収束の速さは P の第2固有値の大きさ |λ₂| で決まる(第2回 §で述べた冪乗法の収束と同じ機構)。これが「ウォームアップに何ステップ要るか」への理論的な答である。

### 3. ポアソン過程 — 連続時間への橋 (Poisson process)

時間を連続にすると、基本の構成要素は**ポアソン過程**(事象が率 λ で「完全にランダムに」起きる過程)になる。3つの同値な特徴づけが使い分けられる (Ross 2019, Ch. 5)。

```text
(1) 区間 t 内の事象数 ~ Pois(λt)
(2) 事象間隔が独立に Exp(λ) (無記憶性 — 前回 §4)
(3) 微小区間 dt に事象が起きる確率 = λ·dt (履歴に依らず)
```

ポアソン過程の合流・分岐は簡単に扱える(独立なポアソン流の和はポアソン、確率 p での間引きもポアソン)ため、「多数の独立なユーザーからのリクエスト到着」のモデルとして自然かつ計算可能である。ただし現実のトラフィックにはバースト性・自己相似性があり、ポアソン仮定は**楽観側に外れる**(バーストはポアソンより待ちを悪化させる)ことを常に注記すべきである。モデルの限界込みで使うのが実務の作法である。

### 4. M/M/1 待ち行列 (the M/M/1 queue)

最も基本的な待ち行列モデル: 到着がポアソン(率 λ)、サービス時間が指数分布(率 μ)、窓口1つ。キュー長(系内客数)は連続時間マルコフ連鎖になり、定常分布が閉形式で解ける (Kleinrock 1975, Ch. 3)。

```text
利用率:        ρ = λ/μ  (< 1 が安定条件)
定常分布:      P(系内に n 人) = (1−ρ)ρⁿ  (幾何分布)
平均系内数:    L = ρ/(1−ρ)
平均応答時間:  W = 1/(μ−λ) = (1/μ) × 1/(1−ρ)
```

決定的に重要なのは W の形である。応答時間はサービス時間 `1/μ` の **`1/(1−ρ)` 倍**に膨らむ。ρ = 0.5 で2倍、0.8 で5倍、0.9 で10倍、0.95 で20倍となる。

```text
ρ:  0.5   0.7   0.8   0.9   0.95  0.99
W/W₀: 2×    3.3×  5×    10×   20×   100×
```

**利用率と応答時間のトレードオフは双曲線であり、飽和近くでは利用率の数%がレイテンシの倍増に化ける**。「サーバの目標利用率をなぜ 70–80% に置くのか」「なぜ 95% で運用してはいけないのか」の定量的な答がこの1行にある。しかもこの爆発は平均の話で、分布 (1−ρ)ρⁿ の裾はρ→1 で急速に重くなる。テイルレイテンシは平均より先に悪化する。

### 5. リトルの法則 (Little's law)

到着率 λ、平均系内数 L、平均滞在時間 W の間には、**分布の形にも到着過程にも依らず**

```text
L = λW
```

が成り立つ (Little 1961)。仮定がほぼ要らない(定常であればよい)ため、M/M/1 のようなモデルが当てはまらない実システムでも使える、待ち行列理論で最も頑健な結果である。実務では3変数のうち2つを測って残りを推定する使い方をする。すなわち「同時実行数 = スループット × 平均レイテンシ」である。この形は、帯域遅延積(ウィンドウ = 帯域 × RTT)、ストレージの Queue Depth と IOPS・レイテンシの関係、コネクションプールのサイズ設計、リトルの法則ベースの負荷試験設計として、システム性能分析の全域に現れる。

## 工学への接続 (Engineering Connections)

- **予測器・状態機械の定量評価**: 2ビット飽和カウンタは4状態マルコフ連鎖であり、入力パターンの統計を与えれば定常ヒット率が計算できる (§1–2)。「この予測器はこのワークロードで何%当たるか」を測定の前に見積もる道具。
- **キャパシティプランニング**: 目標レイテンシから逆算して許容利用率を決める (§4)。「CPU 使用率 90% はまだ余裕」が誤りである理由(レイテンシは 1/(1−ρ) で既に10倍)を経営層に説明する言語でもある。
- **バッファサイズとバックプレッシャ**: キュー長の定常分布 (1−ρ)ρⁿ はバッファ溢れ確率を与え、NIC・スイッチのバッファ設計、アドミッション制御、バックプレッシャ発動閾値の根拠になる。
- **測定からの推定**: リトルの法則 (§5) は分散トレーシングの整合性チェックに使える。測った同時実行数・スループット・レイテンシが L = λW を満たさなければ、計測のどれかが間違っている。
