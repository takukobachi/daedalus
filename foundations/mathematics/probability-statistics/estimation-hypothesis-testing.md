# 推定と仮説検定 (Estimation and Hypothesis Testing)

## 概要 (Overview)

確率・統計シリーズの第3回。前2回は「分布が分かっているときに何が起きるか」を計算した(確率論)。本回は矢印を逆向きにする——**観測データから、背後の分布・パラメータについて何が言えるか**(統計的推測, statistical inference)。ベンチマークを10回走らせた、ウェハを50枚検査した、A/B テストを1週間回した——そこから「本当の平均」「本当の歩留まり」「本当に速くなったのか」を語るための道具である。

柱は3つ。(1) **点推定**——データからパラメータの最良の一点を得る原理(最尤推定)と、推定量の良さの物差し(バイアスと分散)。(2) **区間推定**——推定の不確かさを幅で表す信頼区間。中心極限定理(第1回)がここで働き、`1/√n` 則が測定計画を決める。(3) **仮説検定**——「差がある」という主張を、偶然では説明しにくいかどうかで審査する枠組みと、その誤用しやすさ(p 値の意味、多重比較)。最後に、事前知識を確率として組み込む**ベイズ推定**を対置し、2つの推測観の使い分けを整理する。統計は「数字に語らせる」技術であると同時に「数字に嘘をつかせない」技術である——後者の側面を一貫して強調する。

## 本論 (Main Content)

### 1. 推定という問題設定 (the estimation problem)

母集団の分布はパラメータ θ(平均、不良率、故障率 …)を持つが θ は見えない。見えるのは標本 X₁, …, Xₙ だけである。標本から θ を言い当てる関数 `θ̂ = g(X₁,…,Xₙ)` を**推定量 (estimator)** と呼ぶ。決定的に重要な視点: **推定量自身が確率変数である**——同じ実験を繰り返せば毎回違う値が出る。だから推定量の良さは分布で評価する (Casella & Berger 2002, Ch. 7)。

```text
バイアス:     bias = E[θ̂] − θ     (系統的なズレ)
分散:        Var(θ̂)              (実験ごとのばらつき)
平均二乗誤差: MSE = bias² + Var    (総合誤差の分解)
```

この分解は「不正確さには2種類ある」ことを言う——照準がずれている(バイアス)のと、手が震えている(分散)のは別の欠陥であり、対策も異なる。少しのバイアスを受け入れて分散を大きく下げる**バイアス–分散トレードオフ**は、正則化・シュリンケージ・機械学習の汎化理論まで貫く中心概念である。

### 2. 最尤推定 (maximum likelihood estimation, MLE)

点推定の第一原理は**最尤法**: 「観測されたデータが最も起こりやすくなるパラメータを選ぶ」。

```text
尤度:     L(θ) = P(データ | θ)   (データを固定し、θ の関数と見る)
最尤推定: θ̂_MLE = argmax_θ log L(θ)   (対数を取り、微分 = 0 で解く)

例: n 回中 k 回成功 → p̂ = k/n (直観と一致)
    正規標本 → μ̂ = 標本平均, σ̂² = 標本分散
```

MLE は一致性(n→∞ で真値に収束)と漸近正規性(誤差の分布が正規に近づき、分散も理論式で見積れる)を持ち、「原理・計算・保証」が揃った標準手法である (Wasserman 2004, Ch. 9)。現代的に重要なのは機械学習との等式——**交差エントロピー損失の最小化 = 負の対数尤度の最小化**、つまりニューラルネットの学習は巨大な MLE である。損失関数の設計が「データの確率モデルの選択」と同義になる、という視点はモデルのデバッグ(なぜこの損失か、外れ値になぜ弱いか)に直結する。

### 3. 信頼区間 — 不確かさを幅で語る (confidence intervals)

点推定だけでは「9.8 ms」と「9.8 ± 3 ms」の区別がつかない。中心極限定理(第1回 §5)により標本平均は `N(μ, σ²/n)` に近づくから、次の信頼区間が得られる。

```text
95% 信頼区間: X̄ ± 1.96·σ̂/√n
幅は 1/√n でしか縮まない — 精度1桁 = 測定100倍 (√n 則の再登場)
```

解釈の罠に注意する。「この区間に真値が 95% の確率で入っている」は頻度主義では厳密には誤りで、正しくは「**この手続きを繰り返せば、作った区間の 95% が真値を含む**」——確率は区間の作り方に付いており、目の前の1本には付いていない(その直観的な読み方をしたければ §5 のベイズへ)。実務上の効用は明確で、ベンチマーク結果に信頼区間を付ければ「9.8 ms vs 10.1 ms の差」が意味を持つか一目で判定でき、区間が重なり合う比較を「改善」と報告する誤りを機械的に防げる。

### 4. 仮説検定 — 偶然と区別できるか (hypothesis testing)

「新実装は速い」「このロットは不良率が高い」という主張を審査する枠組みを次に示す (Casella & Berger 2002, Ch. 8)。

```text
帰無仮説 H₀ (差はない・効果はない) を仮に立てる
p 値 = H₀ が真のとき、観測された以上に極端なデータが出る確率
p < α (慣習的に 0.05) なら H₀ を棄却 —「偶然では説明しにくい」

第一種の誤り (α): 差がないのに「ある」と言う (偽陽性)
第二種の誤り (β): 差があるのに見逃す。検出力 = 1 − β
```

正しく使う要点は3つ。(i) **p 値は「H₀ が正しい確率」ではない**——データの珍しさの尺度であって、仮説の確率ではない。(ii) **有意 ≠ 重要**——n を増やせばどんな微小な差も有意になる。効果量(差の大きさ)を必ず併記する。(iii) **多重比較**——20 個のメトリクスを α = 0.05 で検定すれば、全部無関係でも平均1個は「有意」になる。ダッシュボードを眺めて光った指標だけ報告する行為は、この誤りの自動生成器である(補正: Bonferroni ほか)。検出力分析(期待する効果量を α, β で検出するのに必要な n の逆算)は、実験を**走らせる前に**行う設計行為であり、「取ったデータで有意になるまで検定を繰り返す」(p-hacking) と対極にある。

### 5. ベイズ推定 — 事前知識の合成 (Bayesian estimation)

頻度主義が θ を未知の定数と見るのに対し、**ベイズ推定**は θ 自身に確率分布を認め、ベイズの定理(第1回 §2)でデータにより更新する。

```text
事後分布 ∝ 尤度 × 事前分布
P(θ | データ) ∝ P(データ | θ) · P(θ)

例 (Beta-Bernoulli): 事前 Beta(a,b) + n 回中 k 回成功 → 事後 Beta(a+k, b+n−k)
事後平均 = (a+k)/(a+b+n) — 「疑似カウント a, b を足した割合」
```

n が小さいとき事前分布が推定を安定化させ(シュリンケージ)、n が大きくなると尤度が支配して MLE に漸近する——「データが少ないうちは慎重、増えれば大胆」という望ましい振る舞いが式から自動的に出る (Gelman et al. 2013, Ch. 2)。1回きりで反復不能な事象(このロケットの成功確率、このシステムの障害確率)にも確率を語れること、逐次更新が自然なこと(オンライン学習・フィルタリング)が実務上の強みである。使い分けの目安: 反復可能な検査・実験の品質管理は頻度主義の道具が整備されており、少データ・逐次更新・事前知識の合成が本質的な場面はベイズが素直である——対立ではなく道具箱の2段である。

## 工学への接続 (Engineering Connections)

- **ベンチマークの作法**: 「平均だけ報告しない」「信頼区間を付ける」「分散の大きい環境 (クラウド) では n を検出力分析で決める」「複数メトリクスの探索的比較に多重比較補正」——§3–4 がそのまま性能評価のチェックリストになる。
- **統計的工程管理 (SPC)**: 管理図は「工程が管理状態 (H₀) にあるとき ±3σ を超える確率は 0.3%」という継続的仮説検定であり、歩留まり監視・装置異常検知の標準言語。第一種の誤り(正常なのに停止)と第二種の誤り(異常の見逃し)のコスト比較が管理限界の設計を決める (Montgomery 2013)。
- **信頼性試験の設計**: 「故障率 < λ を 90% 信頼度で示すには何台×何時間の試験が要るか」は §3–4 の逆算問題であり、加速試験・打ち切りデータの扱いを含めて信頼性工学の中核をなす(シリーズ第4回で詳述)。
- **学習 = 推定という視点**: 交差エントロピー = 負の対数尤度 (§2)、正則化 = 事前分布 (§5, MAP 推定)、バイアス–分散トレードオフ = 汎化理論 (§1)——機械学習の主要概念は統計的推測の語彙で書き直せ、この対応がモデル選択・過学習対策の理論的足場を与える。
