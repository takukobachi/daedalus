# オートマトンと形式言語 (Automata and Formal Languages)

## 概要 (Overview)

離散数学・論理シリーズの第3回・最終回。前回のグラフに「入力で駆動される遷移」を載せると**オートマトン (automaton)**——状態機械——になる。TCP の接続状態、TLS のハンドシェイク、正規表現エンジン、字句解析器、プロトコルパーサは、みなこの一つの数学的対象の実装である。

本回の中心となる問いは「**有限のメモリしか持たない機械は、何を認識できて、何を認識できないのか**」である。答えは驚くほど整然としている——有限状態＝正規言語＝正規表現であり（三者の等価性）、「括弧の対応を数える」ことは原理的にできず（反復補題）、スタックを足せば文法が解析でき（文脈自由言語）、無制限のメモリを足した途端に「このプログラムは止まるか」すら判定不能になる（停止性問題）。この階層は抽象論ではない。正規表現エンジンの2つの実装系譜と ReDoS 脆弱性、パーサの設計、eBPF 検証器が「プログラムを制限する」理由、静的解析が近似を強いられる根拠——現代のシステムの設計判断が、この階層のどこに立つかの選択として読める。

## 本論 (Main Content)

### 1. 決定性有限オートマトン (DFA)

**DFA** は5つ組 (Q, Σ, δ, q₀, F)——有限の状態集合 Q、入力アルファベット Σ、遷移関数 δ: Q×Σ→Q、初期状態 q₀、受理状態集合 F——である (Hopcroft et al. 2006, Ch. 2)。入力文字列を1文字ずつ読んで状態を移り、読み終えて受理状態にいれば**受理**。DFA が受理する文字列の集合がその**言語**であり、有限オートマトンで認識できる言語を**正規言語 (regular language)** と呼ぶ。

グラフとしてみれば DFA は辺に文字ラベルの付いた有向グラフであり、受理判定は「ラベルを消化しながらの経路追跡」、状態の意味は「**ここまでの入力について、将来のために覚えておくべきことのすべて**」である。この「状態＝十分な要約」という視点は確率・統計シリーズのマルコフ性と同じ設計原理であり、プロトコル状態機械の設計論そのものでもある。2つの DFA の直積（状態対の上で同時に走らせる）で言語の共通部分が認識でき、正規言語は和・積・補について閉じている——**フィルタの合成が状態機械の合成で書ける**根拠である。

### 2. 非決定性と部分集合構成 (NFA and subset construction)

**NFA** は遷移を関数から関係に緩め、同じ入力で複数の行き先（または ε 遷移＝入力なしの移動）を許す。「正しい選択肢を推測できる」機械であり、一見強力だが、認識能力は DFA と**同じ**である (Rabin & Scott 1959)。証明が構成的である点が重要で——**部分集合構成 (subset construction)**: NFA の「あり得る状態の集合」を1つの状態とみなす DFA を作れば、非決定性は状態集合の追跡に還元される。

```text
NFA (n 状態) → DFA (最大 2ⁿ 状態)
非決定性は消せる。ただし指数的な状態爆発の可能性と引き換え
```

この「同時にあり得る状態の集合を持ち歩く」操作は、正規表現エンジンのオンライン模擬（後述）としてそのまま実行もできる——**構成を先に行うか (DFA コンパイル)、実行時に行うか (NFA 模擬)** は、まさにコンパイラとインタプリタの関係である。

### 3. 正規表現との等価性 — 2つのエンジン系譜 (regular expressions)

**正規表現**（連接・選択 |・反復 * から成る式）が表す言語のクラスは、有限オートマトンの認識する言語のクラスと一致する。式→機械の方向は **Thompson 構成** (Thompson 1968)——各部分式を小さな ε-NFA に置き換えて配線する、式のサイズに線形の構成——で与えられる。

この定理の工学的な帰結が、正規表現エンジンの2系譜である。

```text
オートマトン系 (grep, RE2, Rust regex):
  Thompson NFA を模擬 (状態集合を持ち歩く) — 入力長 n に対し O(n·m) 保証
バックトラック系 (PCRE, Java, Python, JavaScript の既定):
  「選択肢を試して失敗したら戻る」深さ優先探索 — 後方参照など
  正規を超える機能を足せるが、最悪指数時間
```

バックトラック系に `(a|a)*` のような曖昧な式と不一致入力を与えると、試行の組合せが爆発する——これが **ReDoS (regular expression denial of service)** の機構であり、「数学的には線形時間で判定できる言語を、実装の系譜の選択によって指数時間で処理してしまう」事例として、理論と実装の距離を最も鮮明に示す。DFA の**最小化**（区別不能な状態の併合、Myhill–Nerode の同値関係）まで含め、正規言語の世界は「コンパイルして最適化できる」完結した代数を成す——Lucene の FST（辞書をオートマトンに圧縮し、ワイルドカード検索を式のオートマトンとの積として走らせる）はこの代数の応用である。

### 4. 有限メモリの限界とその先 — 反復補題と Chomsky 階層

有限オートマトンにできないことは何か。**反復補題 (pumping lemma)**: 十分長い文字列が受理されるなら、その経路は必ずどこかの状態を再訪しており（鳩の巣原理）、そのループ部分は何回繰り返しても受理される。ゆえに `aⁿbⁿ`（同数の a と b）は正規でない——**有限状態は無制限に数えられない**。「括弧の対応する言語を正規表現で解析してはならない」（HTML を正規表現でパースするな）の数学的根拠である。

数える能力を最小限足したのが**プッシュダウンオートマトン**（スタック1本付き有限オートマトン）で、認識するのは**文脈自由言語 (CFL)**——文法 (CFG) で生成され、プログラミング言語の構文の標準モデルである。さらにメモリを無制限にすると次節のチューリング機械に至る。この**メモリ構造と言語クラスの対応**が Chomsky 階層である (Sipser 2012, Ch. 1–3)。

```text
正規言語     ⊂ 文脈自由言語 ⊂ … ⊂ 帰納的可算言語
有限状態       +スタック          チューリング機械
字句解析       構文解析            プログラム一般
判定は O(n)    パーサで O(n)〜O(n³) 判定可能とは限らない
```

### 5. 計算可能性の壁 — 停止性問題と Rice の定理

**チューリング機械**（無制限のテープを持つ状態機械）が「計算できる」の数学的定義であり、既知のあらゆる計算モデルと等価である（Church–Turing のテーゼ）。そして Turing (1936) の中心結果: **停止性問題は判定不能**——「任意のプログラムと入力について、停止するか」を常に正しく答えるプログラムは存在しない。証明は対角線論法——判定器 H があると仮定し、「H が『止まる』と言ったら無限ループする」プログラムを H 自身に食わせて矛盾させる——であり、自己言及が有限の機械仕掛けで実現できてしまうことの帰結である。

**Rice の定理**はこれを一般化する: プログラムの**意味論的な**性質（何を計算するかに関する自明でない性質）は、すべて判定不能である。「このプログラムはメモリ安全か」「この入力検証は突破できるか」——静的解析が原理的に**近似**（偽陽性か偽陰性を必ず抱える）を強いられる根拠であり、また eBPF 検証器が「任意のプログラム」を諦めて**ループ制限・状態追跡付きの制限された言語**だけを受け入れる理由でもある。判定不能性は「諦めよ」ではなく「**問題のクラスを制限するか、近似を受け入れるかを設計として選べ**」という指令である——検証器・型システム・fuzzing はこの選択の異なる答である。

## 工学への接続 (Engineering Connections)

- **プロトコル状態機械** (§1): TCP の接続管理も TLS のハンドシェイクも DFA として仕様化される。実装が仕様の遷移関数から逸脱する（未定義の遷移を受け入れる）ことが状態機械バグであり、認証スキップ型の脆弱性の型である。
- **正規表現エンジンの選択** (§3): 入力が攻撃者由来なら線形時間保証のオートマトン系を使う。ReDoS は「機能（後方参照）と保証（線形時間）の交換」を知らずにバックトラック系を使った代償である。
- **パーサと言語クラス** (§4): 字句は正規、構文は文脈自由、という配置はメモリ構造と計算量の対応に基づく設計である。同じ入力を2つの実装が異なって解析する**パーサ差分**は、文法の曖昧さ・仕様逸脱がセキュリティ境界で悪用される形態である。
- **検索インデックスのオートマトン** (§3): FST による辞書表現、ワイルドカード・あいまい検索（編集距離オートマトン）との積——正規言語の閉包性が検索機能として製品化されている。
- **検証可能性の設計** (§5): eBPF の検証器・スマートコントラクトのガス制限・WASM の構造化制御フローは、いずれも「停止性・安全性が機械検証できるようプログラムのクラスを制限する」という同じ設計判断である。
