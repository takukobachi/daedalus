# 仮想ネットワークとオーバーレイ (Virtual Networks & SDN Overlays: VXLAN, EVPN & Cloud VPC)

## 概要 (Overview)

[`kernel-network-stack.md`](kernel-network-stack.md) は 1 台のホストの中でパケットを運ぶ機械を扱った。本ドキュメントはその 1 段上の層を扱う。すなわち、**マルチテナントデータセンター**で、数万のテナントそれぞれに「自分だけのネットワーク」(自前の IP 空間・トポロジ・完全な隔離) を、共有の物理設備の上で幻視させる機構である。走る事例としてクラウドの **VPC (Virtual Private Cloud)**、AWS 型の実装を用いる。

中心テーゼは、仮想ネットワークの本体が**パケット処理ではなく分散データベース**だということ。カプセル化 (encapsulation) 自体はヘッダを 1 枚足すだけの些事であり、難所は「テナント X の IP 10.0.0.5 は、いまどの物理ホストにいるか」という**マッピングを、数百万エンドポイント × 頻繁な変動 (VM の起動・移動・削除) のもとで全ホストに配り続ける**ことにある。VLAN が 12 ビット (4094 網) で尽き、L2 のフラッディングと STP がスケールで破綻するのに対し、オーバーレイは L2 の意味論をほぼ捨て、**L3 (IP ファブリック) の上に L3 (テナント網) を作る**。そしてマッピング分配の解 (フラッド学習・中央ディレクトリ・EVPN・OVN) の系譜は、そのまま [`../distributed-systems/consistency-models.md`](../distributed-systems/consistency-models.md) が扱った複製と一貫性の問題系である。

本書は (1) VLAN が届かない理由、(2) カプセル化 (VXLAN/Geneve) と MTU の税、(3) 制御平面 = マッピング分配の 4 方式、(4) データ平面 (OVS megaflow, SmartNIC/Nitro オフロード)、(5) セキュリティグループという分散ファイアウォール、(6) NAT と外界境界、を整理する。分析深度は Level 3。

## 方法論 (Methodology)

- **出典階層上の注意**: クラウド内部のアーキテクチャは主にベンダー自身の発表 (AWS re:Invent 講演、Azure/VMware の NSDI 論文) を通じてしか文書化されていない。本書はこれらを**ベンダー提示 (vendor-presented)** と明示的にラベルし、同じ問題を公開の場で解いている標準 (VXLAN/Geneve/EVPN の RFC) とオープン実装 (OVS/OVN) で相互検証する。設計空間の制約は共通なので、公開実装が「独立した傍証」として機能する。
- 各機構を「マッピング分配のどの困難 (規模・変動率・一貫性・障害時挙動) への対処か」で説明し、方式間の比較は交換条件の表として示す。
- ホスト内のパケット経路 ([`kernel-network-stack.md`](kernel-network-stack.md))、仮想化の I/O 経路 ([`../virtualization/hardware-virtualization-containers.md`](../virtualization/hardware-virtualization-containers.md))、物理ファブリック ([`../../engineering/datacenters/datacenter-fundamentals.md`](../../engineering/datacenters/datacenter-fundamentals.md)) は既存ドキュメントに委ね、本書は「その間を繋ぐ仮想化層」に集中する。

## 発見事項 (Findings)

1. **仮想ネットワークの本体はパケット処理ではなくマッピングの分配である。** カプセル化は固定長ヘッダの付け外しにすぎない。難しいのは (テナント, 仮想 IP) → 物理ホストという写像を、数百万エントリ・秒単位の変動のもとで、パケットを転送する全地点に配り続けることである。つまりこれは複製されたキーバリューストアの設計であり、キャッシュ・無効化・陳腐エントリという語彙 ([`../distributed-systems/consistency-models.md`](../distributed-systems/consistency-models.md)) がそのまま通用する。
2. **VLAN の破綻は ID 空間 (4094) だけではない。L2 の意味論そのものがスケールしない。** フラッディングと MAC 学習はブロードキャストドメインの全員に仕事を課し、STP は帯域を残して木を刈り、MAC テーブルは全 VM 分をコアスイッチに要求する。オーバーレイは ID を 24 ビットに広げただけでなく、**「未知宛先はフラッド」という L2 の前提を「マッピングは照会する」に置き換えた**点が本質である。
3. **オーバーレイは L2 の幻想を捨てて L3 の上に L3 を作る。** アンダーレイは ECMP で並列化された Clos の IP ファブリック ([`../../engineering/datacenters/datacenter-fundamentals.md`](../../engineering/datacenters/datacenter-fundamentals.md)) であり、その上のトンネルは単なる UDP フロー。テナントに見せる「サブネット」も実体は転送表の中の論理であり、AWS 型 VPC には ARP フラッドすら存在しない。仮想スイッチが ARP 応答を合成する。
4. **VPC は「ネットワークをデータベースとして実装した」システムである。** AWS がベンダー発表 (re:Invent CPN401 系) で示した構造は、マッピングサービスという中央ディレクトリをデータプレーンが照会・キャッシュするというものである。ルーティングプロトコルの収束ではなく、**信頼できる台帳 + キャッシュ無効化**で到達性を管理する。標準側の答え (EVPN) が BGP という複製プロトコルにマッピングを載せるのも、同じ問題の別解である。
5. **セキュリティグループはファイアウォール箱の分散実装である。ポリシーは経路上の箱からファブリック自体へ移った。** 全トラフィックを 1 台の中間箱 (middlebox) に通すのではなく、各ホストの仮想スイッチが接続追跡 (connection tracking) 付きのステートフィルタを ENI ごとに施行する。チョークポイントが消え、施行点はワークロードと同じ数だけ水平にスケールする。これはマイクロセグメンテーション (microsegmentation) の原型である。
6. **Nitro は仮想化のネットワーク税をホスト CPU から専用ハードへ移した。** カプセル化・マッピング照会・セキュリティグループ施行はかつてハイパーバイザの CPU を数割消費していた。AWS Nitro (ベンダー実証) はこの全処理を専用カードに移し、ホスト CPU を 100% テナントに売る。これは [`../../hardware/networking/nic-switch-architecture.md`](../../hardware/networking/nic-switch-architecture.md) の「境界の移動史」の終着点であり、Azure VFP + FPGA (NSDI '17/'18) が同じ結論に独立に到達している。
7. **フローキャッシュが「柔軟なポリシー」と「パケット単価」を両立させる。** OVS の megaflow は「最初の 1 発だけ全表を引き、以後は結果をキャッシュ」という構造で、ポリシーの一般性 (OpenFlow の多段表) と転送の速さを分離した。SmartNIC オフロードもこのキャッシュ層をハードに移すだけで、**例外処理はソフト・定常はキャッシュ**という分業は全実装に共通する。
8. **外界との境界では「到達性そのものが商品」になる。** NAT ゲートウェイはフローごとの状態を持つ (だから課金され、上限がある)。インターネットゲートウェイは 1:1 の無状態変換で済む。PrivateLink 型のエンドポイントは「インターネットを経ずにサービスへ届く」ことを製品として切り売りする。アドレス変換の実装形態が、そのままクラウドの課金モデルと障害特性を規定している。

## アーキテクチャ (Architecture)

### 貫通経路 — テナント VM から VM へ

テナント A の VM1 (10.0.0.5, ホスト X) が VM2 (10.0.0.9, ホスト Y) へ送る 1 パケットの経路を示す。

```
 ホスト X                                                ホスト Y
 ┌─────────────────────────┐                            ┌─────────────────────────┐
 │ VM1 (テナントA 10.0.0.5) │                            │ VM2 (テナントA 10.0.0.9) │
 │   │ ①送信 (dst 10.0.0.9) │                            │   ▲ ⑥配送                │
 │   ▼                      │                            │   │                      │
 │ 仮想スイッチ / Nitro カード│                            │ 仮想スイッチ / Nitro カード│
 │  ②SG 施行 (conntrack)    │      ┌──────────────┐     │  ⑤VNI→テナントA を確認    │
 │  ③マッピング照会:         │◄────►│ マッピング     │     │    SG 施行 → decap       │
 │   (A,10.0.0.9)→ホストY?  │ 照会/ │ サービス       │     │                          │
 │   (キャッシュ命中なら省略) │ 通知 │ (制御平面 DB)  │     │                          │
 │  ④encap:                 │      └──────────────┘     │                          │
 │  [IP X→Y][UDP][VXLAN     │                            │                          │
 │   VNI=A][元パケット]      │                            │                          │
 └───────────┬──────────────┘                            └───────────▲──────────────┘
             │              アンダーレイ (Clos IP ファブリック)        │
             └────► leaf ──► spine (ECMP で分散) ──► leaf ────────────┘
                    ファブリックは外側 IP しか見ない (テナント IP を知らない)
```

要点: アンダーレイの機材はテナントの存在を知らない。知っているのは両端の仮想スイッチと、写像を配る制御平面だけである。

### 制御平面の比較 — マッピングをどう配るか

| 方式 | 分配機構 | 規模の限界 | 一貫性の性格 | 代表 |
|---|---|---|---|---|
| フラッド学習 (flood-and-learn) | 未知宛先を IP マルチキャストで洪水し、応答から学習 | マルチキャスト状態がファブリック側に必要・洪水そのものが負荷 | 学習ベース (陳腐化はエージング任せ) | 初期 VXLAN (RFC 7348 の運用形) |
| 中央ディレクトリ (central directory) | マッピングサービスをデータプレーンが照会・キャッシュ | サービス自体の水平分割で伸ばす (ベンダー提示) | 台帳が正・キャッシュ無効化で追随 | AWS VPC (re:Invent 発表) |
| **EVPN** (BGP) | MAC/IP 経路を BGP (route reflector) で広告 | BGP の実証済みスケール・RT でフィルタ | 結果整合 (伝搬遅延中は陳腐) | RFC 7432、標準トラック |
| 論理フロー (OVN) | 中央 DB (Southbound DB) から各ホストへ論理フローを配布 | DB の複製・増分計算がボトルネック | DB 複製の整合性に従属 | OVN / NSX (NSDI '14) |

四者は「照会か事前配布 (push) か」「中央か分散か」の 2 軸で整理でき、フラッド学習以外はいずれも**ネットワークの収束をデータベースの複製に置き換えた**点で同型である。

### カプセル化の税 — ヘッダの会計

| 方式 | 追加ヘッダ (外側 Ethernet 除く) | 仮想網 ID | 拡張性 |
|---|---|---|---|
| VLAN (802.1Q) | 4B (タグのみ) | 12 bit = 4094 | なし |
| **VXLAN** | 外側 IPv4 20B + UDP 8B + VXLAN 8B = 36B (+外側 L2 で計約 50B) | 24 bit (VNI) | なし (固定ヘッダ) |
| **Geneve** | 同上の基部 + 可変 TLV オプション | 24 bit (VNI) | TLV でメタデータ搬送 |

1500B MTU のままオーバーレイを張ると内側の実効 MTU は約 1450B に落ち、テナントには「なぜかこの経路だけ大きいパケットが通らない」という形で漏れ出す。**カプセル化は透過を装うが MTU だけは隠しきれない** (対処は §1)。

## 技術詳細 (Technical Details)

### 1. カプセル化 — VXLAN, Geneve, そして MTU の税

- **VXLAN** (RFC 7348): 元のイーサネットフレームを [外側 IP][UDP][VXLAN ヘッダ 8B] で包む。**VNI (VXLAN Network Identifier)** は 24 ビットで約 1,677 万網あり、VLAN の 4094 を桁で置き換える。UDP を使うのは、外側 5-tuple のソースポートに内側フローのハッシュを書き込み、**アンダーレイの ECMP に内側フローを見せずに分散させる**ため。
- **Geneve** (RFC 8926): VXLAN の固定ヘッダに対し**拡張可能な TLV オプション**を持つ。テナント文脈・経由した論理ポート・遠隔での施行に必要なメタデータを「パケット自身に運ばせる」ための設計で、NSX/OVN 系はこちらへ向かった。ヘッダの拡張性は制御平面の語彙の拡張性である。
- **MTU の税**: VXLAN で約 50B、Geneve はオプション次第でそれ以上のヘッダが載る。アンダーレイの MTU を 9000B 級 (ジャンボフレーム) に上げるのがデータセンターの定石で、上げられない経路では内側の MSS を削るか経路 MTU 探索に頼ることになる ([`tcp-transport-congestion.md`](tcp-transport-congestion.md) の Mathis 式が示すとおり MSS はスループットの一次係数である)。NIC のトンネル対応オフロード (内側ヘッダのチェックサム・TSO) が欠けると、カプセル化はオフロードを全部剥がして CPU に落とす。**ヘッダ 50B の真の代価は帯域ではなくオフロードの互換性**である。
- encap/decap の実行地点はハイパーバイザの仮想スイッチ (OVS 等) が原点で、SmartNIC/DPU への移管が現在地 (§4)。

### 2. 制御平面 — マッピング分配の 4 方式

- **フラッド学習**: L2 の「未知はフラッド」をマルチキャストで模倣する。VNI ごとにマルチキャストグループを割り当て、未知宛先・ARP をそこへ流す。ファブリックにマルチキャスト状態を要求し、洪水量はテナント数に比例する。RFC 7348 自身が書く運用形だが、クラウド規模では最初に捨てられた。
- **中央ディレクトリ (AWS 型)**: AWS がベンダー発表で示した構造では、マッピングサービスという専用の分散サービスが (VPC, IP) → 物理ホストの台帳を持ち、各ホストのデータプレーンが**照会してキャッシュ**する。VM の移動・削除時は無効化を配る。初回パケットに照会レイテンシが載り、以後はキャッシュ命中となる。CPU キャッシュや DNS と同じ「読み最適化 + 無効化」の構図で、一貫性の設計点は [`../distributed-systems/consistency-models.md`](../distributed-systems/consistency-models.md) の語彙で読める (陳腐キャッシュ = 誤配ではなく到達不能に倒す、が安全側の設計)。
- **EVPN** (RFC 7432): 標準トラックの答え。MAC/IP とトンネル終端の対応を **BGP の経路**として広告し、route reflector で拡散、Route Target で「どの VNI の経路を誰が受け取るか」を絞る。BGP を選んだ理由は運用実績のある大規模複製プロトコルが他になかったからであり、BGP そのものの機構は [`ip-routing-bgp.md`](ip-routing-bgp.md) を参照。アンダーレイ (Clos の各リンク) も BGP で張るのが現代の定石で、**同じプロトコルが物理と仮想の 2 層で別の役を演じる**。EVPN はもともと MPLS 網の L2VPN として標準化されたもので、事業者網での使い方は [`mpls-segment-routing.md`](mpls-segment-routing.md) が扱う。
- **OVN / 論理フロー (NSDI '14)**: 望みのトポロジを中央 DB (Northbound) に書くと、論理フロー表に翻訳され (Southbound)、各ホストの OVS が物理フローに具体化する。「ネットワークの状態 = DB の内容」という等式を最も率直に実装した公開系であり、AWS 型の内部を推定する際の公開参照実装として機能する。

### 3. データ平面 — OVS megaflow と例外・定常の分業

- OVS (NSDI '15) は**カーネル/ユーザ空間分割**を採る: 最初のパケットはカーネルで表に当たらず userspace の `ovs-vswitchd` へ上がり (slow path)、全段のポリシー表を評価した**結果**をカーネルにキャッシュする (fast path)。
- キャッシュの単位は **megaflow** である。これは完全一致 (microflow) ではなく、「評価に実際に使われたフィールドだけ」をワイルドカード化した集約エントリで、1 エントリが多数のフローを吸収しキャッシュミス率を桁で下げる。ポリシーの一般性と転送単価の分離、という [`kernel-network-stack.md`](kernel-network-stack.md) の単価の経済のオーバーレイ版である。
- **接続追跡**: ステートフルなセキュリティグループ (§5) は conntrack を要求する。OVS はカーネルの conntrack を `ct()` アクションとして呼び出し、「この方向の接続は確立済みか」をフロー評価に組み込む。状態を持つ分、テーブル枯渇という攻撃面も持ち込む ([`kernel-network-stack.md`](kernel-network-stack.md) の SYN flood と同型)。conntrack の状態機械と表の枯渇は [`packet-filtering-conntrack.md`](packet-filtering-conntrack.md) で扱う。
- **SmartNIC/DPU オフロード**: megaflow キャッシュと conntrack をカードのハード (eSwitch) に移し、例外だけホストに上げる。**AWS Nitro** はさらに進み、仮想スイッチ・マッピング照会・SG 施行・カプセル化のすべてを専用カードで実行する (ベンダー実証)。ホスト CPU のネットワーク税はゼロになり、かつテナントのコードとネットワーク施行が**別の計算機**に分離される。ハード構造は [`../../hardware/networking/nic-switch-architecture.md`](../../hardware/networking/nic-switch-architecture.md)、SR-IOV/virtio との接続は [`../virtualization/hardware-virtualization-containers.md`](../virtualization/hardware-virtualization-containers.md) を参照。

### 4. セキュリティグループ — 分散ステートフルファイアウォール

- **施行の意味論**: ENI (仮想 NIC) 単位・**デフォルト拒否 (inbound)**・ステートフル。許可した方向の接続の戻りは自動許可 (conntrack が対応付ける)。ルールは「どこかの箱」ではなく**送信元ホストと宛先ホストの仮想スイッチ/Nitro カード**で施行される。
- **NACL との対比**: ネットワーク ACL はサブネット境界の**ステートレス**フィルタで、戻り方向 (エフェメラルポート) を明示的に開ける必要がある。SG が「ワークロードに紐づく意図」、NACL が「境界の粗い防波堤」という役割分担で、後者は前者の誤設定への多層防御 (defense in depth) として機能する。
- **一般原理**: ファイアウォールという機能が中間箱から**ファブリック自体**へ移った。施行点はワークロード数に比例して増え、チョークポイントの帯域上限が消え、ポリシーは「ネットワーク位置」ではなく「ワークロードの同一性」に付く。オンプレミス側で同じ動きを指す語がマイクロセグメンテーションであり、Azure VFP (NSDI '17) は同じ層を「per-NIC のプログラマブルフロー処理」として定式化した公開文献である。

### 5. NAT とインターネット境界 — 到達性の会計

- テナント網は私設アドレス空間 (RFC 1918) であり、外界との接点はすべて**明示的な変換点**を通る。
- **インターネットゲートウェイ**: パブリック IP ↔ プライベート IP の **1:1 無状態**変換。フロー状態を持たないため水平に増やせ、事実上ボトルネックにならない。
- **NAT ゲートウェイ**: 多:1 の **PAT (Port Address Translation)** である。フローごとに (内側 IP:port ↔ 外側 port) の対応を**状態として保持**する。状態はメモリと上限 (同時フロー数・ポート枯渇) を意味し、だから NAT ゲートウェイは課金され、スケール単位を持ち、障害時に全フローを失う。「**ステートレスは無料に近く、ステートフルは商品になる**」という会計が境界設計を貫く。
- **egress-only / エンドポイント型**: 外向きのみ許すゲートウェイ (IPv6 の egress-only IGW が明示形)、および **PrivateLink 型エンドポイント**がある。後者はサービス側の VPC へマッピング層で直結し、インターネットも NAT も経ない。到達性のトポロジそのものを API で売る形態であり、「ネットワーク = データベース」観の帰結 (行を足せば経路が生える) である。

## セキュリティ考察 (Security Considerations)

- **テナント隔離こそが製品保証である。** VPC の売り物は帯域ではなく「他テナントのパケットは決して届かない」という不変条件であり、その施行点はカプセル化境界に集中する。したがって**ファブリックはテナントが作ったカプセル化ヘッダを決して受理してはならない**。VM が VXLAN/Geneve ヘッダ付きパケットを自作して送っても、仮想スイッチはそれを「内側ペイロード」として再カプセル化するだけで、外側ヘッダとして解釈する経路が存在しないこと (および decap 時に VNI と送信元ホストの正当性を検証すること) が隔離の根拠になる。VNI は認証子ではなく識別子であり、正当性は制御平面が保証する。
- **制御平面の侵害は爆心半径が最大である。** マッピングサービス/EVPN リフレクタ/OVN の中央 DB を書き換えられれば、任意のテナントのトラフィックを任意のホストへ誘導できる。暗号化 (テナント側の TLS 等) が最後の防衛線として意味を持つのはこのためであり、制御平面の認証・監査・変更経路の分離は物理ルータの管理面より一段高い密度に値する。
- **サイドチャネルと noisy neighbor** (概観レベル): 共有ファブリック・共有 NIC キュー・共有 conntrack テーブルは、輻輳やレイテンシ変動を通じて他テナントの存在・活動量を漏らしうる。帯域の隔離は QoS で近似できるが、観測面の共有は原理的に残る。「共有 = 観測面」の一般則 ([`kernel-network-stack.md`](kernel-network-stack.md)) の仮想化版。
- **誤設定は境界の内側から来る。** SG の過剰開放 (0.0.0.0/0) はクラウド侵害の定番始点であり、NACL・ルート表・エンドポイントポリシーの多層が「1 枚の誤設定 ≠ 露出」を保つ。分散施行は箱の障害を消したが、**ポリシーの複雑性はテナント側に移った**。
- **メタデータサービスは攻撃面である。** 169.254.169.254 の IMDS はインスタンスに資格情報を配る仕組みだが、アプリ層の SSRF がそのまま資格情報窃取につながる事故類型が公知である (2019 年の大手金融の漏えい事例が典型)。**IMDSv2** はセッション指向 (PUT でトークン取得・TTL ヘッダ必須・ホップ制限 1) にすることで、単純な SSRF・誤ったプロキシ転送を遮断する。「リンクローカルの便利機構」が信頼境界そのものになった例として記憶に値する。

## 結論 (Conclusions)

- 仮想ネットワークとは「L3 ファブリックの上のトンネル + マッピングの分散データベース」であり、後者が本体である。VLAN → VXLAN の進化は ID のビット数の話ではなく、「フラッドで学習する L2」から「台帳を照会する L3」への意味論の交代だった。
- 制御平面の 4 方式 (フラッド学習・中央ディレクトリ・EVPN・OVN) は、複製データベースの設計空間 (push/pull・中央/分散・一貫性の強さ) をそのままなぞる。クラウドのネットワーク運用が「収束を待つ」から「行を書く」へ変わったのは、この置き換えの帰結である。
- データ平面は「例外はソフト・定常はキャッシュ」の分業で単価を払い、そのキャッシュ層ごと SmartNIC/DPU へ移った。Nitro はネットワーク税の消滅と施行点の物理的分離を同時に達成しており、性能の設計がそのまま信頼境界の設計になっている。
- ポリシー (ファイアウォール・NAT・到達性) は経路上の箱からファブリックとホストへ分散し、API で操作される状態になった。その代償として、制御平面とメタデータ機構という新しい一点急所が生まれた。仮想ネットワークのセキュリティ分析は、パケットではなくこの台帳と資格情報の流れを追うことから始まる。
