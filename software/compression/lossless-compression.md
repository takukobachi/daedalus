# 可逆圧縮の機構 (Lossless Compression Internals)

## 概要 (Overview)

可逆圧縮 (lossless compression) は「バイト列を、完全に復元できる形で短くする」機構である。gzip がテキストを 1/3 にし、zstd がストレージエンジンのページを縮め、Gorilla 型符号化が時系列メトリクスを 1/10 にする——これらは別々の技巧に見えるが、内側は同じ2部構成である。すなわち「**次に来る記号の確率を見積もるモデル (model)**」と、「**その確率どおりにビットを割り当てるエントロピー符号器 (entropy coder)**」。理論
([`../../foundations/information-theory/entropy-source-coding.md`](../../foundations/information-theory/entropy-source-coding.md))
は、後者の下限が確率の自己情報量 −log₂ p であることと、全体の下限がエントロピーであることを保証する。したがって可逆圧縮の工学とは、**符号器を理論限界に張り付かせた上で、モデルの質と速度を取引する**営みである。

本ドキュメントは、この分解を座標系として主要フォーマット——DEFLATE (gzip/zlib/PNG)、zstd、brotli、lz4、xz/LZMA——を Level 3 で読む。到達点は2つ。第一に、これらが LZ77 という1つのモデル族の速度・圧縮率パレート面上の点の選び直しにすぎないこと。第二に、汎用圧縮の手前に置く**データ固有の可逆変換**（delta、XOR、bit-packing、列指向化）こそが、実システムで桁を稼いでいる部分だということである。

## 方法論 (Methodology)

- すべての圧縮器を「モデル＋エントロピー符号」に分解し、フォーマット間の差を (a) モデルの記憶（どこまで過去を見るか）、(b) 符号器の精度（Huffman/算術/ANS）、(c) 探索の努力（圧縮レベルの実体）の3軸に射影する。
- 理論限界との距離を常に併記する——エントロピー符号の损失は §技術詳細で定量化し、「なぜ Huffman で足りる場面と足りない場面があるか」を確率の形から説明する。
- 一次資料は原論文 (Ziv–Lempel, Huffman, 算術符号, ANS) と仕様 (RFC 1951/7932/8878) に取る。速度・圧縮率の具体値は実装・データ・世代依存が大きいため、絶対値でなく**桁と序列**（lz4 ≫ zstd ≫ brotli/xz の速度順、圧縮率はその逆）だけを主張する。
- 専用変換 (§技術詳細 5) は、既存分析文書が個別に記述してきたもの（Gorilla、Parquet、WAL 圧縮）を横串で一般化する。

## 発見事項 (Findings)

1. **可逆圧縮器は例外なく「モデル＋エントロピー符号」に分解できる。** gzip = LZ77 モデル + Huffman 符号、zstd = LZ77 + FSE (ANS 系)、xz = LZ77 拡張 + レンジ符号器 (算術系)、PPM/cmix 系 = 文脈モデル + 算術符号。「圧縮アルゴリズムの発明」とは実際にはモデルか符号器のどちらかの改善であり、両者は独立に交換できる部品である。

2. **LZ77 の本質は「入力自身を辞書にする」ことによる普遍性である。** 事前にデータの統計を知らなくても、繰り返しが現れさえすれば漸近的にエントロピーへ収束する (Ziv & Lempel 1977)。この普遍性 (universality) が、LZ 系が 50 年近く汎用圧縮の主役であり続ける理由である——データの種類を選ばない。

3. **エントロピー符号の系譜は「精度と速度の和解」の歴史である。** Huffman (1952) は記号ごとに整数ビットを割り当てるため、確率が 2 の冪から外れると理論限界から最大 1 ビット/記号損する。算術符号 (1976–87) は記号列全体を1つの区間に写して端数ビットまで回収するが、乗算・除算の連鎖で遅い。ANS (Duda 2013) は算術符号と同等の精度を**テーブル参照と整数演算**で達成し、zstd (FSE) 以降の世代交代を駆動した——理論限界への到達と実装速度が、60 年かけて初めて両立した。

4. **実用の主戦場は圧縮率ではなく、スループットとのパレート面である。** ストレージ・ネットワークの内側では「圧縮が I/O より遅ければ本末転倒」という制約が支配し、lz4（GB/s 級・圧縮率控えめ）と zstd（数百 MB/s・gzip 超の圧縮率）が汎用の答えになった。圧縮レベルの実体は符号の変更ではなく**マッチ探索の努力量**であり、復号速度がレベルにほぼ依存しない（探索は圧縮側だけの仕事）ことが、「一度圧縮して何度も読む」配信・ストレージで高レベルを正当化する。

5. **桁を稼ぐのは汎用圧縮器ではなく、その手前の専用変換である。** 時系列の delta-of-delta と XOR 符号化 (Gorilla)、列指向フォーマットの bit-packing・辞書符号化 (Parquet)、PNG のフィルタ、実行ファイル向けの BCJ 変換——データの構造を知る可逆変換が冗長性をエントロピー符号の見える形に「露出」させ、しばしば汎用圧縮単体より1桁良い結果を出す。**圧縮パイプラインの設計とは変換の設計である。**

6. **圧縮は秘密を漏らし、資源を爆発させる攻撃面でもある。** 圧縮後サイズは平文の内容に依存するため、暗号化と併用すると内容が推測できる (CRIME/BREACH)。また高い圧縮率は少ないバイトで巨大な出力を注文できることを意味し (zip bomb)、展開側の資源管理を必須にする。

## アーキテクチャ (Architecture)

### 圧縮パイプラインの共通構造

```text
入力バイト列
   │
   ▼
[前処理変換]  データ固有の冗長性を露出させる可逆変換
   │           delta / XOR / bit-packing / BWT / 列指向化 / フィルタ
   ▼
[モデル]      「次の記号」の確率を見積もる
   │           LZ77 マッチ (長さ,距離) / 文脈モデル / 静的頻度表
   ▼
[エントロピー符号]  確率 p の記号に −log₂p ビットを割り当てる
   │           Huffman / 算術・レンジ符号 / ANS(FSE)
   ▼
圧縮ビット列 (+ 復元に要るメタデータ: 頻度表・辞書 ID・チェックサム)
```

### 主要フォーマットの部品対応

| フォーマット | モデル | エントロピー符号 | 特徴 |
|---|---|---|---|
| DEFLATE (gzip/zlib/PNG) | LZ77, 窓 32 KiB | Huffman | RFC 1951。遍在性が最大の資産 |
| lz4 | LZ77 | **なし**（バイト整列のまま） | 符号を捨てて GB/s 級を取る |
| zstd | LZ77, 窓 ~MiB 級 + 学習辞書 | FSE (ANS) + Huffman | RFC 8878。速度と率の現代的均衡 |
| brotli | LZ77 + 文脈モデリング | Huffman (文脈依存) | RFC 7932。Web 静的資産向け、組込み辞書 |
| xz/LZMA | LZ77 拡張, 窓 ~GiB 級 | レンジ符号器 (算術系) | 最高率側。遅いが「一度だけ圧縮」用途 |
| bzip2 | BWT + MTF | Huffman | ブロックソート系の代表（現在は zstd に譲る） |

lz4 の行が示すとおり、**エントロピー符号は省略可能な部品**である——マッチのコピーだけで LZ の大部分の利得は得られ、残る数十 % を回収するかどうかが速度との取引になる。

## 技術詳細 (Technical Details)

### 1. LZ77 — マッチという名の確率モデル

LZ77 は入力を「直近 W バイト（窓）のどこかに現れた列の再演」として符号化する——出力は (距離, 長さ) 対とリテラルの列である。これがモデルと呼べるのは、「一度現れた列は再び現れやすい」という仮定の下で、マッチは高確率事象＝短い符号、初出リテラルは低確率事象＝長い符号、という割当てを実現しているからである。Ziv–Lempel の定理は、定常エルゴード的な情報源に対しこの方式の圧縮率がエントロピーに漸近することを示す——**データの分布を知らずに限界へ収束する**（普遍性）。

実装の主戦場はマッチ探索である。ハッシュ表で直近の出現位置を引く（lz4, zstd 低レベル）、ハッシュチェーン・二分木で複数候補を比較する（zstd 高レベル, DEFLATE の `--best`）、最適パース（全体最適のマッチ分割を動的計画法で選ぶ）——**圧縮レベルとはこの探索努力のダイヤルであり、フォーマットは変わらない**。ゆえに復号は常に速い: 出力バッファからの memcpy の列にすぎず、これが「圧縮は一度、展開は百万回」の CDN・パッケージ配布・ゲームアセットで決定的に効く。

窓サイズは「モデルの記憶の長さ」である。DEFLATE の 32 KiB は 1990 年代のメモリの妥協であり、zstd の MiB 級・long-range mode の GiB 級への拡大は、バックアップ・スナップショットのような遠距離重複を持つ現代のデータへの適応である。**小さな独立ブロックを大量に圧縮する場合**（ストレージのページ、RPC のメッセージ）は窓が育つ前に入力が終わってしまう——zstd の**学習辞書 (dictionary training)** は、サンプル群から共通パターンを事前抽出して「窓の初期値」として配る機構であり、小データ圧縮の実務上の主解である。

### 2. Huffman 符号 — 整数ビットの限界まで

Huffman 符号は頻度表から二分木を貪欲に構成し（最小頻度の 2 節点を繰り返し併合）、記号ごとに整数長の符号語を割り当てる。期待符号長は H ≤ L < H+1 を達成し、**記号単位の整数長符号としては最適**である (Huffman 1952)。弱点はまさに「整数」にある——確率 0.99 の記号の情報量は 0.014 ビットだが、Huffman は 1 ビット未満を割り当てられない。歪んだ分布（RLE 後のゼロの列、二値の文脈）では限界から大きく離れる。

実装面の要点は2つ。(i) 復号はビット列→表引きで高速化でき（canonical Huffman: 符号長だけ伝えれば木を規約で再構成できる）、(ii) 頻度表自体の転送コストがあるため、小ブロックでは静的表 (DEFLATE の fixed Huffman) と動的表を選択する。

### 3. 算術符号と ANS — 端数ビットの回収

算術符号 (arithmetic coding) は記号列全体を [0,1) の入れ子の区間に写す——各記号で現在区間をその確率比で分割し、最終区間内の1点を出力する。記号ごとの消費は正確に −log₂p ビットで、**確率が偏るほど Huffman との差が開く**。さらに決定的な利点として、**文脈ごとに確率を毎記号切り替えられる**——適応的文脈モデル (PPM、そして動画符号化の CABAC) と組み合わせて初めて真価が出る。代償は乗除算の逐次依存で、長らく「率は最良、速度は最悪」の位置にあった（初期には特許の障壁もあった）。

**ANS (asymmetric numeral systems)** は同じ端数精度を別の機械で達成する (Duda 2013)。状態を1つの整数 x に持ち、記号 s を「x を確率 p(s) に反比例して伸ばす」写像で吸収する——復号はその逆写像で、**表引き＋シフトだけで進む** (tANS/FSE)。算術符号と違い復号が後入れ先出し（LIFO）になるため記号列を逆順に符号化する、という癖はあるが、実装は分岐が少なくスーパースカラに優しい。zstd の FSE、JPEG XL、Linux カーネルの zstd 採用——2010 年代後半の圧縮の世代交代は、ほぼこの1つの発明が駆動した。

### 4. フォーマットの設計読解 — zstd を例に

zstd (RFC 8878) は本ドキュメントの分解がそのまま設計図になっている。フレーム → ブロックの構造を持ち、各ブロックは LZ77 の出力を**リテラル列**と**シーケンス列 (リテラル長, マッチ長, 距離)** に分離し、それぞれを独立のエントロピー符号（リテラルは Huffman、シーケンスの各成分は FSE）で圧縮する。距離の「直近 3 距離の再利用符号」は構造化データの周期性への文脈モデルであり、負荷の重い成分ごとに符号器を選び分けるこの構成は「モデルと符号の分離」の教科書的実装である。圧縮レベル (1–22) は探索（ハッシュ→チェーン→二分木→最適パース）と窓の段階選択に対応し、復号器は全レベル共通——**非対称性の設計**が貫かれている。

### 5. 専用変換 — 構造を知る者が桁を稼ぐ

汎用圧縮器は「バイト列の繰り返し」しか見えない。データの構造を知る前段変換が、冗長性を繰り返しの形に露出させる:

- **delta / delta-of-delta**: 単調増加のタイムスタンプは差分を取ると小さな整数の列になり、等間隔なら二階差分はほぼ 0 の列になる (Gorilla)。
- **XOR 符号化**: 浮動小数点の隣接値は指数部・仮数上位が一致しやすく、XOR を取ると先頭・末尾のゼロが支配的になる——ゼロ長を短符号で送る (Gorilla; 時系列 DB の標準装備)。
- **bit-packing / frame-of-reference**: 列指向フォーマット (Parquet) は「この列の値は min〜max に収まる」を使い、必要ビット数だけで詰める。辞書符号化は低カーディナリティ列を ID 列に変える。
- **BWT (Burrows–Wheeler 変換)**: 全回転の辞書式整列で「似た文脈の次の文字」を隣接させる可逆並べ替え (Burrows & Wheeler 1994)。bzip2 の中核で、ゲノム索引 (FM-index) として検索構造にも転生した。
- **フィルタ**: PNG の行間予測、実行ファイルの相対ジャンプ絶対化 (BCJ)。

共通原理は1つ——**変換自体は 1 バイトも縮めない。縮むのは、変換後の分布のエントロピーが下がる（偏る）からである**。パイプライン設計の実務は「どの変換でどの冗長性を露出させ、残りを汎用圧縮に渡すか」の分担設計に帰着する。

### 6. 運用の勘所 — どこで圧縮するか

同じデータがスタックの複数層で圧縮候補になる（アプリの JSON → HTTP (gzip/br/zstd) → TLS → ストレージエンジンのページ → ファイルシステム → SSD 内部）。二重圧縮は CPU を捨てるだけなので、「**最もデータの構造を知る層で一度だけ**」が原則である。また圧縮率はスループットだけでなく**レイテンシの尾**にも効く——ページ圧縮は I/O を減らす代わりに展開を読み経路の同期コストにするため、ホットパスでは lz4 系、コールドデータでは zstd 高レベル、という温度別の使い分けが LSM ツリーの層別圧縮 (RocksDB) の定石になっている。

## セキュリティ考察 (Security Considerations)

- **圧縮は平文の性質をサイズに漏らす**: 暗号化はサイズを隠さない。攻撃者制御の文字列と秘密が同じ圧縮文脈に入ると、圧縮後サイズの変化から秘密を1文字ずつ確定できる (CRIME (2012)/BREACH (2013))。対策は「秘密と攻撃者入力を同じ圧縮文脈に入れない」——TLS レベル圧縮の廃止 (TLS 1.3)、HTTP 圧縮からの秘密の分離、HPACK/QPACK が採った「ヘッダは Huffman のみ・辞書は明示管理」という設計は、この教訓の制度化である。
- **展開は資源の増幅器**: 数 KiB の入力が数十 GiB に展開しうる (zip bomb; 入れ子 zip や DEFLATE の理論比 ~1:1032)。展開側は**出力量・入れ子深さ・メモリの明示的上限**を持たねばならない。アーカイブのパス (`../`) 検証 (zip slip) も同族の「入力を信じない」問題である。
- **パーサとしての圧縮ライブラリ**: zlib・xz・各種アーカイバは「信頼できない入力を解釈する C 言語のパーサ」であり、メモリ安全性の主要な攻撃面である。xz-utils 事件 (2024, CVE-2024-3094) は、圧縮ライブラリが「あらゆる場所にリンクされる」ことをサプライチェーン攻撃の足場に変えた——遍在性は資産であると同時に攻撃価値である。
- **辞書は共有状態**: zstd の外部辞書や brotli の組込み辞書は復号の前提条件であり、辞書の取り違え・改竄は誤復号や攻撃面になる。辞書 ID・チェックサムの検証はフォーマットの一部として扱う。

## 結論 (Conclusions)

可逆圧縮は「モデル＋エントロピー符号」という2部品の組合せであり、理論
([`../../foundations/information-theory/entropy-source-coding.md`](../../foundations/information-theory/entropy-source-coding.md))
が符号器側の下限を固定した今、進歩の余地はモデル側——どの冗長性を、どれだけの計算で見つけるか——に集中している。LZ77 の普遍性が汎用の座を守り、ANS が理論限界と実装速度をようやく和解させ、実システムの利得の大半はデータ構造を知る前段変換が稼ぐ。設計者への含意は3つ: (1) 圧縮の選定は率ではなく**速度・率パレート面上の位置**で行う、(2) 構造を知る層で一度だけ圧縮する、(3) 展開側を「信頼できない入力の増幅器」として資源制限とともに設計する。ニューラルモデルによる「圧縮＝予測」の直接実装（ロードマップ参照）は、モデル側の伸び代がまだ大きいことを示唆している。
