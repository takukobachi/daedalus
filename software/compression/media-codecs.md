# 映像・音声コーデックの構造 (Video & Audio Codec Architecture)

## 概要 (Overview)

インターネットトラフィックの過半は圧縮された映像である。生の 1080p60 映像は約 3 Gbps あり、これが配信では 5 Mbps 前後——**約 1/600**——まで縮む。可逆圧縮が届くのはせいぜい 1/2〜1/3 だから、残りは情報を**捨てる**ことで稼いでいる。非可逆圧縮 (lossy compression) の理論的な枠組みはレート歪み理論
([`../../foundations/information-theory/channel-capacity-coding.md`](../../foundations/information-theory/channel-capacity-coding.md) §5)
——「許す歪みを決めれば最小レートが決まる」——であり、コーデックの工学とはこの曲線に、**人間の知覚が気づかない歪みだけを選んで**近づく営みである。

本ドキュメントは JPEG から H.264/AVC、HEVC、AV1 までの映像符号化と、MP3 から Opus までの音声符号化を、共通の4段スケルトン——**予測 (predict) → 変換 (transform) → 量子化 (quantize) → エントロピー符号化 (entropy code)**——で Level 3 で読む。世代間の差はこの骨格の交換ではなく各段の洗練であり、情報を捨てる段は**量子化ただ1箇所**である。この見取り図の上で、レート制御、規格が定めるのはデコーダだけという非対称、ハードウェアコーデックの位置づけ、そしてコーデックパーサという攻撃面（Stagefright）までを繋ぐ。

## 方法論 (Methodology)

- すべてのコーデックを予測→変換→量子化→エントロピー符号の4段に分解し、世代比較（JPEG → H.264 → HEVC → AV1）を「各段に何が足されたか」の差分として整理する。
- 一次資料は標準規格の overview 論文 (IEEE TCSVT/Proc. IEEE) と RFC に取る。圧縮率の世代間比較（「同品質で約半分」）は各 overview 論文が報告する主観評価ベースの目安であり、コンテンツ・実装依存で大きく振れる**目標値**として扱う。
- 「規格はビットストリームとデコーダのみを規定し、エンコーダは自由」という非対称を一貫した視点とし、品質差・レート制御・知覚最適化はすべてエンコーダ側の自由度として読む。
- 知覚モデル（視覚の空間周波数感度、聴覚のマスキング）は、歪み尺度がなぜ単純な二乗誤差でないのかの根拠として、工学的に必要な深さまでに留める。

## 発見事項 (Findings)

1. **すべての主要コーデックは同じ4段で構成され、情報を捨てるのは量子化だけである。** 予測・変換・エントロピー符号は可逆な「並べ替え」であり、冗長性を量子化が捨てやすい形に露出させる係である。この構造は可逆圧縮の「モデル＋エントロピー符号」([`lossless-compression.md`](lossless-compression.md)) に「量子化」という1段を挿入したものと正確に読める。

2. **動画圧縮の主役は変換ではなく予測である。** フレーム間の動き補償予測 (motion compensation) が桁を稼ぎ、DCT はその残差の後始末をする。1/600 の内訳はおおまかに「時間方向の予測が桁、空間方向の変換・量子化が桁、エントロピー符号が数十 %」であり、世代進化の大部分は予測の細分化（ブロック分割の柔軟化、参照フレームの増加、イントラ予測方向の増加）に投資されてきた。

3. **規格はデコーダだけを縛る。** ビットストリーム文法と復号結果は規定されるが、「どう探索し、どこにビットを使うか」はエンコーダの自由である。同じ H.264 でも x264 とハードウェアエンコーダで品質が大きく違うのはこのためであり、規格年次だけでは品質を語れない。エンコーダの進歩は規格公開後も何年も続く（psy 最適化、適応量子化、シーン検出）。

4. **世代あたり「同品質で約半分」を、計算量の桁上がりで買っている。** H.264 → HEVC → AV1/VVC は各世代ざっくり 30–50 % のビットレート削減を主張するが、探索空間（ブロック分割・予測モード・参照構造）の爆発でエンコード計算量は桁で増える。採用の律速は技術よりむしろ特許ライセンスの経済（HEVC の分裂したパテントプール vs ロイヤリティフリーを掲げる AV1/AOM）である。

5. **音声符号化の主役は音響心理モデルである。** 聴覚は強い音の近傍（周波数・時間）の弱い音を知覚できない（マスキング）。MP3/AAC はこのマスキング閾値の下に量子化雑音を「隠す」ことで 1/10 を達成した。Opus (RFC 6716) は音楽向け変換符号化 (CELT) と音声向け線形予測 (SILK) を単一コーデックに統合し、~20 ms 級の低遅延で VoIP から音楽配信までを覆う——リアルタイム通信では符号化遅延が圧縮率と同格の設計変数である。

6. **ハードウェアコーデックは品質ではなく電力とスループットの装置である。** モバイル SoC・GPU の専用ブロック (NVENC 等) は 4K60 実時間・数百 mW を実現するが、探索予算が固定されるため同ビットレート品質はソフトウェアエンコーダの高プリセットに劣るのが通例。録画・ビデオ会議はハード、VOD の事前エンコードはソフト多パス、という分業が成立している。

7. **コーデックは「信頼できない入力を解釈する複雑なパーサ」であり、モバイル史上級の攻撃面になった。** Android の Stagefright (2015) は MMS で届く動画のメタデータ解析だけで RCE に至り、以後のメディアスタックのプロセス分割・サンドボックス化 (Codec2) と、ブラウザのレンダラ隔離におけるデコーダの位置づけを規定した。

## アーキテクチャ (Architecture)

### 共通スケルトン — ハイブリッド符号化ループ

```text
            ┌────────────────────────────────────────────────┐
入力フレーム │                                                  │
 ──────────►(−)──► [変換 DCT] ──► [量子化 Q] ──┬──► [エントロピー符号] ──► ビット列
            ▲                                  │      (CABAC / range coder)
            │                                  ▼
      [予測 P]                          [逆量子化・逆変換]
       ├ イントラ予測 (空間: 近傍画素から外挿)      │
       └ インター予測 (時間: 動きベクトル+参照フレーム)▼
            ▲                                 (+)──► [ループフィルタ] ─► 再構成フレーム
            │                                              │ (deblocking 等)
            └───────────── 参照フレームバッファ ◄────────────┘
```

エンコーダが**デコーダを内蔵する**ことがこのループの要点である。予測は「デコーダが持つはずの再構成フレーム」から行わねばならず（そうでないと量子化誤差が予測に混入して累積する）、ゆえに符号化とは「デコーダの状態を遠隔操作する命令列の生成」だと読める。

### 世代比較 — 各段に何が足されたか

| | JPEG (1992) | H.264/AVC (2003) | HEVC (2013) | AV1 (2018) |
|---|---|---|---|---|
| 分割 | 8×8 固定 | 16×16 MB + サブ分割 | 64×64 CTU 四分木 | 128×128 SB + 多分木 |
| イントラ予測 | DC 係数の差分のみ | 9 方向 | 35 モード | 56 方向 + パレット等 |
| インター予測 | — | 複数参照, 1/4 画素 | Merge, AMVP | 複合予測, ワープ動き, OBMC |
| 変換 | 8×8 DCT | 4×4/8×8 整数 DCT | 4–32 の可変 + DST | 4–64, 方向依存の変換選択 |
| エントロピー符号 | Huffman | CABAC/CAVLC | CABAC | マルチシンボル適応算術符号 |
| ループフィルタ | — | deblocking | + SAO | + CDEF, ループ内超解像, film grain 合成 |

どの行も「同じ段の細分化・適応化」であり、骨格は 30 年間不変である。分割の柔軟化（右へ行くほど大きく・可変に）が最大の投資先で、平坦な空には大ブロック、細部には小ブロックを割り当てる**ビット配分の空間適応**が世代利得の主因である。

### 音声 — 変換符号化と音響心理

```text
PCM ──► [MDCT 変換] ──► [音響心理モデルが決める量子化] ──► [エントロピー符号] ──► ビット列
                 ▲ 臨界帯域ごとに「マスキング閾値」を計算し、
                   閾値下に量子化雑音を整形する (noise shaping)
```

Opus は低遅延 MDCT 符号化 (CELT) と音声特化の線形予測符号化 (SILK) を切替・併用し、フレーム長 2.5–60 ms・ビットレート 6–510 kbps を単一ストリームで連続可変にした。「電話品質/音楽品質」「低遅延/高圧縮」という従来の二分法を、1 つの適応コーデックが吸収した設計である。

## 技術詳細 (Technical Details)

### 1. DCT — エネルギー集中という前処理

離散コサイン変換 (DCT) は画素ブロックを空間周波数成分に分解する（[`../../foundations/mathematics/fourier-signal-processing/fourier-series-transform.md`](../../foundations/mathematics/fourier-signal-processing/fourier-series-transform.md) の実数版近縁。境界の折返し対称性により、自然画像のようななだらかな信号で DFT より係数が偏る）。自然画像の 8×8 ブロックでは、エネルギーの大半が左上（低周波）の少数係数に集中する——**DCT は 1 ビットも捨てないが、「どこを捨てれば痛くないか」を座標として露出させる** (Ahmed et al. 1974)。JPEG 以降の整数 DCT は、浮動小数点の実装差でデコード結果がずれる（＝予測ループが発散する）ことを防ぐための、ビット正確 (bit-exact) な規格化である。

### 2. 量子化 — 唯一の非可逆段と知覚重み

量子化は変換係数をステップ幅 Q で割って丸める——捨てられた端数が歪みのすべてである。要点は Q が一様でないこと: 視覚は高空間周波数とクロマ（色差）に鈍いため、そこに大きな Q を割り当てる（JPEG の量子化テーブル、動画の適応量子化）。クロマを最初から 1/2 解像度に落とす 4:2:0 サブサンプリングも同じ論理で、カメラ ISP・ディスプレイパイプライン（[`../../hardware/peripherals-connectivity/camera-image-sensors.md`](../../hardware/peripherals-connectivity/camera-image-sensors.md), [`../../hardware/peripherals-connectivity/display-pipeline.md`](../../hardware/peripherals-connectivity/display-pipeline.md)）と共有される YUV 表現の存在理由である。「品質スライダ」や CRF 値の実体は、この Q 群の一括スケーリングにほぼ等しい。

### 3. 動き補償 — 時間方向の辞書引き

インター予測は「このブロックは参照フレームの (dx, dy) だけずれた場所のコピー」という記述であり、可逆圧縮の LZ77 マッチ ([`lossless-compression.md`](lossless-compression.md) §技術詳細 1) の 2 次元・非可逆版と正確に同型である——過去の自分自身が辞書になる。1/4 画素精度の補間、複数参照フレーム、双方向予測 (B フレーム)、そして AV1 のワープ（アフィン）動きへと、「ずれ」の表現力が世代ごとに拡張されてきた。GOP 構造 (I/P/B) はランダムアクセス（シーク・チャンネル切替・エラー回復）と圧縮率の取引であり、ストリーミングのセグメント境界は必ず I フレーム（キーフレーム）に置かれる。

### 4. エントロピー符号 — CABAC と文脈モデル

量子化後の係数・モード・動きベクトルは強く偏った離散分布を持ち、ここで算術符号が本領を発揮する。H.264 で導入された **CABAC (context-adaptive binary arithmetic coding)** は、全シンボルを二値化し、**文脈（周辺ブロックの状態）ごとに適応更新される確率**で二値算術符号化する——[`lossless-compression.md`](lossless-compression.md) §技術詳細 3 で述べた「算術符号は文脈適応と組んで真価が出る」の代表実装である。逐次依存が強くデコードの並列化を阻むため、規格側にタイル・波面並列 (WPP) などの並列化構造が後から彫り込まれた——**エントロピー符号の直列性がマルチコア時代の規格設計を歪めた**、という因果は覚えておく価値がある。

### 5. レート制御 — 歪み曲線上の運転

エンコーダは「ブロックごとに、どのモードにどれだけビットを使うか」を選び続ける。基準がレート歪み最適化 (RDO): コスト J = D + λR を最小化するモードを選ぶ——λ がレートと歪みの交換レートであり、レート制御とはこの λ（実装上は QP）の時間的な運転である。CBR（放送・会議: 遅延とバッファが厳格）、VBR/CRF（VOD: 品質一定でレートを浮動）、そして配信では複数解像度・レートを事前に用意する ABR ラダーを、クライアントが帯域計測で渡り歩く (HLS/DASH)——CDN ([`../networking/cdn-edge-delivery.md`](../networking/cdn-edge-delivery.md)) 上のセグメント配信と、コーデックのキーフレーム境界がここで噛み合う。

### 6. ハードウェアコーデックとメディアスタック

SoC のコーデック IP は、探索候補を絞った動き探索・固定パイプラインの変換/CABAC を数百 mW で回す。ソフト (x264/x265/SVT-AV1) は探索・psy 最適化・多パスに CPU を注げるため、同レートの品質で上回るのが通例——「規格はデコーダのみ規定」の帰結である。プラットフォーム側では、Android がメディア処理を `mediaserver` から Codec2 ベースの分離プロセスへ移し、ブラウザはデコーダをサンドボックス化レンダラ・GPU プロセスに閉じ込める（[`../android/security-model.md`](../android/security-model.md), [`../browsers/browser-architecture.md`](../browsers/browser-architecture.md)）——次節の攻撃面への構造的応答である。

## セキュリティ考察 (Security Considerations)

- **パーサとしてのコーデック**: コンテナ (MP4/MKV) とビットストリームの解析は、長さフィールド・入れ子構造・可変長符号だらけの「攻撃者制御入力の解釈」である。Stagefright (2015, CVE-2015-1538 ほか) は MMS の自動サムネイル生成経由で**ユーザ操作なし**の RCE に至り、モバイルのメディアスタック全面再設計（プロセス分割・権限最小化・fuzzing 常態化）の引き金になった。
- **デコードは信頼境界の内側で起きる**: ブラウザ・メッセンジャーは受信メディアを自動デコードするため、コーデックは「開かなくても踏む」攻撃面である。ハードウェアデコーダの脆弱性はさらに厄介で、ファームウェア・DMA 経由でOSの隔離を迂回しうる——GPU/コーデック IP への入力検証 (shim) をカーネル側に置く設計が一般化した。
- **リソース攻撃**: 解像度・参照フレーム数・タイル数の極端な宣言でメモリ・時間を注文する decompression bomb 型の入力に対し、デコーダはプロファイル/レベル (例: H.264 Level) の上限を**割り当て前に**検証する必要がある。
- **サイドチャネル**: 可変ビットレートは内容を漏らす——暗号化されていてもトラフィックのレート波形から視聴コンテンツが識別されうる（CBR 化・パディングが緩和策）。[`lossless-compression.md`](lossless-compression.md) の CRIME と同族の「圧縮がサイズに情報を写す」問題である。

## 結論 (Conclusions)

映像・音声コーデックは、予測→変換→量子化→エントロピー符号という 30 年不変の骨格の上で、各段の適応性を細分化し続けることで「同品質で半分」を世代ごとに達成してきた。捨てる情報を選ぶのは知覚モデルであり、捨てる場所は量子化ただ1つ、残りはすべて可逆な露出装置である——この見取り図は可逆圧縮 ([`lossless-compression.md`](lossless-compression.md)) と情報理論の限界地図
([`../../foundations/information-theory/channel-capacity-coding.md`](../../foundations/information-theory/channel-capacity-coding.md))
に正確に接続する。実務上の設計変数は規格そのものより、エンコーダ実装・レート制御・ハード/ソフト分担・特許経済であり、セキュリティ上は「自動的に解釈される攻撃者制御入力」としてサンドボックスの内側に置くことが現代の標準である。次の世代交代の候補——ニューラルコーデック——は、予測段を学習モデルで置き換える試みであり、骨格の連続性はここでも保たれつつある。
