# 転置インデックスと全文検索 (Inverted Index & Full-text Search)

## 概要 (Overview)

**全文検索 (full-text search)** が解く問題は、数十億文書のコーパスから「このクエリに最も関連する上位 k 件」を数十ミリ秒で返すことである。これは RDB の索引が解く問題——キーに一致する行を全部返す——とは似て非なるものだ。述語は「一致」ではなく**関連度 (relevance)** という順序付きの曖昧な概念であり、答えは全件ではなく top-k であり、そして対象は構造化された値ではなく自然言語である。Lucene とその上に立つ Elasticsearch/OpenSearch/Solr、あるいは Web 検索エンジンの中核は、いずれもこの問題への同じ解——**転置インデックス (inverted index)**——の実装である。

本ドキュメントの中心となる問いは 5 つ。(1) なぜ B+tree ではなく転置インデックスなのか——「転置」は何と何を交換したのか、(2) テキストはどうやって索引可能な「語」になるのか——そしてこの変換が検索品質の上限をなぜ索引時に確定させてしまうのか、(3) 数十億のポスティングから top-k を返すとき、システムは何を**読まずに済ませて**いるのか（圧縮・スキップ・動的枝刈り）、(4) BM25 の関連度はどこから導出されるのか——なぜあの式形なのか、(5) 更新と分散はどう処理されるのか——不変セグメントという LSM-tree と同型の答えと、scatter-gather の代償。通奏低音として、全文検索エンジンは「**読まない工学**」である——索引構造・圧縮・枝刈り・分散のすべてが「関連しない文書に一切触れずに終える」ための装置だ、という視点を採る。分析深度は Level 3。

## 方法論 (Methodology)

- 情報検索 (IR) の教科書的基礎（Manning らの *Introduction to Information Retrieval*）と、Zobel & Moffat のサーベイを背骨に、実装の詳細は Lucene 系の公開設計に即して読む。理論（確率的関連度モデル）と工学（圧縮・枝刈り）を分離せず、**式の形が実装の形を決める**過程として一体で追う。
- ストレージエンジンとしての側面は [`../databases/storage-engines.md`](../databases/storage-engines.md) の LSM-tree/WAL を基準系に取り、「転置インデックス版 LSM」として差分だけを読む。
- 分散検索は [`../distributed-systems/consistency-models.md`](../distributed-systems/consistency-models.md) の語彙と、テールレイテンシの議論（[`../observability/observability-performance-engineering.md`](../observability/observability-performance-engineering.md)）を借用する。
- ランキングの確率的導出は [`../../foundations/mathematics/probability-statistics/probability-random-variables.md`](../../foundations/mathematics/probability-statistics/probability-random-variables.md) の語彙（条件付き確率・独立性仮定）で読む。
- ベクトル検索（埋め込みによる意味検索）は姉妹編 [`vector-search-ann.md`](vector-search-ann.md) に譲り、本稿は語彙一致 (lexical) の検索に集中する。

## 発見事項 (Findings)

1. **転置インデックスとは行列の転置であり、書き込み時の労働で読み出し時の探索を買う契約である。** 文書×語の出現行列を素直に持てば「文書→含まれる語」（前向き索引）になるが、検索が要るのは「語→含まれる文書」である。この転置を索引時に済ませておくことで、クエリ処理は「数個の語のポスティングリスト (posting list) を取り出して交差・合併する」だけになり、コーパス全体のサイズから切り離される。B+tree が「キー空間の順序」を前払いで維持するのと同じ構図で、転置インデックスは「語→文書」の対応を前払いで維持する——**検索エンジンの速さの本体はクエリ時ではなく索引時にある**。
2. **テキスト解析 (analysis) は非可逆な正規化であり、検索品質の上限を索引時に確定させる。** 検索されるのは原文ではなく、トークナイズ・正規化・ステミングを通過した後の語の列である。「Tokyo」と「tokyo」を同一視するか、「走った」を「走る」に還元するか、日本語を形態素で切るか bi-gram で切るか——これらの決定は再現率 (recall) と適合率 (precision) の交換であり、索引と検索で解析器が一致していなければ検索はエラーを出さずに誤った結果を返す。解析は前処理ではなく、**検索エンジンの意味論そのもの**である。
3. **ポスティングリスト圧縮は容量の問題ではなく速度の問題である。** 文書 ID を昇順に並べれば差分 (delta) は小さく、varint や PForDelta で 1 エントリ数ビットまで潰せる。だが本質は索引がメモリ・キャッシュに収まることによる**デコード帯域**にある——クエリ処理の内側ループはポスティングのデコードであり、圧縮率と展開速度の積が検索スループットを律速する。圧縮形式の選択は空間効率ではなく [`../../hardware/cpu-architecture/cache-memory-hierarchy.md`](../../hardware/cpu-architecture/cache-memory-hierarchy.md) のメモリ階層に対する最適化として読むべきである。
4. **top-k 検索の核心は「スコアせずに捨てる」動的枝刈りにある。** 全候補文書をスコアして並べ替えるのは、頻出語を含むクエリでは数千万文書のスコア計算になる。WAND や Block-Max WAND は、各ポスティングリスト（またはブロック）が持つ**スコア上界**を使い、「この文書は現在の top-k の最下位を超えられない」と証明できた文書をスコア計算どころかデコードすらせずに飛ばす。安全な（結果が厳密に一致する）枝刈りであり、これが数十億文書 top-k 検索を成立させている——読まない工学の最先鋭である。
5. **BM25 は魔法の式ではなく、確率的関連度モデルから導出された近似の系譜の到達点である。** 語の出現頻度 (TF) の寄与は線形ではなく飽和し（同じ語が 100 回出ても 10 回の 10 倍関連するわけではない）、長い文書はそれだけで語を多く含むから正規化する——この 2 つの直観が k1 と b という 2 パラメータに縮約されている。IDF 項は「珍しい語ほど識別力がある」の定量化であり、二値独立モデル (Binary Independence Model) の対数オッズから来る。**式の各項が確率モデルの近似として説明できる**ことが、TF-IDF の経験則との差である。
6. **不変セグメント＋マージは LSM-tree の再発明であり、同じ理由から独立に到達された。** 転置インデックスへの in-place 追記は事実上不可能である——1 文書の追加が数百の語のポスティングリスト全部への挿入になるからだ。Lucene の答えは「小さな不変索引（セグメント）を書き、検索は全セグメントに投げて統合し、背景でマージする」——書き込み増幅・読み出し増幅・空間増幅の三律背反を含め、[`../databases/storage-engines.md`](../databases/storage-engines.md) の LSM-tree と完全に同型である。削除が墓標（削除ビットマップ）になり、マージが償却されるところまで一致する。
7. **分散検索は scatter-gather であり、その代償は統計の分断とテールの増幅である。** 文書でパーティションした各シャードに全クエリを撒き、各シャードの top-k を集めて統合する——この構図は単純だが、(a) IDF などの大域統計がシャード毎に微妙に異なりスコアが歪む、(b) ページ n を取るには各シャードから n×k 件集める必要があり深いページングが破綻する、(c) 応答時間は**最も遅いシャードが決める**ため、シャード数を増やすほどテールレイテンシ問題が増幅される。scatter-gather は並列化の道具であると同時に、テール工学（ヘッジリクエスト、レプリカ選択）の発生源である。

### 転置インデックス vs LSM ストレージエンジン — 同型対応表

| 観点 | LSM-tree ([`storage-engines.md`](../databases/storage-engines.md)) | Lucene 系転置インデックス |
|---|---|---|
| 書き込みバッファ | memtable | インメモリ索引バッファ |
| 永続化単位 | 不変 SSTable | 不変セグメント |
| 耐久性 | WAL | translog（WAL 相当） |
| 削除 | 墓標レコード | 削除ビットマップ（live docs） |
| 読み出し | 全レベルを重ねて解決 | 全セグメントに検索して統合 |
| 背景処理 | コンパクション | セグメントマージ |
| 読み出し増幅の抑制 | ブルームフィルタ・レベル化 | セグメント数の抑制（マージポリシー） |

どちらも「in-place 更新が高くつく構造を、不変単位の追記＋背景統合に変換する」という同じ手で、ランダム書き込みを順次書き込みに変えている。検索特有の差は、**可視性が明示的な refresh 操作**（バッファを検索可能なセグメントへ変換する）に切り出されている点で、これが「書き込んだ文書は約 1 秒後に検索に現れる」という**準リアルタイム (near-real-time) 検索**の意味論を作る——耐久性 (translog) と可視性 (refresh) が別々のノブであることは、データベースのコミット＝可視と対照的である。

## 技術詳細 (Technical Details)

### 1. テキスト解析 — 語彙の意味論を決める非可逆変換

- **解析チェーン**: 文字フィルタ（Unicode 正規化、全半角統一）→ トークナイザ（境界の決定）→ トークンフィルタ（小文字化、ストップワード、ステミング、同義語展開）。各段が再現率と適合率を交換する——ステミングは「走った/走る」を束ねて再現率を上げるが、「花/鼻」を誤って束ねれば適合率を落とす。
- **日本語の二方式**: 空白で語が切れない日本語では、(a) **形態素解析** (morphological analysis)——MeCab 系辞書（Lucene では kuromoji）で言語学的な語に切る。高適合率だが未知語（新語・固有名詞）が辞書の切り方次第で取りこぼされる——と、(b) **n-gram**（bi-gram が典型）——機械的に 2 文字ずつ重ねて切る。未知語も必ず引っかかる高再現率だが、「京都」が「東京都」に部分一致する類のノイズを生む——の選択がある。実務では両方の索引を持ちスコアで合成することも多い。**辞書の更新が索引の再構築を要求する**（切り方が変わると索引と検索の解析が食い違う）ことは、発見事項 2 の帰結である。
- **クエリ側との契約**: 索引時と検索時の解析器は原則同一でなければならない。同義語展開だけは「索引時に展開（索引が膨れるが高速）」と「検索時に展開（柔軟だがクエリが膨れる）」の選択があり、更新頻度と索引コストの交換になる。

### 2. 索引構造 — 語彙表・ポスティング・列指向の三点セット

- **語彙表 (term dictionary)**: 全ユニーク語→ポスティング位置の対応。Lucene は FST (finite state transducer) で接頭辞・接尾辞を共有圧縮し、数千万語をメモリ常駐させる。前方一致・ワイルドカードはこのオートマトン上の走査として実装される。
- **ポスティングリスト**: 語ごとに文書 ID 昇順の列。ファイルは役割別に分離される——文書 ID と出現頻度（スコア用）、出現位置（フレーズ検索用）、オフセット（ハイライト用）。フレーズ検索「"分散 検索"」は、両語のポスティング交差の後に**位置の隣接**を検証する二段階になる。
- **doc values（列指向）**: 転置インデックスは「語→文書」専用で、ソート・集計・ファセットに要る「文書→値」は引けない。このため同じデータを列指向 (columnar) でも持つ。1 つの検索エンジンの中に、行指向（stored fields、結果表示用）・転置（検索用）・列指向（集計用）の三形態が同居する——アクセスパターン毎に**同じデータを別形状で複製する**のは、データベースが索引と本体で行うことの徹底版である。
- **フィルタとビットマップ**: スコア不要の絞り込み（`status:published` など）の結果は文書 ID 集合であり、Roaring 系の圧縮ビットマップで表現・キャッシュされる。密な範囲はビット列、疎な範囲は ID 配列と、密度で内部表現を切り替えるハイブリッドである。

### 3. 圧縮と交差 — 内側ループの工学

- **差分符号化**: 昇順の文書 ID 列 `[3, 7, 21, 24]` を差分 `[3, 4, 14, 3]` に変換すると値域が縮み、varint（1 バイト 7 ビット）や、例外値を別置きして本体を固定ビット幅で詰める PForDelta 系で高密度に符号化できる。ブロック単位（128 件など）の固定幅詰めは SIMD 展開と相性がよく、[`../../hardware/cpu-architecture/simd-vector.md`](../../hardware/cpu-architecture/simd-vector.md) の世界と直結する。
- **スキップ構造**: 交差 (AND) では「相手のリストの現在位置以上まで飛べ」という advance 操作が主役になる。ブロック先頭にスキップポインタを張り、リスト長が非対称なら短い側を軸に長い側を**二分/ギャロッピング探索**で飛ぶ——交差コストは短いリストの長さに支配され、O(min(|A|,|B|) · log) 級に落ちる。
- **枝刈りとの結合**: Block-Max WAND はブロック毎に「ブロック内スコア上界」を持ち、スキップ構造と上界を組み合わせて「このブロックは丸ごと top-k に入らない」を判定する。圧縮ブロック・スキップ・スコア上界が同じブロック境界に揃えて設計されるのはこのためである。

### 4. ランキング — 確率モデルから BM25 へ

- **確率的関連度の枠組み**: 「クエリ q の下で文書 d が関連する確率 P(R|d,q) の順に並べよ」が出発点（確率的ランキング原理）。語の出現を独立と仮定した二値独立モデルの対数オッズから IDF 型の重みが導出される——「文書頻度 df が小さい語ほど識別力が高い」は直観ではなく計算の帰結である。
- **BM25**: TF の飽和と文書長正規化を加えた到達点が

  ```
  score(q,d) = Σ_{t∈q} IDF(t) · tf(t,d)·(k1+1) / ( tf(t,d) + k1·(1 − b + b·|d|/avgdl) )
  ```

  である。k1（typ. 1.2）は TF 飽和の速さ——tf→∞ でも寄与は (k1+1)·IDF に漸近する。b（typ. 0.75）は文書長正規化の強さ——b=0 で長さを無視、b=1 で完全正規化。TF-IDF との差は「線形 TF を飽和曲線に置き換えた」ことに集約され、これはスパム的な語の連打への頑健性でもある。
- **二段階検索**: BM25 での高速な第一段検索（数百〜数千件）の上に、より高価なモデル——学習型ランキング (learning to rank)、近年は交差エンコーダ等の意味的リランカ（[`../ml-systems/ml-inference-systems.md`](../ml-systems/ml-inference-systems.md) の推論基盤に載る）——を重ねるのが標準構成である。第一段の役割は「正解を候補に残すこと」（再現率）に純化し、順序の precision は上段に譲る——枝刈り（発見事項 4）が安全に効くのも、第一段のスコア関数が単純な加法形だからである。

### 5. セグメントライフサイクルと準リアルタイム性

- **書き込み経路**: 文書はインメモリバッファに解析済みの形で溜まり、同時に translog へ追記される（クラッシュ耐性）。**refresh**（typ. 1 秒毎）がバッファを検索可能な小セグメントへ変換し、**flush** がセグメントを fsync して translog を切り詰める。可視性 (refresh) と耐久性 (flush/translog) が独立のノブである点が肝で、「検索に見える＝ディスクに安全」ではない。
- **マージ**: セグメント数の増加は検索時の統合コスト（全セグメントへの問い合わせ＋top-k 統合）を増やすため、背景マージが階層的に統合し、削除ビットマップで死んだ文書を物理的に落とす。マージ I/O と前景検索の帯域の綱引き、階層化パラメータの意味論も LSM のコンパクションと同型である（アーキテクチャ節の表）。
- **削除と更新**: 不変セグメント内の文書は消せないため、削除は live-docs ビットマップの消灯、更新は「削除＋再索引」である。頻繁な更新は削除済み文書の比率を押し上げ、スコアの分母（文書頻度統計）にも遅れて反映される——統計の鮮度はマージに従属する。

### 6. 分散検索 — scatter-gather の幾何学

- **パーティショニング**: 文書 ID のハッシュでシャードに分割する（語で分割する term partitioning は、複数語クエリが常にシャード間通信になるため実システムでは稀）。各シャードは独立の Lucene インデックスであり、クエリは全シャードへ撒かれる。
- **top-k 統合**: 各シャードがローカル top-k を返し、コーディネータが統合する。ページ n の取得は各シャードから (n+1)·k 件要求することになり、**深いページングはシャード数×深さで発散する**——「10000 件目以降は search_after（カーソル型）で」という API 制約はこの幾何学の直接の表明である。
- **統計の分断**: IDF はシャードローカルの文書頻度から計算され、シャード間で文書分布が偏ればスコアが揃わない。ハッシュ分割ならば大数の法則で実用上収束するが、時系列インデックスなど意図的な偏りがある構成では大域統計の事前収集 (DFS query-then-fetch) が要る——**正しさと 1 往復の追加コストの交換**である。
- **テールと複製**: 応答時間は max(シャード応答) で決まるため、シャード数を増やすほど「どれか 1 つが遅い」確率が増す。ヘッジリクエスト・アダプティブレプリカ選択・部分結果の返却（タイムアウトしたシャードを欠いた結果に degraded フラグを立てる）が定石であり、これは [`../observability/observability-performance-engineering.md`](../observability/observability-performance-engineering.md) のテールレイテンシ工学の代表的な適用先である。複製は主に「文書を各レプリカで再索引する」論理複製で行われ、セグメントファイルを物理配布する方式（索引 CPU を 1 回に節約し、可視性遅延を払う）との選択は [`../distributed-systems/consistency-models.md`](../distributed-systems/consistency-models.md) の複製設計の縮図である。

## セキュリティ考察 (Security Considerations)

- **無認証クラスタの露出は繰り返される古典類型である**: 検索エンジンは歴史的に「内部ネットワーク前提・デフォルト無認証」で出荷され、インターネットに直接露出した Elasticsearch/MongoDB クラスタからの大規模漏えいと、2020 年の "Meow" 攻撃（露出クラスタの無差別破壊）のような事件を生んだ。現行メジャー版はセキュリティ既定有効へ転換したが、「検索インデックスは本番データの複製である」——本体 DB を守ってもインデックスが漏れれば同じ——という認識が監査の出発点になる。
- **クエリ言語はインジェクション面である**: ユーザ入力を検索 DSL（JSON クエリやクエリ文字列構文）へ文字列連結で埋め込めば、フィールド指定子や論理演算子の注入により意図しない範囲の検索・フィルタ回避が起きる。対策は SQL と同じで、DSL の構造化組み立て（テンプレート／パラメータ化）に限定し、ユーザ入力は常に「値」の位置にのみ置く。
- **高価なクエリは DoS プリミティブである**: 先頭ワイルドカード（全語彙表の走査）、複雑な正規表現（オートマトンの状態爆発）、巨大なファセット集計、深いページングは、単発で CPU・メモリを占有できる。サーキットブレーカ（メモリ見積りによる拒否）、クエリ複雑度の制限、タイムアウトとキャンセルは可用性のためのセキュリティ機構である。
- **文書・フィールドレベルのアクセス制御は集計・スコアと干渉する**: 行レベル制限をフィルタで実装する場合、ヒット件数・ファセット集計・さらには IDF 経由のスコアが「見えないはずの文書の存在」を漏らしうる。件数を返す API は認可フィルタ**適用後**の統計だけを露出しているか、集計がフィルタより先に走っていないか、が監査点になる。
- **索引汚染 (index poisoning)**: 攻撃者が投入できる文書（UGC、クロール対象）に検索語を詰めればランキングを操作できる（Web 検索におけるスパム SEO の内部版）。TF 飽和（BM25 の k1）は連打への頑健性を与えるが十分ではなく、投入経路の検証・フィールド分離（ユーザ入力をタイトルフィールドに入れない等）・リランカでの品質信号が防御層になる。RAG 経由で LLM の文脈に注入される場合の毒性は [`vector-search-ann.md`](vector-search-ann.md) のセキュリティ考察で扱う。

## 結論 (Conclusions)

- 転置インデックスは「語→文書」対応の前払い構築であり、検索の速さの本体は索引時にある。テキスト解析はその前払いの意味論を決める非可逆変換で、検索品質の上限を索引時に確定させる。
- クエリ処理は「読まない工学」である——差分圧縮はデコード帯域のため、スキップ構造は触れないブロックのため、Block-Max WAND はスコアすらしない文書のためにあり、三者は同じブロック境界に揃えて設計される。
- BM25 は確率的関連度モデルの系譜の到達点であり、TF 飽和と文書長正規化という 2 つの直観を 2 パラメータに縮約した加法形スコアである。加法形であることが動的枝刈りと二段階検索の土台になっている。
- 更新問題への答えは不変セグメント＋背景マージであり、LSM-tree と同型である。検索固有の貢献は可視性 (refresh) を耐久性 (translog) から切り離した準リアルタイムの意味論にある。
- 分散検索は scatter-gather であり、深いページングの発散・大域統計の分断・テールの増幅という三つの幾何学的代償を払う。検索エンジンの運用とはこの三つを予算内に抑える仕事である。
- 語彙一致という本稿の世界は「クエリの語が文書に現れる」ことを前提にする。この前提が崩れる意味検索の領域と、両者の合成（ハイブリッド検索）は [`vector-search-ann.md`](vector-search-ann.md) に続く。
