# 割り込み・例外・トラップ (Interrupts, Exceptions & Traps)

## 概要 (Overview)

通常、CPU はプログラムカウンタ (program counter) を1命令ずつ進めて実行する。しかしこの逐次の流れは、しばしば**強制的に中断**される。デバイスが事象を通知してきたり (外部割り込み)、命令の実行自体が成立しなかったり (ページフォルト、ゼロ除算)、プログラムが自らカーネルへ依頼したり (システムコール) するためだ。これらを総称して**例外的制御移行 (exceptional control flow)** と呼ぶ。本ドキュメントが扱うのは、その移行を **CPU 内部がどう実現するか**——どの命令の境界で止め、どこへ飛び、何を保存し、どう元へ戻るか——である。

デバイス側が割り込みを「どう発行するか」(MMIO レジスタ、MSI、割り込みコントローラ APIC/GIC) は `../hw-sw-interface/mmio-dma-interrupts.md` が扱う。本ドキュメントはその一歩 CPU 寄り、**割り込み信号が CPU コアに届いた後**に集中する。すなわち、精密例外 (precise exception) とアウトオブオーダ実行 (out-of-order execution) の関係、特権レベル遷移、ベクタテーブル/IDT、コンテキスト保存とハンドラ進入、マスクと優先度、ネスト、そしてシステムコールがトラップとして実装される仕組みである。

## 方法論 (Methodology)

- 制御移行の契機を**同期 (synchronous)** と**非同期 (asynchronous)** に二分し、さらに同期側をフォールト/トラップ/アボートに細分する。「いつ起きるか」がハンドラの設計と再開可否を決めるためである。
- 1回の制御移行を「検出 → 命令境界の確定 → 特権遷移 → ベクタ選択 → コンテキスト保存 → ハンドラ → 復帰」という一本の流れで通し、各段が何を保証するかを対応づける。
- x86 (ring, IDT)、ARM (Exception Level, ベクタテーブル)、RISC-V (M/S/U, `mtvec`/`stvec`) の三系統を対比し、共通する骨格と実装差を切り分ける。
- 数値 (レイテンシ、ベクタ数など) は桁感として示し、世代・実装依存であることを明記する。

## 発見事項 (Findings)

1. **「同期か非同期か」が分類の根である。** 同期例外は特定の命令の実行に起因し、その命令の位置で再現する (フォールト/トラップ/アボート)。非同期割り込みは実行中の命令と無関係に外から到来し、どの命令境界で受けるかは CPU が選ぶ。この違いが、再開可能性とマスク可否を決める。

2. **精密例外 (precise exception) はアウトオブオーダ実行との緊張関係で成立している。** 現代の CPU は命令を並べ替え・投機的に実行するが、例外を報告する時点では「その命令より前は完了、以降は未実行」という整然とした状態を見せねばならない。これを担うのが**リオーダバッファ (reorder buffer) によるインオーダ・リタイア**であり、例外は命令がリタイアする瞬間に確定する。

3. **制御移行は必ず特権レベルの遷移を伴いうる。** x86 の ring、ARM の Exception Level (EL0–EL3)、RISC-V の M/S/U モードは、いずれも「ユーザコードが触れない資源 (ページテーブル基点、割り込み制御、物理メモリ)」を守る同心円構造である。例外/割り込みは、この円の外側 (より高特権) へ制御を移す唯一の正規の入口である。

4. **システムコールは「意図的に起こす同期例外 (トラップ)」にすぎない。** `ecall`/`syscall`/`svc` は、例外機構を流用してユーザ→カーネルの越境を実現する。割り込みハンドラ進入と同じ配管 (ベクタ、特権遷移、コンテキスト保存) を通る。

5. **割り込みレイテンシはマスク・優先度・ネストの設計で決まる。** 「割り込みを禁止している区間」「保存すべきコンテキストの量」「より高優先度の割り込みに割り込まれるか (ネスト)」が、最悪応答時間を左右する。リアルタイム性 (real-time) の要は、平均ではなく**最悪値 (worst-case latency)** の有界性にある。

## アーキテクチャ (Architecture)

### 制御移行の分類

| 種別 | 同期/非同期 | 契機 | 復帰先 | 例 |
|---|---|---|---|---|
| フォールト (fault) | 同期 | 命令実行前/中に検出、修正後に再実行可 | **障害命令そのもの** | ページフォルト、未整列アクセス |
| トラップ (trap) | 同期 | 命令を完遂し、意図的に制御移行 | **次の命令** | システムコール、ブレークポイント |
| アボート (abort) | 同期 | 回復不能なエラー | 不定 (多くは終了) | ハードウェアエラー、二重フォールト |
| 割り込み (interrupt) | 非同期 | 外部デバイス/タイマ | **中断点の命令** | タイマ割り込み、デバイス完了通知 |

「フォールトは障害命令へ戻る／トラップは次へ進む」という復帰先の差が決定的である。ページフォルトはページを供給してから**同じ命令を再実行**することで透過的にデマンドページングを成立させる (`virtual-memory-mmu.md`)。一方システムコールは処理を終えて**次の命令**から続ける。

### 特権レベル/例外レベルの同心円

```
   ┌──────────────────────────────────────────────────────────┐
   │  最外殻 = 最高特権 (ファームウェア/ハイパーバイザ)         │
   │   x86: (VMX root)   ARM: EL3 / EL2   RISC-V: M-mode       │
   │  ┌────────────────────────────────────────────────────┐  │
   │  │  カーネル / OS                                       │  │
   │  │   x86: ring 0     ARM: EL1        RISC-V: S-mode     │  │
   │  │  ┌──────────────────────────────────────────────┐  │  │
   │  │  │  ユーザプログラム                              │  │  │
   │  │  │   x86: ring 3   ARM: EL0       RISC-V: U-mode  │  │  │
   │  │  └──────────────────────────────────────────────┘  │  │
   │  └────────────────────────────────────────────────────┘  │
   └──────────────────────────────────────────────────────────┘
        例外/割り込み = 内側から外側(高特権)への正規の入口
        復帰命令 (iret / eret / sret) = 外側から内側への帰還
```

x86 は理論上 ring 0–3 の4階層を持つが、実用上は 0 (カーネル) と 3 (ユーザ) のみ使う。ring 1/2 はほぼ使われない。仮想化は VMX root/non-root の直交軸で扱う。ARM と RISC-V は階層を明示的なレベル/モードとして整理しており、各レベルに固有のシステムレジスタ群が対応する。

### ベクタテーブルとハンドラ選択

CPU は「どの例外/割り込みか」を番号 (vector) で識別し、対応するハンドラの入口アドレスを**ベクタテーブル**から得る。方式は二系統に大別できる。

```
  方式A: テーブル参照型 (x86 IDT)
  ─────────────────────────────
   割り込み/例外ベクタ番号 n
        │
        ▼
   IDTR ─▶ ┌──────────── IDT (Interrupt Descriptor Table) ────────────┐
           │ [0]  #DE  除算エラー       → ハンドラ addr + セグメント     │
           │ [1]  #DB  デバッグ          → ...                          │
           │ [14] #PF  ページフォルト    → ハンドラ addr + 特権/ゲート型 │
           │ ...                                                        │
           │ [32..255] デバイス割り込み  → 各デバイスのISR              │
           └────────────────────────────────────────────────────────────┘
        │ ディスクリプタが指す入口へジャンプ (特権遷移ゲートを伴う)
        ▼
   ハンドラ進入

  方式B: ベース+オフセット型 (RISC-V mtvec/stvec, ARM ベクタテーブル)
  ──────────────────────────────────────────────────────────────
   trap base (mtvec) ──▶ [固定オフセット表]
        direct  : すべての trap が base へ (ソフトが原因レジスタで分岐)
        vectored: base + 4*cause へ分岐 (原因ごとに別エントリ)
```

x86 はベクタ番号で IDT の256エントリを引く (0–31 が CPU 予約の例外、32–255 がデバイス割り込みに割り当て可能)。RISC-V は `mtvec`/`stvec` が指すベース番地へ飛び、direct モードでは単一入口に集約してソフトウェアが `mcause`/`scause` を読んで分岐、vectored モードでは原因ごとにオフセットする。ARM は各 Exception Level に16エントリ (同期/IRQ/FIQ/SError × 現在EL/下位EL × 実行状態) のベクタ表を持つ。番号の刻みやエントリ数は実装依存だが、「番号 → 入口」という骨格は共通である。

## 技術詳細 (Technical Details)

### 1. 精密例外とアウトオブオーダ実行

インオーダ実行の単純な CPU なら、例外は「今の命令で起きた」と自明である。しかし現代の高性能コアは、命令を**順序を入れ替えて投機的に**実行する。ここで例外を素朴に報告すると、「後ろの命令が先に走って状態を汚した」状態が OS から見えてしまい、再開できない。

**精密例外 (precise exception)** の要件は、例外ハンドラ進入時に次の状態が見えることである。

- 例外を起こした命令より**前**の命令は、すべて完了し結果が確定している。
- 例外を起こした命令と**それ以降**の命令は、アーキテクチャ状態 (レジスタ/メモリ) に一切影響していない。
- 保存される PC は、例外を起こしたまさにその命令を指す (フォールト) か、次を指す (トラップ)。

これを成立させる標準的な仕組みが**リオーダバッファ (reorder buffer, ROB) によるインオーダ・リタイア**である。命令は乱れた順で実行・完了しうるが、アーキテクチャ状態への反映 (リタイア/コミット) はプログラム順に行う。例外フラグも命令に紐づいて ROB を流れ、その命令がリタイアの先頭に来た瞬間に初めて確定する。これにより、投機的に先走った後続命令はリタイア前に破棄でき、整然とした状態が保たれる。

代償として、例外は「即座」ではなく「リタイア時点」まで遅延する。投機実行された後続命令がキャッシュ状態などのマイクロアーキテクチャ的痕跡を残しうる点が、後述の Meltdown 系脆弱性の温床となった。

### 2. コンテキスト保存とハンドラ進入

割り込み/例外を受けた CPU が、ハードウェアとして自動で行う処理とソフトウェアに委ねる処理の境界は、アーキテクチャごとに異なる。共通する流れは次の通り (例示 (illustrative)、x86/RISC-V を折衷した擬似フロー)。

```
ハードウェアが自動で行う (atomic に):
  1. 現在の命令境界を確定 (精密例外を保証)
  2. 復帰用の PC と現在の特権/状態を退避
       x86  : SS,RSP,RFLAGS,CS,RIP をカーネルスタックに push
       RISC-V: PC→mepc/sepc, 現状態→mstatus/sstatus, 原因→mcause/scause,
               付随情報→mtval/stval (例: フォルトしたアドレス)
  3. 特権レベルを上げ、割り込みを (既定で) マスク
  4. ベクタからハンドラ入口を取得しジャンプ
       x86  : IDT[n] のゲート経由、カーネルスタックへ切替
       RISC-V: mtvec/stvec ベースへ

ソフトウェア (ハンドラ先頭) が行う:
  5. 残りの汎用レジスタを退避 (callee/caller の区別なく全部)
  6. 原因レジスタを読み、種別ごとに分岐
  7. 本処理 (ページ供給 / デバイス応答 / syscall ディスパッチ ...)
  8. 退避したレジスタを復元
  9. 復帰命令 (iret / eret / sret) で PC・特権・状態を atomic に巻き戻す
```

要点は二つ。第一に、**スタックの切り替え**である。ユーザのスタックポインタは信用できない (壊れている、未マップ、悪意があるかもしれない) ため、カーネルは専用スタックへ切り替える。x86 はこの目的に TSS の特権スタックや IST (Interrupt Stack Table)、RISC-V は `sscratch` レジスタにカーネルスタックポインタを退避しておく慣用を持つ。第二に、汎用レジスタの保存は**多くがソフトウェアの責任**である点だ。関数呼び出しの callee-saved 規約 (`../hw-sw-interface/abi-syscalls.md`) と違い、非同期割り込みは任意の命令境界で割り込むため、ハンドラは「壊してよいレジスタ」を仮定できず、原則すべてを退避する。

### 3. システムコール = トラップとしての例外

システムコールは、例外機構を**意図的に起こして**ユーザ→カーネルへ越境する。`../hw-sw-interface/abi-syscalls.md` がレジスタ規約と越境コストを扱うのに対し、ここでは「なぜそれが例外と同じ配管を通るのか」を示す。

- `ecall` (RISC-V) / `svc` (ARM) は同期例外を発生させ、`mtvec`/ベクタ表経由でカーネルの trap handler に入る。トラップなので復帰は**次の命令**。
- x86-64 の `syscall`/`sysret` は、毎回 IDT を引く一般的な例外経路より**軽量化した専用経路**である。`MSR` (`LSTAR` 等) にあらかじめ入口アドレスと遷移時のフラグを設定しておき、IDT 参照やスタック上のゲート処理を省く。それでも「特権を上げて固定入口へ飛ぶ同期トラップ」という本質は同じである。

```
  [User] a7=__NR_write; a0,a1,a2=引数        [Kernel S-mode trap handler]
         ecall ──── 同期トラップ (特権 U→S) ──▶ scause=ECALL を確認
                                                 a7 で sys_write へディスパッチ
         a0 = 戻り値  ◀──── sret (S→U) ────────  引数を検証して実行、戻り値設定
```

割り込み (非同期) との対比が理解の鍵である。両者ともベクタ・特権遷移・コンテキスト保存という同じ骨格を共有するが、**syscall は予測可能な命令境界で自分から起こす**ため、ABI で「この時点で壊れてよいレジスタ」を定義でき、保存量を割り込みより削れる。

### 4. ページフォルトの流れ (フォールトの典型)

ページフォルトはフォールトの代表例であり、`virtual-memory-mmu.md` のデマンドページング/CoW/スワップを駆動する。CPU 内部の視点では次のように進む。

```
1. ロード/ストア命令が VA を発行 → MMU が page walk
2. PTE が present=0、または権限違反 (書込禁止ページへの書込 等)
3. CPU がページフォルトを発生 (x86: #PF=ベクタ14)
   - フォルトしたアドレスを退避 (x86: CR2, RISC-V: stval)
   - エラーコードを残す (読/書/実行、ユーザ/特権、present 有無)
   - 障害命令の PC を保存 (フォールトなので「次」ではなく「その命令」)
4. カーネルのフォルトハンドラが原因を判定:
   - 正当 (未割当領域の初回アクセス) → 物理ページを割当/読込、PTE 更新
   - CoW → 複製して書込可能に
   - 不正 (未マップ領域、権限なし) → SIGSEGV 等でプロセスを罰する
5. 正当なら sret/iret で復帰 → 障害命令を再実行 → 今度は成功
```

「障害命令を再実行して透過的に成功させる」というフォールトの性質が、デマンドページングを可能にしている。トラップ (syscall) ならここで次へ進んでしまい、再試行という概念が成り立たない。

### 5. 割り込みマスク・優先度・ネスト

非同期割り込みは「いつでも来うる」ため、CPU は**マスク (mask)** で受付を一時的に止められる。

- **大域マスク**: x86 の `RFLAGS.IF` (`cli`/`sti`)、RISC-V の `mstatus.MIE`/`SIE`。クリティカルセクションや割り込み進入直後に割り込みを止め、競合や再入を防ぐ。なお x86 の **NMI (Non-Maskable Interrupt)** や、致命的フォールトはマスクできない (止めると検知不能になるため)。
- **優先度 (priority)**: 割り込みコントローラ (APIC/GIC) と CPU が、低優先度の処理中でも高優先度割り込みを通す閾値を持つ。ARM の GIC は優先度レベルとプリエンプション閾値を、x86 APIC は TPR (Task Priority Register) を持つ。
- **ネスト割り込み (nested interrupt)**: 高優先度割り込みが、低優先度ハンドラの実行中に割り込むこと。これを許すにはハンドラ先頭で十分なコンテキストを保存してから割り込みを再許可する必要がある。ネストはレイテンシを改善する (緊急事象を待たせない) が、スタック消費と再入の複雑さが増す。

```
   通常実行 ───┐
              ▼ IRQ-A (低優先度) 受付、マスク解除して処理開始
        ハンドラA 実行中
              ▼ IRQ-B (高優先度) が割り込む  ← ネスト
           ハンドラB 実行 ──┐
                           ▼ 完了 → A へ復帰
        ハンドラA 続き ──┐
                        ▼ 完了 → 通常実行へ復帰
```

これは `../hw-sw-interface/mmio-dma-interrupts.md` の「上半分/下半分 (top half / bottom half)」と接続する。割り込み禁止区間を短く保つために、ISR の上半分は最小限にとどめ、重い処理は割り込み許可状態の下半分へ追い出す。

### 6. 割り込みレイテンシとリアルタイム性

**割り込みレイテンシ (interrupt latency)** は、割り込み発生からハンドラの実処理開始までの時間である。構成要素は概ね以下。

- 割り込みが**マスクされている区間**の残り時間 (最悪、最長クリティカルセクション分待たされる)。
- ハードウェアによるコンテキスト退避とベクタディスパッチ (数十サイクル規模、実装依存)。
- ソフトウェアのレジスタ退避・分岐。
- より高優先度割り込みによる先行 (優先度設計次第)。

数値は世代・実装依存だが、桁感として、ハードウェアの最小限の進入だけなら数十〜数百サイクル (ナノ秒オーダ) で済む一方、OS の汎用パスやキャッシュ/TLB が冷えた状態を含めると数マイクロ秒以上に膨らみうる。リアルタイムシステムが問題にするのは平均ではなく**最悪値の有界性**である。Linux の `PREEMPT_RT` のような構成は、割り込み禁止区間を縮め、ハンドラをスレッド化して優先度継承を効かせることで、最悪レイテンシの予測可能性を高める。

## セキュリティ考察 (Security Considerations)

- **特権境界としての例外入口**: 例外/割り込みは低特権から高特権への正規の入口であり、入口でのスタック切替・レジスタ退避・状態の健全性確認を誤ると権限昇格に直結する。ユーザが制御するスタックポインタやセグメントを信用してハンドラに入ってはならない (x86 の IST はまさに信頼できるスタックを保証するための仕組み)。
- **精密例外と投機実行の交差 (Meltdown 系)**: 精密例外は「例外を起こした命令以降をアーキテクチャ状態に反映しない」ことを保証するが、リタイア前に投機実行された命令はキャッシュ等のマイクロアーキテクチャ状態に痕跡を残しうる。Meltdown はこの隙を突いてカーネルメモリを漏らした。対策の KPTI は `virtual-memory-mmu.md` を参照。
- **二重フォールトと枯渇攻撃**: フォルトハンドラ自体がフォルトする (例: ハンドラのスタックが未マップ) と二重フォールト→トリプルフォールトに至りシステムが落ちる。スタックオーバーフローを例外契機にする攻撃や、割り込み嵐 (interrupt storm) による DoS は、レート制限・専用スタック・閾値で防ぐ (`../hw-sw-interface/mmio-dma-interrupts.md`)。
- **境界での引数検証**: トラップ (syscall) でユーザから渡されたポインタ・長さは信頼できない入力として検証する (`../hw-sw-interface/abi-syscalls.md` の `copy_from_user`/`copy_to_user`)。例外経路はカーネルが最初にユーザ入力に触れる地点であり、検証漏れは即座にカーネル権限での読み書きを許す。
- **割り込みハンドラの再入性**: マスクとネストの設計を誤ると、ハンドラが自分自身や共有データに再入して破壊する。共有状態へのアクセスは割り込み禁止やロックで守る必要がある。

## 結論 (Conclusions)

- 制御移行は「同期 (フォールト/トラップ/アボート) か非同期 (割り込み) か」で根本的に分かれ、この区別が復帰先 (障害命令へ戻るか次へ進むか) とマスク可否を決める。
- 現代の高性能コアは命令を並べ替え投機実行するが、例外は**精密例外**として整然とした状態で報告される。これを支えるのが ROB によるインオーダ・リタイアであり、その隙間が Meltdown 系脆弱性の温床でもある。
- 例外/割り込みは低特権から高特権への唯一の正規の入口であり、ベクタテーブル (IDT / mtvec / ARM ベクタ表) でハンドラを選び、スタック切替とコンテキスト保存を経てハンドラへ入る。
- システムコールは「意図的に起こす同期トラップ」にすぎず、割り込みと同じ配管を共有する。違いは予測可能性 (保存量を削れる) にある。
- 割り込みレイテンシはマスク区間・コンテキスト量・優先度/ネストの設計で決まり、リアルタイム性の要は平均ではなく最悪値の有界性にある。
