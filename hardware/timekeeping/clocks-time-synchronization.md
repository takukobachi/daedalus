# 時刻同期とクロック (Timekeeping & Clock Synchronization)

## 概要 (Overview)

「いま何時か」という問いは、分散システムの問題である前に**物理工学の問題**である。分散アルゴリズムが仮定する時計スキュー (clock skew) の上界 ε は、突き詰めれば**発振器 (oscillator) の物理**と**ネットワーク遅延の非対称性 (path asymmetry)** で決まる。どれほど洗練された合意プロトコルも、その足元では水晶片の温度特性と、行きと帰りでケーブル長が違うかもしれないという不確かさの上に立っている。

本ドキュメントは、時刻という抽象がどう作られ配られるかを1本のスタックとして整理する。すなわち **発振器 (oscillator) → 時系 (timescale) → 配信 (dissemination) → 規律 (discipline) → アプリケーション API** の5層である。`../hw-sw-interface/clock-power-reset.md` はチップ内のクロック生成・分配（PLL、クロックツリー、skew）を扱ったが、本稿はその外側——基板を越え、装置間、大陸間へと「同じ時刻」を届ける層——を扱う。到達点は `../../software/distributed-systems/consistency-models.md` の論理時計との合流点、すなわち「良い物理時計は分散システムの性能を買い戻す」という洞察である。

## 方法論 (Methodology)

- 時刻の問題を**周波数 (frequency)** と**位相 (phase / time offset)** に厳密に分けて扱う。「進む速さが合っている」ことと「今の値が合っている」ことは別問題であり、同期プロトコルはこの2つを別々の機構で規律する。
- 各技術を統一の5層スタック（発振器 → 時系 → 配信 → 規律 → API）に位置づけ、層ごとに達成可能な精度の**桁 (order of magnitude)** を対応づける。数値は世代・実装・環境（温度、ネットワーク負荷）で大きく変動するため、絶対値ではなく桁の序列を理解の基準とする。
- 安定度の評価には標準偏差ではなく**アラン偏差 (Allan deviation)** を用いる理由を、発振器雑音の統計的性質から説明する。
- 仕様値 (spec) と実測値 (demonstrated) を区別して表記する。特にベンダ公称の精度は理想条件下の値であることが多い。
- 評価軸は終始「**不確かさの桁**と、それを保証するための前提条件（ハードウェア支援・ネットワーク仮定・信頼モデル）」である。

## 発見事項 (Findings)

1. **時刻同期の限界は最終的に発振器物理とネットワーク非対称性で決まる。** プロトコルをどう工夫しても、往復遅延の行きと帰りの差（非対称性）は片道遅延の測定からは原理的に検出できず、その半分がそのままオフセット誤差になる。また同期の合間を埋める自走精度は発振器の安定度（アラン偏差）が決める。プロトコルは物理の限界を配るだけで、超えることはできない。

2. **標準偏差は発振器の安定度指標として破綻しており、アラン偏差が業界標準である。** 発振器の周波数雑音にはフリッカ雑音やランダムウォークが含まれ、これらに対して古典的な標準偏差はサンプル数とともに発散して収束しない。隣接する周波数測定値の差分に基づくアラン偏差 (Allan deviation, ADEV) は収束し、かつ平均化時間 τ への依存の形から雑音の種類まで識別できる (Allan 1966)。

3. **GNSS は測位システムである前に時刻配信システムである。** 衛星測位は「4つ以上の原子時計からの信号の到達時刻差で位置と時刻を同時に解く」仕組みであり、位置とは時刻差の幾何にほかならない。この副産物として、受信アンテナ位置で数十 ns 級（実装依存）の UTC トレーサブルな時刻が世界中で無料で手に入る。その結果、電力系統・通信網・金融が GNSS という単一障害点 (single point of failure) に静かに依存する構造が生まれた。

4. **NTP と PTP の精度差（ms 級 vs sub-µs 級）の本質はタイムスタンプを押す場所である。** NTP はソフトウェア（カーネル/ユーザ空間）でタイムスタンプを押すため、OS のスケジューリングとネットワークスタックの揺らぎを丸ごと被る。PTP (IEEE 1588) は PHY 直近のハードウェアでタイムスタンプを押し、さらに中間スイッチが滞留時間を申告（トランスペアレントクロック）することで、キューイング遅延という最大の雑音源を測定から除去する。

5. **うるう秒 (leap second) は「正しさ」の定義の衝突であり、運用上は事故源である。** UTC が地球自転に合わせて挿入するうるう秒は、POSIX 時刻の「1日=86400秒」という仮定と衝突し、61秒目の存在が繰り返し実障害を起こしてきた。Google 等の**スメアリング (leap smearing)** は秒を長時間に薄く引き延ばす回避策だが、スメアする系としない系が混在すると相互に時刻がずれるという相互運用性の代償を払う。CGPM は 2035 年頃までのうるう秒廃止を決議している（決定済みの計画であり、施行細部は今後の調整事項）。

6. **有界な時計不確かさは分散システムの設計を変える。** Lamport (1978) は「順序が欲しいだけなら物理時刻は不要」と示したが、その逆も成り立つ。Google Spanner の TrueTime は時刻を点ではなく**区間 (interval)** として返し、不確かさの分だけコミットを待つ (commit-wait) ことで、通信なしに外部一貫性 (external consistency) を達成する。時計への投資（GPS 受信機＋原子時計）が、分散合意の通信コストを買い戻している。

## アーキテクチャ (Architecture)

### 計時スタックの全体像

発振器からアプリケーション API までの5層。各層の右に、その層で達成される典型的な精度の桁を示す（環境・実装依存の桁感であり保証値ではない）。

```
 層                     構成要素                          精度の桁 (目安)
┌─────────────────────────────────────────────────────────────────────┐
│ 5. アプリケーション API                                              │
│    clock_gettime / TrueTime.now() → [earliest, latest]              │
│    知るべきは「点」ではなく「区間 = 時刻 ± 不確かさ」                  │
├─────────────────────────────────────────────────────────────────────┤
│ 4. 規律 (discipline)                                                │
│    サーボループ: 測定オフセット → 周波数/位相補正                     │
│    slew (adjtime) / step (settimeofday), OS: TSC+vDSO               │
├─────────────────────────────────────────────────────────────────────┤
│ 3. 配信 (dissemination)                                             │
│    NTP ..................... ms 級 (WAN, SWタイムスタンプ)           │
│    PTP / IEEE 1588 ......... µs〜数十ns級 (LAN, HWタイムスタンプ)    │
│    White Rabbit ............ sub-ns 級 (専用光ファイバ, SyncE+PTP)   │
│    GNSS 直接受信 ............ 数十ns級 (アンテナ位置, 空が見える事)   │
├─────────────────────────────────────────────────────────────────────┤
│ 2. 時系 (timescale)                                                 │
│    TAI (原子時系) ── +うるう秒調整 ──> UTC ──> 各国標準時             │
│    GPS time = TAI - 19 s (うるう秒なし・連続)                        │
├─────────────────────────────────────────────────────────────────────┤
│ 1. 発振器 (oscillator)  ← すべての足元                               │
│    XO → TCXO → OCXO → Rb → Cs / H-maser → 光時計                    │
│    安定度: 10⁻⁶ ......... 10⁻¹² ......... 10⁻¹⁵ ...... 10⁻¹⁸ 級     │
└─────────────────────────────────────────────────────────────────────┘
```

- 下の層ほど「時刻の源」に近く、上の層ほどソフトウェアに近い。各層は下の層の不確かさを**引き継ぎ、自層の雑音を加算する**。
- 配信層の選択は「どの桁が要るか」ではなく「どの桁が要り、どのインフラ（HW タイムスタンプ対応 NIC、対応スイッチ、アンテナ）を許容できるか」で決まる。

### 同期の基本ループ

どの同期方式も抽象的には同じ**規律ループ (clock discipline loop)** である。

```
        参照時刻源 (GNSS / 上位サーバ / グランドマスタ)
              │ 時刻比較 (プロトコル固有: NTP交換, PTP, 1PPS)
              ▼
      ┌──> オフセット/周波数誤差の推定 ──┐
      │                                  ▼
   ローカル発振器 <── 補正 (サーボ) ── フィルタ (外れ値除去, PLL/FLL)
      │
      ▼
   自走 (holdover): 参照喪失時は発振器の素の安定度で維持
```

参照が生きている間はループが誤差を殺し続け、参照を失うと**保持動作 (holdover)** に落ちて発振器の素性がむき出しになる。「同期精度」と「保持性能」は別のスペックであり、後者を決めるのは発振器の階級（OCXO か Rb か）である。

## 技術詳細 (Technical Details)

### 1. 発振器の物理と安定度の測り方

**水晶発振器 (quartz crystal oscillator)** は水晶の圧電共振を使う。周波数の主な敵は3つ:

- **温度**: 共振周波数は温度の関数で、**AT カット (AT-cut)** は室温付近で3次曲線の変曲点を持つよう結晶軸から切り出したもの。それでも温度範囲全体では ppm 級 (10⁻⁶) 動く。
- **経年変化 (aging)**: 実装応力の緩和や汚染の吸脱着で周波数が単調にドリフトする。年あたり ppm〜sub-ppm 級（品種依存）。
- **短期雑音**: 位相雑音・フリッカ雑音。短い平均化時間での揺らぎを決める。

対策の階段が **XO → TCXO → OCXO** である:

| 種別 | 機構 | 周波数安定度の桁 (spec 目安) | 電力・コストの桁感 |
|---|---|---|---|
| **XO** (素の水晶) | 補償なし | 10⁻⁵〜10⁻⁶ (数十 ppm) | µW〜mW 級・数十円〜 |
| **TCXO** (温度補償型) | 温度センサ+補正回路 | 10⁻⁶〜10⁻⁷ (sub-ppm) | mW 級・数百円〜 |
| **OCXO** (恒温槽型) | 水晶を恒温槽で一定温度に保つ | 10⁻⁸〜10⁻¹⁰ | W 級（ヒータ常時通電）・数千〜数万円 |
| **Rb** (ルビジウム) | Rb 原子遷移に水晶をロック | 10⁻¹¹ 級 | 数 W〜十数 W・数十万円級 |
| **Cs ビーム** (セシウム) | Cs-133 超微細遷移 (SI 秒の定義そのもの) | 10⁻¹³ 級 (長期で漂わない=確度を持つ) | 数十 W・車一台分 |
| **水素メーザ (H-maser)** | 水素の誘導放出 | 短期 10⁻¹⁵ 級（長期は Cs に劣る） | ラック級・研究所用 |
| **CSAC** (チップスケール原子時計) | 小型化した Rb/Cs 系 (CPT 方式) | 10⁻¹⁰〜10⁻¹¹ 級 | 100 mW 級・組込可能 |

数値はいずれも代表的な仕様の桁であり、平均化時間 τ・温度環境・世代で変わる。重要なのは**1段上がるごとに安定度が1〜2桁、電力とコストも桁で上がる**という序列である。

**なぜ標準偏差ではなくアラン偏差か。** 発振器の周波数誤差 y(t) には白色雑音だけでなく**フリッカ周波数雑音 (flicker FM)** や**ランダムウォーク周波数雑音 (random walk FM)** が含まれる。これらは低周波成分が発散するスペクトルを持つため、平均値のまわりの分散という古典統計はサンプルを増やすほど大きくなり収束しない。**アラン偏差 (Allan deviation)** σ_y(τ) は、平均化時間 τ で区切った隣接する周波数平均値の**差分**の2乗平均で定義される:

```
σ_y²(τ) = (1/2) · < ( ȳ_{k+1} − ȳ_k )² >
   ȳ_k: k 番目の長さ τ の区間での平均規格化周波数偏差
```

差分を取ることで発散する低周波成分が抑えられて収束し、さらに log σ_y(τ) 対 log τ のグラフの**傾きから雑音の種類が同定できる**（白色 FM は τ^{-1/2}、フリッカ FM は平坦、ランダムウォーク FM は τ^{+1/2}）。「τ を伸ばすとどこまで平均化が効き、どこから経年ドリフトに負けるか」が一目で読める。これが Allan (1966) 以来、発振器業界の共通言語である。

**GPSDO (GPS-disciplined oscillator)** はこの表の実用的な合成解である。GNSS 受信機の 1PPS（1秒パルス）は長期的には原子時計系（衛星搭載時計＋地上管制）にトレーサブルだが、1パルスごとには ns〜数十 ns 級のジッタを持つ。逆に OCXO は短期安定度が高いが長期にドリフトする。GPSDO は **OCXO を GNSS の長期確度でゆっくり規律する**ことで、短期は OCXO・長期は原子時系という両者の良所を合成し、GNSS 喪失時は OCXO の保持動作 (holdover) で数 µs/日級（品種依存）の自走を提供する。

### 2. 時系 — TAI・UTC・GPS 時刻・うるう秒

- **TAI (International Atomic Time)**: 世界中の原子時計の加重平均で作られる連続な時系。うるう秒を含まない。
- **UTC (Coordinated Universal Time)**: TAI に**うるう秒 (leap second)** を挿入して地球自転 (UT1) との差を 0.9 秒以内に保った時系。2026年時点で TAI − UTC = 37 秒。
- **GPS 時刻**: 1980-01-06 の UTC に一致させて以降うるう秒を入れない連続時系。恒等的に GPS = TAI − 19 s。GNSS 受信機は航法メッセージ中のうるう秒情報で UTC へ換算する。
- **UNIX 時刻 (POSIX time)**: 「1970-01-01 UTC からの経過秒」を名乗るが、うるう秒を**数えない**。うるう秒挿入時は同じ秒を繰り返すか止まるかで、真の経過秒数とずれる。つまり UNIX 時刻は連続な物理時間軸ではなく「UTC のラベルの符号化」である。

**うるう秒の運用ハザード**: `23:59:60` という POSIX が表現できない時刻の出現は、カーネル・DB・分散システムで繰り返し実障害（ライブロック、時刻逆行によるクラッシュ）を起こしてきた。**スメアリング (leap smearing)** は挿入日の前後（例: 24時間）にわたり秒の長さをわずかに引き延ばして 1 秒を吸収する回避策で、大手クラウドの NTP サービスが採用する。ただしスメア中の時刻は UTC から最大 0.5 秒ずれるため、**スメアする系としない系を混在させると相互の時刻が食い違う**。金融タイムスタンプ規制のように UTC トレーサビリティが要る系では使えない。この混乱の根本解として、CGPM（国際度量衡総会）は 2022 年の決議で **2035 年までにうるう秒の挿入を事実上廃止する**方針を採択した（決定済みの計画。以後は UT1 との差の拡大を許容し、扱いを将来再検討する）。

### 3. GNSS 時刻配信

GNSS の測位方程式は、受信機の未知数が位置 3 + **受信機時計誤差 1** の計4つであり、4衛星以上の擬似距離 (pseudorange) から連立で解く。つまり**測位とは時刻差の幾何学**であり、時刻解は測位の副産物ではなく対等な出力である。

- 各衛星は Rb/Cs 原子時計を搭載し、地上管制が GNSS システム時刻（さらに UTC(k) 系）へ規律する。
- 受信機はアンテナ位置で **1PPS + 時刻情報**を出力する。確度は数 ns〜数十 ns 級（受信機品位・アンテナケーブル遅延補正・マルチパス環境に依存。仕様値と実環境値の差が大きい領域である）。
- **共視 (common-view) 時刻転送**: 2地点が同じ衛星を同時に観測し差分を取ると、衛星時計誤差と軌道誤差の共通成分が相殺され、大陸間でも ns 級の時刻比較ができる。BIPM が TAI を合成する国際時刻比較の基盤技術である。
- **依存リスク**: 電力系統の PMU（位相計測。`../power-generation/` 参照）、携帯基地局の TDD 同期、金融の規制タイムスタンプ、放送、いずれも GNSS を事実上の一次参照とする。受信は地表で −130 dBm 級の微弱信号であり、妨害が容易（→ セキュリティ考察）。「空からの無料の ns」への依存は、インフラ横断の**単一障害点**として各国の政策文書で繰り返し指摘されている。

### 4. NTP — ソフトウェアタイムスタンプの限界まで

**NTP (Network Time Protocol)** は4つのタイムスタンプの交換でオフセットと往復遅延を推定する (Mills 1991)。

```
  クライアント                     サーバ
      │  t1 (送信時刻を記録)          │
      ├──────── request ────────────>│ t2 (受信時刻)
      │                              │ t3 (応答送信時刻)
      │<─────── response ────────────┤
      │  t4 (受信時刻を記録)          │

  オフセット θ = ((t2 − t1) + (t3 − t4)) / 2     … 時計のずれの推定
  往復遅延  δ = (t4 − t1) − (t3 − t2)            … 経路往復時間

  ★盲点: θ の式は「行き遅延 = 帰り遅延」を仮定している。
    実際の行き d1・帰り d2 に対し、推定誤差 = (d1 − d2) / 2。
    非対称性は t1..t4 からは原理的に観測できない。
    δ は分かるが、その内訳 (d1, d2) は分からない。
```

- **非対称遅延が原理限界**: 上図のとおり、経路非対称（行きと帰りで経路・キュー深さ・帯域が違う）の半分がそのまま誤差になる。WAN では数 ms の非対称が普通にあり、これが NTP の実効精度を LAN で sub-ms〜、WAN で ms 級（環境依存の桁感）に規定する。
- **ストラタム (stratum) 階層**: stratum 0 = 参照時計（GNSS・原子時計）、stratum 1 = それに直結したサーバ、以下段数が増えるごとに誤差が累積する。階層は信頼度の系譜であってループを防ぐ構造でもある。
- **規律ループ**: ntpd/chrony はオフセット標本をフィルタ（最小遅延標本の選好、外れ値棄却）し、PLL/FLL ハイブリッドのサーボでローカルクロックの周波数を微調整する。補正は原則 **slew**（クロックの進む速さを僅かに変えて滑らかに追い込む。時刻の単調性を保つ）で行い、ずれが大きいときのみ **step**（値を書き換えるジャンプ）に落ちる。step は時刻の逆行を起こしうるため、タイムスタンプの単調性に依存するアプリケーション（ログ、リース、Make）には slew が安全である。

### 5. PTP / gPTP / White Rabbit — ハードウェアの介入

**PTP (Precision Time Protocol, IEEE 1588-2019)** は NTP と同じ「タイムスタンプ交換」だが、3つの介入で桁を変える:

1. **ハードウェアタイムスタンプ**: NIC の PHY/MAC 直近でパケットの送受信瞬間に時刻を押す。OS のスケジューリング・割り込み遅延・プロトコルスタックの揺らぎ（合わせて µs〜ms 級の雑音源）が測定から消える。
2. **トランスペアレントクロック (transparent clock)**: 中間スイッチがパケットの**滞留時間 (residence time)** を測って補正フィールドに加算する。ネットワークで最大かつ最も変動するキューイング遅延が既知量になる。
3. **バウンダリクロック (boundary clock)**: スイッチ自身が同期して各ポートでマスタとして振る舞い、同期を1ホップずつ区切る。

結果、対応ハードウェアで構成された LAN では sub-µs〜数十 ns 級（構成・機器品位依存）に達する。逆に言えば、**PTP の精度は経路上の全機器の対応に依存する**——非対応スイッチが1台挟まるだけでキューイング雑音が復活する。

- **gPTP (IEEE 802.1AS)**: PTP の TSN 向けプロファイル。車載・産業 Ethernet では、時刻同期そのものが目的ではなく **802.1Qbv の時間ゲートスケジュールの前提**となる（`../automotive/automotive-ethernet-tsn.md` 参照。同期が崩れると決定論保証ごと崩壊する、という依存構造もそちらで論じた）。
- **White Rabbit**: CERN の加速器制御網のために開発された、精度フロンティアの実証。**SyncE (Synchronous Ethernet) で物理層の周波数を揃え**（全ノードが同一周波数で刻む）、その上で PTP により位相を合わせ、さらにリンク遅延を位相検出で ps 分解能に測る。専用光ファイバ網で **sub-ns 級（実測報告あり）** を達成し (Lipiński et al. 2011)、IEEE 1588-2019 に High Accuracy プロファイルとして取り込まれた。
- **データセンタ展開**: 歴史的には NTP の ms 級で足りていたが、分散 DB の外部一貫性・分散トレーシング・高頻度取引の要件から、ハイパースケーラは HW タイムスタンプ+PTP 系で µs → 数十 ns 級へと降りてきている（展開状況・達成値は事業者と世代に強く依存する）。

### 6. 同期技術の比較

| | **NTP** | **PTP (1588)** | **gPTP (802.1AS)** | **White Rabbit** | **GNSS 直接受信** |
|---|---|---|---|---|---|
| 精度の桁 (目安) | ms 級 (WAN)〜sub-ms (LAN) | sub-µs〜数十 ns | sub-µs (TSN 要件) | sub-ns | 数十 ns (アンテナ位置) |
| HW 要件 | なし（汎用 NIC で可） | HW タイムスタンプ NIC + 対応スイッチ | 全ノード 802.1AS 対応 | 専用 NIC/スイッチ + SyncE | 受信機 + 屋外アンテナ |
| ネットワーク仮定 | ベストエフォート・経路対称を期待 | LAN・全ホップ PTP 対応が理想 | TSN ドメイン内で完結 | 専用光ファイバリンク | 不要（衛星可視のみ） |
| 障害モード | 非対称遅延・混雑で劣化 | 非対応機器混在で劣化 | 同期喪失 = スケジュール崩壊 | リンク断 | 妨害・偽装・遮蔽 |
| 典型ドメイン | インターネット汎用・サーバ群 | データセンタ・通信・放送・電力 | 車載・産業 TSN | 加速器・物理実験・研究網 | stratum-0 参照・基地局・PMU |

### 7. OS の計時 — スタック最上層の実装

配信された時刻を**アプリケーションが読む**までが計時である。x86 Linux を例に:

- **TSC (Time Stamp Counter)**: CPU サイクルカウンタを `rdtsc` で読む。現代 CPU の **invariant TSC** は P-state/C-state に関わらず一定レートで進むため、クロックソースとして使える。読み出しは数十サイクル級で最速。
- **HPET / ACPI PM タイマ**: プラットフォーム側のタイマ。TSC が信頼できない環境のフォールバックだが、MMIO 読みでありレイテンシは桁で遅い。
- **clocksource 選択**: カーネルは起動時に候補を検査し（TSC の同期性検証を含む）、最良のものを選ぶ。`current_clocksource` で確認できる。
- **vDSO**: `clock_gettime(CLOCK_MONOTONIC)` はシステムコールに入らず、カーネルが共有ページに置いた「TSC→時刻の換算係数（NTP/PTP 規律で常時補正される）」をユーザ空間で読んで TSC と掛け合わせる。時刻読み出しが ns 級で済むのはこの機構による。
- **CLOCK_REALTIME vs CLOCK_MONOTONIC**: 前者は UTC のラベル（step で逆行しうる）、後者は単調（slew のみ反映）。タイムアウトや間隔測定に REALTIME を使うのは典型的なバグである。
- **PPS 入力**: GNSS 受信機や PTP グランドマスタの 1PPS 信号をシリアル/GPIO 経由でカーネルの PPS サブシステム (`/dev/pps*`, RFC 2783 の PPS API) に入れると、パルスエッジの到達をカーネルがタイムスタンプし、chrony/ntpd がそれを最上位の参照として規律に使える。ネットワークを介さない分、stratum-1 サーバ構築の定石である。
- **VM 移行と時刻**: 仮想化下では TSC の同一性が保証されず、ライブマイグレーションで物理クロックが突然変わる。準仮想化クロック (**kvm-clock** 等) はホストが換算パラメータをゲストと共有して吸収する（`../../software/virtualization/hardware-virtualization-containers.md` 参照）。VM の時計は物理機より一段悪い、という前提は分散システム設計に効いてくる。

### 8. 分散システムへの橋 — 不確かさを区間として運ぶ

Lamport (1978) の洞察は「イベントの順序づけが目的なら物理時刻は不要であり、論理時計 (logical clock) で足りる」だった（`../../software/distributed-systems/consistency-models.md`）。しかしその対偶も実務上重要である——**良い物理時計は、論理時計が支払う通信・待ち合わせコストを買い戻す**。

- **Google Spanner / TrueTime** (Corbett et al. 2013): 各データセンタに GPS 受信機と原子時計を置き、API は時刻を点ではなく**区間** `TT.now() = [earliest, latest]` として返す。トランザクションのコミットは `latest` が過ぎるまで待つ (**commit-wait**)。待ち時間は不確かさ ε そのもの（論文当時の報告値で平均数 ms）であり、これにより**通信なしで外部一貫性 (external consistency)**——コミット順序がタイムスタンプ順序と一致する保証——を得る。時計インフラへの投資が、グローバルな調整通信の削減として回収される構造である（`../../software/distributed-systems/consensus.md` の Spanner 節参照）。
- **AWS 系のアプローチ**: 衛星由来の参照をラック近くまで配り、クライアントに「時刻 + 誤差上界」を返すクロックバウンド (clock-bound) API を提供する系。設計思想は TrueTime と同型で、「点を信じるな、区間で運べ」に収束している。
- 一般化すると: 時計スキュー ε が桁で縮むと、リースの安全マージン、スナップショット読み取りの待ち、コンフリクト判定の保守性がすべて桁で縮む。**発振器とタイムスタンプハードウェアの選定が、分散データベースのレイテンシ設計変数になる**——これが本スタックを貫く結論である。

## セキュリティ考察 (Security Considerations)

時刻は認証・整合性の**前提**であるため、時刻への攻撃は他の攻撃の増幅器 (amplifier) になる。防御側の視点で整理する。

- **GNSS 妨害 (jamming) と偽装 (spoofing)**: 地表での GNSS 信号は極めて微弱であり、安価な発信器で広域を妨害できる。偽装はより高度だが、民間航空・海運で実地の観測事例が継続的に報告されているクラスの脅威である（`../aerospace/avionics-gnc.md` のセキュリティ節と同根）。防御は多層で: (1) **受信機レベルの検知**——信号強度の異常、時刻解の不連続、ドップラーの矛盾の監視、(2) **多コンステレーション・多周波** (GPS+Galileo+…, L1+L5) による相互検証、(3) **保持動作 (holdover) への退避**——検知したら GNSS を切り捨て、OCXO/Rb の自走で凌ぐ。保持時計の品位は「攻撃を無害化できる時間の長さ」というセキュリティ予算に直結する。
- **NTP への攻撃**: (1) **増幅 DDoS**——かつて `monlist` 応答の増幅率を悪用した大規模攻撃があり、機能無効化で対処された歴史がある。(2) **中間者 (MITM)**——素の NTP は無認証であり、経路上の攻撃者は応答改竄や選択的遅延（非対称遅延の人為的注入は θ の式の盲点を直接突く）でクライアントの時計を静かに引きずれる。対策は **NTS (Network Time Security, RFC 8915)**——TLS で鍵を確立し NTP パケットを認証する拡張——と、複数の独立ソースの合議・時刻ジャンプ上限（panic threshold）の設定である。
- **PTP のセキュリティギャップ**: IEEE 1588 は設計上**信頼された LAN** を仮定しており、認証は 1588-2019 で Annex として追加されたものの展開は限定的である。PTP ドメインに侵入できる攻撃者は、偽グランドマスタの広告（BMCA の乗っ取り）や補正フィールド改竄で ns 級精度の系全体を汚染できる。緩和はネットワーク分離・MACsec によるリンク保護・冗長グランドマスタと相互監視である（TSN 文脈は `../automotive/automotive-ethernet-tsn.md` 参照）。
- **時刻は攻撃の増幅器**: 時計を狂わせられると——証明書の有効期間検証 (X.509 の notBefore/notAfter) が無効化され、期限切れ・失効済み証明書が復活する。**Kerberos** のチケット再生防止（許容スキュー窓）が破れる。**ログの時系列**が崩れフォレンジックが妨害される。TrueTime 型のシステムでは ε の仮定が破れれば**外部一貫性の保証ごと崩壊**する。つまり時刻同期インフラの完全性は、それ自体が守るべき資産である前に、他のすべてのセキュリティ機構の暗黙の依存先である。
- **設計指針**: 時刻ソースの多重化（GNSS + 地上参照 + 保持時計）、ソース間の相互監視と投票、時刻ジャンプの速度制限、同期トラフィックの認証と分離。「時計がおかしい」を検知可能なイベントにすることが第一歩である。

## 結論 (Conclusions)

- 時刻同期は5層スタック——発振器 → 時系 → 配信 → 規律 → API——であり、達成可能な精度は最下層の発振器物理（アラン偏差）と配信路の非対称性で決まる。プロトコルの工夫は雑音源を除去・測定可能化するが、物理の上界を超えない。
- 精度の桁は「どこでタイムスタンプを押すか」で決まる: ソフトウェア (NTP, ms 級) → PHY ハードウェア + 滞留時間補正 (PTP, sub-µs〜ns 級) → 周波数の物理層同期まで動員 (White Rabbit, sub-ns 級)。桁を1つ買うたびに、対応ハードウェアという前提条件が増える。
- GNSS は世界規模の無料の時刻配信網であると同時に、微弱無線に依存する単一障害点である。保持時計 (holdover) と多重参照は性能仕様ではなく耐攻撃予算として設計すべきである。
- うるう秒は「地球自転への忠実さ」と「計算機の連続時間仮定」の衝突であり、スメアリングという弥縫策を経て、CGPM の 2035 年廃止決議（決定済み計画）で物理側が折れる方向に決着しつつある。
- 分散システムにとっての含意は明確である: Lamport 的には順序は物理時刻なしで作れるが、有界な不確かさ ε を持つ物理時計は commit-wait 型の設計（TrueTime）を可能にし、調整通信を待ち時間 ε で置き換える。**時計への投資は分散アルゴリズムの性能で回収される**。この橋があるからこそ、本ドキュメントは `hardware/` にありながら `software/distributed-systems/` の前提章である。
