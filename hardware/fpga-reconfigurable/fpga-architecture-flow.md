# FPGA のアーキテクチャと設計フロー (FPGA Architecture & Design Flow)

## 概要 (Overview)

[`../gpu-accelerators/tpu-systolic-arrays.md`](../gpu-accelerators/tpu-systolic-arrays.md) は、汎用 CPU → GPU → ドメイン特化アーキテクチャ (DSA) という**専用化スペクトラム**の DSA 端を見た。本ドキュメントはこのスペクトラムの**中間に位置する第三の選択肢**——製造後に回路そのものを書き換えられる **FPGA (field-programmable gate array)**——を分析する。CPU が「固定されたハードウェアの上で命令列を時間方向に実行する」機械であり ([`../cpu-architecture/pipeline-superscalar-ooo.md`](../cpu-architecture/pipeline-superscalar-ooo.md))、ASIC が「回路を製造時にシリコンへ焼き付ける」選択だとすれば、FPGA は「**回路を SRAM の設定ビットとして表現し、電源投入のたびにロードする**」——ハードウェアの形をしたソフトウェア、あるいはソフトウェアの柔軟性を持つハードウェアである。

この構造は二重の代償を払う: 論理は真理値表のルックアップで、配線はスイッチの連鎖で実現されるため、同一回路の ASIC 実装に対し面積で 1 桁以上、動作周波数で数倍劣る (Kuon & Rose の古典的定量化)。それでも FPGA が 40 年間市場を保持し続けるのは、[`../semiconductor-manufacturing/semiconductor-fabrication.md`](../semiconductor-manufacturing/semiconductor-fabrication.md) が示した先端ノードの NRE (マスク費用数億円〜数十億円規模) を**ゼロにする**からであり、さらに近年はデータセンターのネットワークデータプレーン (Microsoft Catapult / Azure SmartNIC) という「変化し続けるが線速で動かねばならない」ワークロードで固有の谷を見つけたからである。本ドキュメントはファブリックの構造 → ハード化ブロック → 設計フロー → HLS → 応用と専用化スペクトラムの順に、この特異なデバイスを解剖する。分析深度は Level 3。

## 方法論 (Methodology)

- ファブリックの分析は査読サーベイ (Kuon, Tessier & Rose 2008) を基点とし、**面積・遅延・電力の支配要因が何か**という定量的視点で構造を読む。ベンダ資料 (AMD/Xilinx・Intel/Altera) はアーキテクチャの一次資料として使うが、性能値はマーケティングと実測を区別する。
- FPGA vs ASIC のギャップは Kuon & Rose (2007) の測定を典拠とし、「典型値・桁の議論」であることを明示する——プロセス世代・回路の性質で数倍動く数字である。
- 設計フローはソフトウェアのコンパイルとの**構造的な差**——配置が物理座標を持つこと、タイミング収束が反復であること——を軸に整理する。
- データセンター応用は査読論文 (Putnam et al. ISCA'14、Firestone et al. NSDI'18) を一次資料とし、ベンダの応用例リストの網羅は避ける。

## 発見事項 (Findings)

1. **FPGA の本体は論理ではなく配線である。** LUT や演算器そのものはダイのごく一部にすぎず、面積の大半 (古典的な島型ファブリックで**軒並み 8〜9 割**) はプログラマブル配線——配線トラック・スイッチボックス・それらを制御する設定 SRAM——が占める。遅延も同様で、クリティカルパスの過半は論理段ではなく配線スイッチの通過が占めるのが典型である。FPGA のアーキテクチャ研究とは実質的に**配線アーキテクチャの研究**であり (Kuon et al. 2008)、後述の「配置配線が設計フローの主戦場になる」こともこの帰結である。
2. **LUT は「真理値表を SRAM に入れた万能論理素子」である。** k 入力 **ルックアップテーブル (LUT: lookup table)** は 2^k ビットの SRAM とマルチプレクサであり、k 入力の任意の組合せ論理関数を実装できる——AND も XOR も加算器の 1 段も、すべて「表引き」に均される。LUT サイズには面積と段数のトレードオフがあり (大きい LUT ほど段数は減るが 2^k で面積が爆発する)、業界は k=4 から k=6 近傍へ収斂した。LUT + フリップフロップ + キャリーチェーンの束が **CLB (configurable logic block)** / **ALM (adaptive logic module)** という配置の単位を成す。
3. **FPGA は時間方向の周波数で負けて空間方向の並列で勝つ。** ファブリックの実用周波数は典型 **100〜800 MHz** であり、3〜5 GHz の CPU に対し 5〜10 倍遅い (いずれも桁の議論)。それでも勝てるのは、CPU が「1 本の高速なパイプラインに命令を時分割で流す」のに対し、FPGA は「アルゴリズムの形をした回路を空間に展開し、**全段が毎サイクル同時に働く**」からである——数百段のパイプラインと数百個の並列演算器が立てば、周波数 1/10 でもスループットは 1〜2 桁勝ちうる。これは TPU のシストリックアレイと同じ空間計算の論理であり、FPGA はそれを「どんな形にでも」組める代わりに密度で劣る、という位置取りである。
4. **FPGA の進化は固定機能ブロックの取り込みの歴史である——純粋なファブリックから異種 SoC へ。** LUT でメモリや乗算器を組むのは桁違いに非効率なので、ベンダは頻出機能を**ハード化ブロック (hardened block)** としてシリコンに焼き、ファブリックはそれらを繋ぐ役に退いていった: **ブロック RAM (BRAM)** → **DSP スライス** (乗加算器) → **SerDes トランシーバ** → メモリコントローラ・PCIe・Ethernet MAC → ついには **ARM コア群との統合** (Xilinx Zynq / Versal、Intel SoC FPGA)。現代のハイエンド FPGA は「プログラマブル配線を接着剤とする異種 SoC」であり、「ゲートアレイ」という名前はもはや歴史的遺物である。
5. **配置配線はコンパイルではなく物理最適化であり、タイミングクロージャは反復である。** ソフトウェアのコンパイラは命令列を吐けば終わるが、FPGA の**配置配線 (place & route)** は各論理要素にダイ上の物理座標を与え、有限の配線資源を奪い合わせる NP 困難な最適化である。配線遅延は配置が決まるまで分からないため、**静的タイミング解析 (STA: static timing analysis)** が全パスの最悪遅延を検査し、目標周波数に届かなければ制約・コード・アーキテクチャを変えて再実行する——この**タイミングクロージャ (timing closure)** のループが数時間単位で回る。「ビルドに一晩かかり、結果が乱数シードで変わる」ことは、FPGA 開発がソフトウェア開発と根本的に異なる体験である最大の理由である。
6. **HLS はコンパイラではなく設計空間探索の道具である。** **高位合成 (HLS: high-level synthesis)** は C/C++ から RTL を生成するが、素朴な逐次コードを流しても良い回路は出ない——性能は `#pragma` で指示する**パイプライン化** (ループの **開始間隔 (II: initiation interval)** を 1 に詰める)・**アンローリング**・配列分割 (メモリポート数の確保) が決める。HLS が本当に抽象化するのはステートマシンとスケジューリングの記述であり、「どの並列性を空間に展開するか」という設計判断は人間に残る。抽象化は漏れる——II が 1 に詰まらない原因 (ループ搬送依存・メモリポート競合) を診断するには結局ハードウェアの思考が要る (Cong et al. 2011)。
7. **専用化スペクトラム上で FPGA は「少量・可変・低遅延」の谷を埋める。** ASIC は量産単価と電力効率で必ず勝つが NRE と 1〜2 年の設計期間を要し、仕様が動くと死ぬ。GPU は開発が速くスループットも高いが、レイテンシは百 µs 級でばらつき、電力も大きい。FPGA が選ばれるのは (a) 数量が NRE を償却できない、(b) 仕様・プロトコルが進化し続ける (Azure が SmartNIC に FPGA を選んだ明示的理由)、(c) **マイクロ秒未満の決定的レイテンシ**が要る (線速パケット処理・高頻度取引)、の交差点である。逆に言えば、ワークロードが固定し数量が立った瞬間、FPGA は ASIC に置き換えられる——FPGA は永住地ではなく、**仕様が固まるまでの中間状態**でもある。
8. **部分再構成は「回路のプロセス切替」であり、FPGA-as-a-Service の基盤である。** **部分再構成 (PR: partial reconfiguration)** は、ファブリックの一部領域だけを稼働中に書き換える——静的領域 (シェル: PCIe・DRAM・ネットワーク) を動かしたまま、動的領域 (ロール) のアクセラレータを差し替える。クラウド FPGA (AWS F1 型) はこのシェル/ロール分離でテナントのビットストリームを受け入れており、OS のプロセスモデルに相当する隔離をハードウェアで再発明している——そしてその隔離の綻びが後述のセキュリティ問題になる。

## アーキテクチャ (Architecture)

### 島型ファブリック (Island-Style Fabric) の構造

```
        IO / SerDes トランシーバ リング (10〜112 Gbit/s 級)
   ┌──────────────────────────────────────────────────────────┐
   │  IO   IO   IO   IO   IO   IO   IO   IO   IO   IO   IO    │
   │      ═╬════╬════╬═══╦════╬════╬═══╦════╬════╬═          │
   │  IO  ║CLB││CLB││CLB║B│  │CLB││CLB║D│  │CLB││CLB│   IO   │
   │      ═╬════╬════╬═══║R═══╬════╬═══║S════╬════╬═          │ ═║═ : 配線チャネル
   │  IO  ║CLB││CLB││CLB║A│  │CLB││CLB║P│  │CLB││CLB│   IO   │      (トラック束 +
   │      ═╬════╬════╬═══║M═══╬════╬═══║ ════╬════╬═          │       スイッチボックス)
   │  IO  ║CLB││CLB││CLB║列│  │CLB││CLB║列│  │CLB││CLB│  IO   │ CLB : LUT + FF +
   │      ═╬════╬════╬═══╩════╬════╬═══╩════╬════╬═          │       キャリーチェーン
   │  IO  │PCIe ハード IP │ メモリコントローラ │ (ARM コア群) │      │
   └──────────────────────────────────────────────────────────┘
    CLB の海に BRAM 列・DSP 列が柱状に埋まり、周縁をハード IP と
    高速 IO が囲む。すべての接続は設定 SRAM が制御するスイッチ経由。
```

- 論理はこの格子に**空間的に配置**され、信号はチャネルのスイッチを乗り継いで進む——発見事項 1 の「配線が支配する」構造がそのまま図になっている。BRAM/DSP を列状に置くのは、配置配線ツールがデータパスを列に沿って整列できるようにするためである。
- **設定ビットストリーム (configuration bitstream)** はこの全スイッチ・全 LUT の SRAM 内容を直列化したもので、現代の大型デバイスでは数百 Mbit〜Gbit 級に達する。SRAM ベースゆえ電源断で消え、起動のたびに外部フラッシュ等からロードされる——このロード経路がセキュリティ考察の主戦場になる。

### 専用化スペクトラム: FPGA vs GPU vs ASIC

| 観点 | FPGA | GPU ([`gpu-simt`](../gpu-accelerators/gpu-simt-architecture.md)) | ASIC (TPU 等) |
|---|---|---|---|
| NRE | ほぼゼロ (デバイス購入のみ) | ゼロ (既製品) | 数億〜数十億円 + 設計 1〜2 年 |
| 量産単価 | 高い (数万〜数百万円/個) | 中〜高 | 数量が立てば最安 |
| 柔軟性 | 回路レベルで再定義可能 | ソフトウェアで自由 | 製造後は固定 |
| 電力効率 | ASIC の 1/10 前後 (典型) | 汎用オーバーヘッド大 | 最高 |
| レイテンシ決定性 | クロック精度で決定的 | カーネル起動・スケジューラで変動 | 決定的 |
| 市場投入時間 | 数週〜数ヶ月 | 即日 | 1〜2 年 |

- 読み筋: 三者は優劣ではなく**「数量 × 仕様の安定度 × レイテンシ要求」の関数としての最適点の違い**である。TPU の分析で見た「固定して効率を買う」戦略の対極に「柔軟性を買って効率を払う」FPGA があり、GPU はその中間で「プログラミングモデルの慣性」という独自の資産を持つ。

## 技術詳細 (Technical Details)

### 1. LUT・CLB・配線 (LUT, CLB & Routing)

6 入力 LUT は 64 bit の SRAM + 64:1 マルチプレクサであり、設定ビットが真理値表そのものである。CLB はこれを数個束ね、各 LUT 出力に**フリップフロップ**を併設する (パイプライン段を「タダで」切れることが FPGA 設計の基本語彙になる)。加算のための**キャリーチェーン**だけは LUT を迂回する専用配線を持つ——汎用配線を通すと遅すぎるからで、「頻出パターンのハード化」の最小単位である。配線側は、CLB 間のチャネルを走る長さ別のトラック (隣接・4 飛び・長距離) と、交差点の**スイッチボックス**で構成され、どのトラック同士を繋ぐかも設定 SRAM が決める。1 個の論理を通すために信号は複数のパストランジスタ/バッファ付きスイッチを通過し、これが ASIC 比の遅延ギャップ (Kuon & Rose 2007 の測定で遅延 3〜4 倍、面積 20〜40 倍、動的電力 10 倍強——ハード化ブロックの活用で面積ギャップは大幅に縮む) の主因になる。

### 2. ハード化ブロック (Hardened Blocks)

- **BRAM**: 数十 Kbit 級 (Xilinx で 36 Kbit が典型) のデュアルポート SRAM ブロック。LUT の分散 RAM では数百ビットが限度であり、FIFO・バッファ・テーブルはすべて BRAM に載る。近年はさらに大きい UltraRAM/eSRAM 階層が加わる——[`../cpu-architecture/cache-memory-hierarchy.md`](../cpu-architecture/cache-memory-hierarchy.md) の階層の論理がファブリック内で再現される。
- **DSP スライス**: 18×27 bit 級の乗算器 + 前置加算器 + アキュムレータ。フィルタ・行列積・機械学習推論の主役で、ハイエンドデバイスは数千〜1 万個超を積む。
- **SerDes トランシーバ**: 10〜112 Gbit/s 級の送受信器。構造は [`../serdes-signal-integrity/serdes-link-architecture.md`](../serdes-signal-integrity/serdes-link-architecture.md) で分析した CDR・イコライザの積層そのものであり、これを LUT で組むことは物理的に不可能——ハード化が必然の代表例である。
- **プロセッサ統合**: Zynq/Versal は ARM Cortex-A 群 + 周辺回路の完全な SoC サブシステムとファブリックを AXI で結合する。制御平面 (Linux・管理・例外処理) をソフトウェアに、データ平面をファブリックに置く分業が定型化した。

### 3. 設計フロー (Design Flow)

```
 HDL (Verilog/VHDL)                     ソフトウェアとの対比
   │ 論理合成 (synthesis)                = コンパイル (論理→LUT ネットリスト)
   ▼
 配置 (placement)                       ここから先に相当物がない:
   │  各要素へ物理座標を割当             ネットリストの各要素がダイ上の
   ▼                                    座標を持ち、距離が遅延になる
 配線 (routing)
   │  有限トラックの割当 (NP 困難)
   ▼
 STA (静的タイミング解析) ──不合格──▶ 制約/コード/配置シードを変えて再実行
   │ 合格                              (タイミングクロージャのループ、
   ▼                                    1 周が数十分〜数時間)
 ビットストリーム生成
```

ソフトウェアのコンパイルと決定的に違うのは、(a) 中間段階の**配置が物理的**であり局所最適化の連鎖では解けないこと (焼きなまし・解析的配置などの大域最適化を使う)、(b) 正しさが機能だけでなく**時序** (すべてのレジスタ間パスがクロック周期内に収まるか) で定義されること、(c) それゆえフローが**一発では通らない前提の反復**であること。STA はクロック制約に対し全パスのセットアップ/ホールドスラックを網羅的に計算する——シミュレーションではなく静的解析なので網羅性が保証される代わりに、クロック乗り換えや偽パスの制約記述 (SDC) を人間が正しく与える責任が残る。

### 4. 高位合成 (HLS)

HLS はループを回路のパイプラインに写像する。**II = 1** (毎サイクル新しい入力を受ける) が理想で、`ap_pipeline` 相当のプラグマで指示するが、ループ搬送依存 (前反復の結果を次反復が読む) や BRAM のポート数 (デュアルポートに 3 読み出しは同時にできない) が II を押し上げる。対策——配列分割・依存の距離化・アンローリング——はすべて「メモリと依存の空間配置」の話であり、HLS の生産性向上 (RTL 比で記述量 1 桁減、検証は C レベルで高速) は本物だが、性能チューニングの思考はハードウェアのままである。近年の AI 向けフレームワーク (DSL → HLS → ビットストリーム) はこの上にさらに抽象を積む方向にある。

### 5. 応用: どこで勝つか (Where FPGAs Win)

- **Microsoft Catapult (ISCA'14)**: Bing 検索ランキングを 1,632 台のサーバに載せた FPGA で加速し、スループット約 2 倍/テールレイテンシ 29% 削減を実測——データセンター規模で FPGA が経済的に成立することを示した画期であり、後続の Azure 全面展開の起点。
- **Azure Accelerated Networking (NSDI'18)**: 仮想ネットワークのフロー処理 (VFP 相当のマッチアクション) を SmartNIC の FPGA にオフロードし、ホスト CPU コアを解放しつつ 25 µs 級→数 µs 級のレイテンシを達成。**「仕様が進化し続けるためASIC にできず、CPU では線速に届かない」**という FPGA の谷の教科書的事例。NIC/スイッチ側の全体像は [`../network-hardware/nic-switch-architecture.md`](../network-hardware/nic-switch-architecture.md) が扱う。Open vSwitch のフローテーブルオフロードも同型の分業 (例外系はソフトウェア、定常フローはハードウェア) である。
- その他の定番: プロトコルブリッジ (規格間変換)、ASIC プロトタイピング/エミュレーション (テープアウト前の実機検証)、計測器・軍用・宇宙 (少量 + 長寿命 + 現地更新)。共通項は**線速・低固定レイテンシ・少量・可変**である。

### 6. 定量的特性 (Quantitative Characteristics)

いずれも**典型値・桁の議論**であり、世代・製品ラインで数倍動く (ベンダの「ロジックセル数」は LUT 数に係数を掛けたマーケティング単位である点にも注意)。

| 特性 | ローエンド | ミッドレンジ | ハイエンド |
|---|---|---|---|
| LUT 数 | 数千〜数万 | 数万〜数十万 | 数十万〜数百万 (最大級で 400 万超) |
| BRAM 総量 | 〜1 Mbit | 数 Mbit〜数十 Mbit | 数十〜数百 Mbit (+UltraRAM) |
| DSP スライス | 数十 | 数百〜数千 | 数千〜1 万超 |
| ファブリック実用クロック | 100〜300 MHz | 200〜500 MHz | 300〜800 MHz (設計依存) |
| トランシーバ | なし〜数 Gbit/s | 10〜28 Gbit/s 級 | 56〜112 Gbit/s (PAM4) |
| ビットストリーム | 〜数 Mbit | 数十 Mbit | 数百 Mbit〜Gbit 級 |
| 電力 | 〜1 W (電池駆動可) | 数 W〜数十 W | 数十〜100 W 超 |

- 実用クロックが「設計依存」なのは本質的である: ASIC・CPU の周波数はほぼ製品仕様だが、FPGA の周波数は**その設計の配置配線結果**であり、同じデバイスでもパイプライン切りと配置の質で 2〜3 倍変わる。発見事項 3 の 5〜10 倍ギャップは、この設計依存の上に載る桁の目安である。

## セキュリティ考察 (Security Considerations)

- **ビットストリームは「回路の実行ファイル」であり、同じ脅威モデルを持つ**。平文ビットストリームは (a) リバースエンジニアリングによる IP 窃取、(b) 改竄による**ハードウェアトロイの木馬**注入、(c) クローン製品の複製に晒される。対策は**ビットストリーム暗号化** (AES、鍵はデバイス内の eFuse/BBRAM に格納) + **認証** (HMAC/RSA 署名検証をロード前に実施) + **リードバック禁止**の三点セットで、[`../hardware-security/side-channels-tee-secure-boot.md`](../hardware-security/side-channels-tee-secure-boot.md) のセキュアブートの信頼連鎖がそのまま適用される——そして同文書の教訓どおり、鍵を扱う復号回路自体が電力サイドチャネル攻撃の標的になった実例 (7 シリーズ世代の暗号化破り) がある。
- **クラウドのマルチテナント FPGA は電気的な隔離破りを許す**。論理的に分離されたテナント間でも、共有する電源網 (PDN) と物理的近接が漏洩路になる: リングオシレータ等で構成した**電圧センサをファブリック内にソフトウェア的に構築**し、隣接テナントの消費電力波形——すなわち処理内容や暗号鍵の痕跡——を読み取る攻撃、逆に電力を意図的に振動させて隣接テナントに**故障注入**する攻撃 (Krautter/Gnad らの一連の研究、FPGAhammer 等) が学術的に実証された。さらに**長配線 (long wire) の容量結合**により、隣接配線の信号値が静的にリークすることも示されている。いずれも「回路を書ける」という FPGA の本質的能力がセンサ/攻撃器の構築能力そのものであることに根差し、クラウド事業者は組合せループ検査などのビットストリーム静的検査で対抗するが、検査とすり抜けの追いかけ合いが続いている。
- **部分再構成は攻撃面を動的にする**。PR はロード経路が常時開いていることを意味し、シェル/ロール境界の検証 (ロールが勝手にシェルの資源・他テナント領域に配線を伸ばせないこと) をツールチェーンと検査に依存する。検証をすり抜けた悪意あるロールは、上記の電気的攻撃の理想的な足場になる。
- **サプライチェーン**: FPGA 自体は「製造後にロジックが決まる」ためファウンドリでのトロイ注入に相対的に強い——設計者の回路を工場が知り得ない——が、その分**ツールチェーンとビットストリームの完全性**に信頼が集中する。閉じたバイナリ形式であるビットストリームの難読性は防御ではなく、フォーマットのリバースエンジニアリングは複数世代で公開済みと考えるべきである。

## 結論 (Conclusions)

FPGA は「論理を SRAM の表引きに、接続をスイッチの海に均す」ことで製造後の完全な可塑性を獲得し、その代償として面積・遅延・電力で ASIC に 1 桁譲るデバイスである。本体は配線であり、設計フローの重心も配線 (配置配線とタイミングクロージャ) にある。周波数で CPU に 5〜10 倍負けながら空間並列で勝つという構図は GPU・TPU と同じ空間計算の系譜だが、FPGA だけが「回路の形自体を後から決められる」。その固有の谷——少量・可変仕様・決定的低レイテンシ——は、NRE の高騰 (半導体製造側の事情) とデータセンターネットワークの進化速度 (ソフトウェア側の事情) に挟まれて今後も存続する。一方でハード化ブロックの取り込みが進むほど FPGA は ASIC の集合体に近づき、「どこまでをファブリックに残すか」という問い自体が専用化スペクトラムの縮図になっている。
