# ハードウェアセキュリティ (Hardware Security) — サイドチャネル・TEE・信頼の起点

## 概要 (Overview)

命令セットアーキテクチャ (ISA) は、プログラマとハードウェアの間の**契約 (contract)** である。だがその契約が規定するのは**アーキテクチャ状態 (architectural state)**（汎用レジスタ、メモリの値、フラグ）の振る舞いだけであり、それを実現する**マイクロアーキテクチャ状態 (microarchitectural state)**（キャッシュ、分岐予測器、各種バッファ、DRAM のセル電荷）については何も規定しない。性能はまさにこの「規定されない部分」を最適化することで稼がれる。そして**サイドチャネル (side channel) は、契約が沈黙するちょうどその隙間に棲む**。

本ドキュメントは、この「アーキテクチャ状態とマイクロアーキテクチャ状態の乖離」を一貫した軸として、ハードウェアセキュリティの中核を Level 3（完全）で整理する。すなわち、キャッシュタイミングチャネル、一時的実行攻撃 (transient execution attack)、Rowhammer という**論理的・遠隔の攻撃**から、電力・電磁波・フォールト注入という**物理的・局所の攻撃**まで、攻撃面を脅威モデル (threat model) で分類する。その上で、隔離の側にある **TEE (Trusted Execution Environment)**、**信頼の起点 (root of trust)** と Secure/Measured Boot を、攻撃との対で扱う。`../cpu/branch-prediction-speculation.md`（投機実行と Spectre）と `../hw-sw-interface/boot-initialization.md`（信頼の連鎖）の上に立ち、それらを「防御の体系」として束ね直す位置づけである。

本章は公開研究・防御教育のレベルに徹する。機構と緩和策を説明するが、動作する攻撃コードや手順書は示さない。

## 方法論 (Methodology)

- 攻撃面を**脅威モデルの3分類**で切る。(1) 論理的・遠隔（サイドチャネル: 攻撃者コードが被害者と同一マシンで走る）、(2) 物理的・局所（電力・電磁波・フォールト注入: 攻撃者がデバイスに物理接触する）、(3) サプライチェーン（設計・製造・流通段での改竄）。要求される攻撃者の能力が根本的に異なる。
- 一貫した観測モデルとして「**符号化 → 伝送 → 復号**」を使う。秘密がマイクロアーキテクチャ状態に符号化され、共有資源を通じて伝送され、タイミング差として復号される、という共通の枠組みで各攻撃を並べる。
- 攻撃と緩和を必ず**対**で扱う。攻撃だけ・緩和だけを孤立させず、「何を封じると何が残るか（残余リスク）」を各所で明示する。
- 数値は**桁感 (order of magnitude)** に徹する。緩和策のオーバーヘッドは公表された範囲 (published range) で示し、世代・ワークロード依存であることを都度断る。捏造された精度は用いない。
- 評価軸は終始「**隔離 (isolation) と最適化 (optimization) の対立**」。両者は根本的に緊張関係にあり、あらゆる緩和策はこの対立のどこに線を引くかの選択である、という視点で貫く。

## 発見事項 (Findings)

1. **サイドチャネルは ISA 契約の「規定されない隙間」に棲む。** ISA はアーキテクチャ状態の契約であり、キャッシュ・予測器・バッファ・DRAM 物理といったマイクロアーキテクチャ状態は仕様外である。攻撃者はこの仕様の空白、つまり性能のために存在する共有状態を観測経路に変える。したがってサイドチャネルはバグではなく、抽象化の**構造的帰結**である。

2. **一時的実行攻撃の分水嶺は「予測器の訓練」か「例外の遅延」かである。** Spectre は攻撃者が予測器を汚染して被害者に誤った投機をさせる（プログラム構造の問題）のに対し、Meltdown は権限チェックの遅延評価 (lazy permission check) を突く実装欠陥である。この差ゆえに Meltdown は OS のページテーブル分離 (KPTI) で塞げたが、Spectre v1 はプログラムの構造そのものに宿り、包括的なハードウェア修正が難しい。

3. **Rowhammer は「信頼性マージンが安全境界である」ことを暴いた。** DRAM の微細化 (cell density) が進み、隣接行の反復アクセスによる電荷漏洩 (charge leakage) がビット反転を起こす。これは本来「信頼性の欠陥 (reliability defect)」だが、攻撃者が権限境界を跨ぐビット（ページテーブルエントリ等）を狙って反転させれば**安全境界の侵犯**になる。物理層の余裕を削る最適化が、そのまま攻撃面を開く。

4. **TEE は「何を信頼から外すか」で設計が分かれ、万能はない。** TrustZone はワールド二分、SGX は最小の TCB (Trusted Computing Base) を目指す飛び地 (enclave)、SEV-SNP / TDX は VM 全体の機密計算、Secure Enclave は独立コプロセッサ、と設計思想が異なる。どれも縮めた TCB の外は守るが、内側に残るサイドチャネル（特に SGX はマイクロアーキテクチャ的に多孔質）や、脅威モデル外の攻撃には無力である。

5. **信頼の起点は「最初の一点だけは無条件に信じる」設計上の妥協である。** ソフトで検証する以上、最初の検証コードは検証できない。ゆえに書き換え不能なブート ROM を**信頼の起点 (root of trust)** としてシリコンに固定し、そこから署名検証で信頼を連鎖させる。Measured Boot は TPM の PCR に測定値を積んで事後の遠隔検証を可能にする。連鎖の一段でも検証を飛ばせば、そこが崩壊点になる。

6. **隔離と最適化は根本的に対立し、緩和は常に性能と引き換えである。** 共有（キャッシュ、予測器、SMT、cache-to-cache 転送）は性能を生むが、共有こそが漏洩経路である。したがって隔離を強めれば性能が落ちる。Meltdown/Spectre 緩和の実測オーバーヘッドがこれを定量的に示す。「速く」と「漏らさない」は同じ資源を奪い合う。

## アーキテクチャ (Architecture)

### アーキテクチャ状態とマイクロアーキテクチャ状態の乖離

すべての出発点は、ISA が保証する層と、性能のために存在する層の**乖離**である。サイドチャネルはこの境界を斜めに貫く。

```
   ┌──────────────────────────────────────────────────────────┐
   │  アーキテクチャ状態 (Architectural State) — ISA の契約     │
   │    汎用レジスタ / メモリの値 / フラグ / 例外の可視性       │
   │    ← プログラムから見える。仕様で振る舞いが定義される      │
   └──────────────────────────────────────────────────────────┘
        ▲                                          │
        │ 正規のインタフェース (load/store, 分岐)   │ 秘密が「漏れる」
        │                                          ▼   斜めの経路
   ┌──────────────────────────────────────────────────────────┐
   │  マイクロアーキテクチャ状態 (Microarchitectural State)     │
   │    キャッシュ占有 / 分岐予測器 / TLB / ラインフィル・      │
   │    ストアバッファ / DRAM セル電荷 / ポート競合             │
   │    ← 仕様外。性能のためだけに存在し、共有される            │
   └──────────────────────────────────────────────────────────┘
     ╲                                                        ╱
      ╲────  side channel: 下層の状態を「時間」として観測  ───╱
            (Flush+Reload / Prime+Probe / 一時的実行 / …)

   凡例: ═ 契約で定義された経路   ╲╱ 契約外の観測経路（サイドチャネル）
```

上層は契約で守られるが、下層は「速さのための共有状態」であり誰の契約にも縛られない。攻撃者は下層の状態を**タイミング**という物差しで読み、上層の秘密を復元する。本章の攻撃はすべて、この一枚の図の「斜めの矢印」の変奏である。

### 脅威モデルの分類

| 分類 | 攻撃者の位置 | 必要能力 | 代表 | 主眼の防御 |
|---|---|---|---|---|
| 論理的・遠隔 (side channel) | 同一マシンで攻撃者コードが実行 | 共有資源へのアクセス、精密タイマ | Flush+Reload, Spectre, Meltdown | 隔離・定数時間・投機制御 |
| 物理的・局所 (physical) | デバイスに物理接触 | 測定器・グリッチ装置 | 電力/EM 解析, フォールト注入 | 遮蔽・マスキング・センサ・冗長 |
| サプライチェーン | 設計/製造/流通段 | 改竄機会・内部アクセス | ハードウェアトロイ, 差し替え | 来歴・検証・多者検証 |

要求される能力の差が決定的である。サイドチャネルはネットワーク越しや同一クラウド上でも成立しうる一方、フォールト注入はデバイスの物理占有を要する。防御はこの脅威モデルに対して初めて意味を持つ。想定外のモデルには無力なのが原則である。

## 技術詳細 (Technical Details)

### 1. キャッシュタイミングサイドチャネル

キャッシュヒットとミスの**時間差**（ヒット数サイクル vs ミス数十〜数百サイクル、`../cpu/cache-memory-hierarchy.md`）が、すべてのキャッシュチャネルの物差しである。攻撃者は自分のアクセス時間を測ることで、被害者がどのアドレス（キャッシュライン／セット）に触れたかを推定する。共有 LLC (last-level cache) が包含的 (inclusive) であること、`clflush` でラインを追い出せることが前提技術になる。

- **Flush+Reload**: 攻撃者と被害者が**同一の物理ページを共有**する（共有ライブラリ、ページ重複排除など）ことを前提とする。攻撃者は対象ラインを `clflush` で全キャッシュ階層から追い出し、被害者を動かし、再び同じラインを読んでアクセス時間を測る。速ければ「被害者が触れた（=キャッシュに載せ直した）」、遅ければ「触れていない」。**ライン粒度**で高分解能・低ノイズ。Yarom & Falkner (2014) が定式化した。
- **Prime+Probe**: 共有メモリを**前提としない**。攻撃者は対象キャッシュ**セット**を自分のデータで埋め (prime)、被害者を動かし、再び自分のデータを読み返す (probe)。被害者が同じセットを使えば攻撃者のラインが追い出され、probe が遅くなる。共有メモリ不要ゆえ適用範囲が広いが、分解能は**セット粒度**でノイズが多い。
- **Evict+Time**: 対象ラインを追い出してから被害者の**実行全体の時間**を測り、そのラインを使ったか否かを実行時間の差から推定する。最も間接的でノイズが大きいが、`clflush` も共有も使えない状況の観測手段になる。

三者の差は要求資源にある。Flush+Reload は共有メモリを要する代わりに高精度、Prime+Probe は同一セットへの競合 (same-set contention) だけで済む代わりに粗い。`../cpu/cache-coherence.md` のコヒーレンス状態を跨コアで観測するクロスコア変種もある。

### 2. 一時的実行攻撃 (Transient Execution Attacks)

投機実行 (speculative execution) は、分岐や例外の確定前に後続命令を先行実行する。確定後、投機分はアーキテクチャ状態からは**ロールバック**されるが、その途中でキャッシュ等に残した痕跡は巻き戻らない。この非対称性がすべての一時的実行攻撃の根である（`../cpu/branch-prediction-speculation.md`）。攻撃は「秘密に依存する投機を誘発 → 秘密をキャッシュへ符号化 → Flush+Reload 等で復号」の流れを共有する。

**Spectre v1 (Bounds Check Bypass, CVE-2017-5753)** は境界チェック分岐を標的とする。教科書的なガジェットパターン（Kocher et al. 2019 で公表されたもの）を示す。

```c
// 例示 (illustrative)。攻撃される側の脆弱パターン。実コードではない。
if (x < array1_size) {            // ① 攻撃者が予測器を「成立」に訓練
    uint8_t v = array1[x];        // ② 境界外の秘密 v を投機的にロード
    uint8_t y = array2[v * 64];   // ③ v 依存アドレスをキャッシュに符号化
}
// 分岐解決後 ②③ はロールバックされるが、array2 のキャッシュ痕跡は残る。
// 攻撃者は array2 を走査し、ヒットしたラインから v を逆算する。
```

攻撃者は正当な `x` で分岐を繰り返し**方向予測器を訓練**し、次に境界外の `x` を与える。CPU は境界チェックの解決を待たず投機し、範囲外の秘密をキャッシュに刻む。要点は**予測器の訓練**にある。

**Spectre v2 (Branch Target Injection, CVE-2017-5715)** は間接分岐の**ターゲット**を汚染する。攻撃者は自プロセスから BTB／間接分岐予測器を細工し、被害者の間接分岐 (`jmp [reg]`) を攻撃者の選んだガジェットへ投機的に飛ばす。被害者権限で任意コード断片を投機実行させ、秘密を符号化する。予測器が物理コア内（SMT 兄弟スレッド含む）で共有される構造が汚染を可能にする。

**Meltdown (CVE-2017-5754)** は本質的に異なる。分岐予測ではなく、権限違反ロードの**例外が遅延評価される**実装欠陥を突く。ユーザモードからカーネルアドレスをロードすると最終的に例外が上がるが、それが確定する前の短い窓で、投機的にその値を使いキャッシュへ符号化できてしまう。これは**遅延した権限チェック (lazy permission check)** という実装の穴であり、予測器の訓練を要しない。

この差が緩和の運命を分けた。Meltdown はユーザ空間からカーネルのページテーブルを見えなくする **KPTI (Kernel Page-Table Isolation, `../cpu/virtual-memory-mmu.md`)** で OS 側から塞げた。例外窓で参照する対象そのものを、アドレス空間から消せたからである。対して Spectre v1 は「境界チェックの後に秘密依存アクセスがある」というプログラム構造そのものが脆弱性であり、単一のハードウェア／OS 修正では包括的に消せず、脆弱箇所ごとの対処が要る。

**MDS / L1TF クラス（漏れやすいバッファの一般化）**: Meltdown が権限境界を跨いだのに対し、MDS (Microarchitectural Data Sampling; RIDL/Fallout/ZombieLoad 等) と L1TF (Foreshadow) は**中間バッファ**（ラインフィルバッファ、ストアバッファ、ロードポート、L1D）に残るデータを投機的に拾う。「秘密は L1 やバッファに滞留し、境界を越えて漏れうる」という一般化であり、SMT 兄弟スレッド越しにも成立しうる。

**緩和策とコスト階級**:

| 緩和 | 対象 | 機構 | コスト階級（桁感・要約） |
|---|---|---|---|
| KPTI | Meltdown | ユーザ/カーネルのページテーブル分離 | syscall/割込多発で重い。範囲は数%〜二桁%（PCID 有無・ワークロード依存） |
| retpoline | Spectre v2 | 間接分岐を `call`/`ret` へ書換え予測を無効化 | 間接分岐の多いコードで無視できない。低〜中 |
| IBRS / eIBRS / IBPB | Spectre v2 | 特権/文脈境界で間接予測を制限・障壁 | eIBRS で常時化し軽減。境界頻度依存 |
| fence マスキング (`lfence`, index mask) | Spectre v1 | 秘密依存ロードの投機を停止／範囲丸め | 脆弱箇所限定なら軽微、広域適用は重い |
| MDS/L1TF 緩和 (バッファフラッシュ, SMT 無効化) | MDS/L1TF | 遷移時にバッファ消去、必要なら SMT 停止 | SMT 無効化はスループットを大きく削る |

すべてに共通するのは、**共有を断つか投機を抑えるほど性能を失う**という等式である。実務では信頼境界（カーネル、サンドボックス、JIT）を跨ぐコードにのみ重い緩和を絞るのが妥協点になる。

### 3. Rowhammer — 物理層の信頼性が安全境界になる

DRAM のセルはコンデンサの電荷で 1bit を保持し、微細化でセルは密集し電荷も小さくなった。ある行 (row) を高頻度で反復アクセス（開閉）すると、**隣接行のセルから電荷が漏れ**、リフレッシュ前にビットが反転する。これが**擾乱誤り (disturbance error)** である。Kim et al. (2014) が市販 DRAM で系統的に実証した。

これは本来 DRAM の**信頼性欠陥**である。だが攻撃者が、権限昇格に使えるビット（ページテーブルエントリの権限ビット、暗号鍵、`setuid` 判定など）を含む物理行を狙って反転させれば、**安全境界の侵犯**に転化する。物理メモリ配置を仕向ける手法（メモリスプレー、ページ重複排除の悪用）と組み合わせて標的ビットを近傍に配置する。

- **TRR (Target Row Refresh)** はハンマー対象の近傍行を検出して余分にリフレッシュする緩和だが、**TRRespass** はアクセスパターンを多数行に分散させて TRR の検出ロジックを飽和・回避し、緩和を無力化しうることを示した。
- **ECC (Error-Correcting Code)** は単一ビット誤りを訂正・二重を検出するが、Rowhammer は**複数ビット**を同時反転しうるため万能ではなく、ECC は攻撃を難しくするが排除はしない（ECCploit 等）。
- 教訓は明快である。**物理層の信頼性マージンは、そのまま安全境界である**。性能・密度・コストのために削った物理的余裕が、直接に攻撃面を開く。ここでも最適化と隔離は対立する。

### 4. TEE (Trusted Execution Environment) の比較

TEE は「システムの大半が侵害されても、なお守られる小さな実行環境」を作る。設計の分岐点は「**TCB (Trusted Computing Base) をどこまで縮め、何を信頼から外すか**」である。

| TEE | 隔離方式 | TCB 規模 | 保護粒度 | メモリ暗号化 | 認証 (attestation) | 既知の攻撃クラス |
|---|---|---|---|---|---|---|
| **ARM TrustZone** | セキュア/非セキュアの**ワールド二分** | 中（セキュア OS 全体） | ワールド単位 | 実装依存（オンチップ隔離が主） | ベンダ依存 | セキュア OS 脆弱性, キャッシュ側チャネル |
| **Intel SGX** | プロセス内の**飛び地 (enclave)** | 最小（enclave コードのみ、OS/VMM を信頼から除外） | ページ単位の飛び地 | あり（メモリ暗号化） | リモート認証あり | 一時的実行 (Foreshadow), マイクロアーキ側チャネルに多孔質 |
| **AMD SEV-SNP** | **VM 全体**の機密化 | 大（ゲスト OS 込み）だがハイパバイザを除外 | VM 単位 | あり（VM 鍵で暗号化＋完全性） | あり | 側チャネル, 初期世代の完全性欠如（SNP で改善） |
| **Intel TDX** | **VM 全体**（Trust Domain） | 大（ゲスト込み）、VMM を除外 | VM 単位 | あり | あり | 側チャネル, インタフェース攻撃面 |
| **Apple Secure Enclave** | **独立コプロセッサ** | 小（専用 SoC ブロック） | デバイス単位（鍵・生体） | あり（専用メモリ） | あり | 物理攻撃, 限定的な側チャネル |

思想の対比が要点である。**SGX** は TCB を enclave コードだけへ極小化し OS も VMM も信頼から外す。だが引き換えに、共有キャッシュ・予測器といったマイクロアーキテクチャ資源は依然ホスト側と共有され、**側チャネルに対して多孔質 (side-channel-porous)** である（Foreshadow/L1TF が enclave を貫いた）。**SEV-SNP / TDX** は逆に、ゲスト OS ごと丸ごと機密化して既存 VM をほぼ無改変で保護する代わりに TCB は大きい（**機密計算 (confidential computing)**）。**Secure Enclave** は物理的に別コプロセッサへ隔離し（`../../software/ios/security-architecture.md`）、鍵材料を主 CPU から根本的に分離する。**TrustZone** はワールド二分で軽量だがセキュア OS 全体が TCB に入る（Android の利用は `../../software/android/security-model.md`）。

どの TEE も「縮めた TCB の外」は守るが、(1) 内側に残るサイドチャネル、(2) 脅威モデル外の物理攻撃、(3) 認証プロトコルやインタフェースの実装欠陥、には本質的に脆弱でありうる。万能な TEE は存在しない。

### 5. 信頼の起点と Secure / Measured Boot

TEE が「実行時の隔離」なら、Secure/Measured Boot は「**起動時の完全性**」を担う（`../hw-sw-interface/boot-initialization.md`）。核心は**信頼の起点 (root of trust)** である。ソフトで検証する以上、最初の検証コードだけは検証できないので、書き換え不能なブート ROM に無条件の信頼を固定する。そこから各段が次段の署名を検証し、信頼を連鎖させる。

```
   信頼の連鎖 (Chain of Trust) と TPM PCR への測定

   ┌───────────────┐  検証+測定   ┌───────────────┐
   │ Boot ROM      │─────────────►│ 1st-stage FW  │
   │ (不変・RoT)   │  署名照合     │ (BL1/SEC)     │
   │ ハッシュ鍵内蔵 │              └──────┬────────┘
   └──────┬────────┘                     │ 検証+測定
          │ measure                       ▼
          │            ┌───────────────┐  ┌───────────────┐
          │            │ Bootloader    │─►│ OS Kernel     │
          │            │ (BL2/DXE)     │  │               │
          │            └──────┬────────┘  └──────┬────────┘
          │  measure          │ measure          │ measure
          ▼                   ▼                  ▼
   ┌──────────────────────────────────────────────────────┐
   │  TPM — Platform Configuration Registers (PCR)          │
   │   PCR[n] ← extend:  new = HASH( old ‖ measurement )    │
   │   * extend は一方向。順序も含めて畳み込むので改変不能  │
   │   → Remote Attestation で外部が起動状態を検証          │
   │   → Sealing: PCR 値が一致する時だけ鍵を解封            │
   └──────────────────────────────────────────────────────┘

   Secure Boot   : 署名が不正なら「起動を止める」（予防）
   Measured Boot : 止めず PCR に「記録する」→ 事後に遠隔検証（検知）
```

- **Secure Boot（検証ブート）**: 各段が次段のデジタル署名を、ROM/ヒューズに焼いた公開鍵で検証し、不正なら起動を止める。ブートキットや改竄カーネルの足場を断つ。
- **Measured Boot（測定ブート）**: 起動は止めず、各段のハッシュを TPM の **PCR (Platform Configuration Register)** に `extend`（`PCR ← HASH(PCR ‖ measurement)`、一方向で順序も畳み込む）で積む。事後に**リモート認証 (remote attestation)** で「何が動いたか」を外部が検証でき、鍵の封印 (sealing) 条件にも使える。両者は予防と検知の補完関係で併用される（TCG TPM 2.0 仕様）。
- **アンチロールバック (anti-rollback)**: 旧い脆弱なファーム／カーネルへ差し戻す攻撃を、バージョンの単調増加を**ヒューズ等のモノトニックカウンタ**で強制して拒む。旧版の署名が有効でも起動させない。

### 6. 物理攻撃の概観（分析レベル）

物理接触を前提とする脅威モデルは、論理的サイドチャネルとは別世界である。ここでは機構と対策を分析レベルで述べ、操作手順は扱わない。

- **電力・電磁波解析 (power / EM analysis)**: CMOS 回路の消費電力とビットの遷移は相関し、**鍵に依存して電力波形が変わる**。単純電力解析 (SPA) は単一波形から演算列を読み、差分電力解析 (DPA, Kocher et al. 1999) は多数波形の統計から鍵ビットを分離する。電磁波はこれを非接触で行う変種である。
- **フォールト注入 (fault injection)**: 動作条件を意図的に逸脱させ計算を誤らせ、その誤りから秘密を漏らす（例: 署名の一時故障から鍵を復元する DFA）。手段は**電圧グリッチ・クロックグリッチ**（電源やクロックを一瞬乱す）、**レーザ注入**（特定トランジスタを光で反転）など。
- **対策**: 電圧/クロック/光/温度の**センサ**による異常検知、計算の**冗長化 (redundancy)** と照合（二重実行・チェックサム）、秘密依存の分岐・アクセスを排した**定数時間 (constant-time)** 実装、電力相関を乱す**マスキング (masking)**（秘密を乱数で分割して処理）。いずれも面積・電力・性能のコストを払って耐性を買う。

## セキュリティ考察 (Security Considerations)

本章全体がセキュリティであるため、ここではメタレベルの構造的論点として、**隔離と最適化の対立、緩和の経済性、残余リスク**を論じる。

### 緩和の経済性 — 桁感の整理

一時的実行攻撃の緩和は、性能という通貨で支払われる。以下は**桁感**であり、世代・ワークロード・構成（PCID、eIBRS、SMT）に強く依存する。単一の精密値ではなく、公表された範囲として読むべきである。

| 緩和 | 重い局面 | オーバーヘッドの桁感（要約・範囲） |
|---|---|---|
| KPTI (Meltdown) | syscall／割込／文脈切替が多い I/O 集約系 | 計算主体なら小、syscall 多発で数%〜二桁%。PCID で大幅緩和 |
| retpoline (Spectre v2) | 間接分岐の多いコード（インタプリタ等） | 低〜中。分岐特性依存 |
| Spectre v1 マスキング | 脆弱箇所限定なら軽微、広域なら累積 | 箇所限定で最小化するのが定石 |
| SMT 無効化 (MDS/L1TF の最終手段) | スループット依存の並列負荷 | スループットを大きく損なう（最も高価な部類） |

要点は**総合オーバーヘッドは「どの緩和を、どこまで、どのワークロードに」適用するかで桁が動く**ことである。だからこそ実務は、信頼境界を跨ぐコードにのみ重い緩和を絞る。無差別適用は最も安全だが最も高価である。

### 残余リスク (Residual Risk)

- **Spectre v1 は原理的に「残る」**。プログラム構造の問題であり、脆弱ガジェットを一つずつ修正する以上の包括的解は難しい。新しいガジェット発見や新チャネル（ポート競合、TLB 等）の登場で攻撃面は更新され続ける。
- **TEE の内側にサイドチャネルは残る**。SGX に対する Foreshadow が示したように、TCB を縮めても共有マイクロアーキテクチャ資源は残り、そこが漏洩経路になる。機密計算は攻撃面を減らすが消しはしない。
- **緩和はしばしば別の攻撃面を開く**か、性能圧で無効化される（管理者が SMT を戻す等）。緩和の有効性は「有効化されている」ことに依存する。

### 構造的論点 — 隔離と最適化の不可分な対立

一貫する結論は、**隔離と最適化は同じ資源を奪い合う**という構造である。共有（キャッシュ、予測器、SMT、cache-to-cache 転送、DRAM 密度）は性能を生み、まさにその共有が漏洩経路になる。したがって次のことが言える。

- 完全な隔離（何も共有しない）は性能機構の放棄に等しく、実用にならない。
- 完全な最適化（すべて共有）は漏洩を最大化する。
- 現実の設計はこの連続体のどこかに線を引く**妥協**であり、Meltdown/Spectre 緩和も、TEE の TCB 選択も、TRR も、すべて「どこに線を引くか」の異なる回答である。

サイドチャネルはバグではなく、**性能のために状態を共有するという設計判断の影**である。これを消すには共有をやめるしかなく、それは性能を捨てることを意味する。ハードウェアセキュリティの本質的な難しさは、ここにある。

## 結論 (Conclusions)

- ISA はアーキテクチャ状態の契約であり、キャッシュ・予測器・バッファ・DRAM 物理といったマイクロアーキテクチャ状態は仕様外である。**サイドチャネルはこの契約の空白に棲む構造的帰結**であって、単なるバグではない。
- 一時的実行攻撃の分水嶺は「予測器の訓練 (Spectre)」か「例外の遅延評価 (Meltdown)」かにある。Meltdown は KPTI で OS から塞げたが、Spectre v1 はプログラム構造に宿り包括的修正が難しい。MDS/L1TF は「漏れやすいバッファ」への一般化である。
- Rowhammer は、DRAM の信頼性マージンがそのまま安全境界であることを暴いた。TRR も ECC も攻撃を難しくするが排除はしない。物理層の最適化が直接に攻撃面を開く。
- TEE は TrustZone（ワールド二分）・SGX（最小 TCB だが側チャネル多孔質）・SEV-SNP/TDX（VM 機密計算）・Secure Enclave（独立コプロセッサ）と設計思想が分かれ、どれも縮めた TCB の外は守るが万能ではない。
- 信頼の起点はブート ROM に固定した無条件の信頼であり、Secure Boot（予防）と Measured Boot＋TPM PCR（検知・遠隔認証）が信頼の連鎖を成立させる。一段の検証漏れが全体の崩壊点になる。
- 貫く教訓は、**隔離と最適化は同じ資源を奪い合う対立関係にあり、あらゆる緩和は性能と引き換えの妥協である**こと。速さと秘匿性は根本的に緊張関係にある。
